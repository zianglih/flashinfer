# R3 same-weight numerical failure: source audit and diagnostic plan

The failed coordinate is **global N=3, EP4, allgather, live Mega capacity1, routing included, no fused finalize**. N=1 passed the same fixed elementwise threshold despite max_abs0.03125; N=3 failed with max_abs0.03125 and relativeL2≈0.00343518943. There is no basis to waive the failure or infer a kernel defect from these aggregate values alone. Preserve r3 and do not relax atol=rtol=1e-2.

Evidence is the final transferred `001-correctness-ep4-allgather-caplive-r1/benchmark.log`: lines163–164 N1 reference/graph PASS; line179 N3 Split graph PASS; line184 N3 reference FAIL; lines205/226/248/268 synchronized rank assertions. N3 Mega graph validation was not reached. These are correctness-gate samples, not an accepted calibration result. The local source HEAD6f88c235 matches recorded benchmark hashes; production kernel files are unchanged from ad0a5e5e. Companion JSON binds source and evidence hashes.

## Established source contracts

- Benchmark lines691–790 quantize once per rank and construct both layouts from the same packed weight/scale bytes. Split swaps/interleaves gate/up bytes; Mega receives canonical gate/up halves. Lines801–836 recreate BF16 inputs and FP32 route logits/bias from fixed rank/global seeds for both variants. This is source sharing, not a dump proving executed per-point tensors.
- Lines1219–1280 use equal padded rank blocks and mask padding to expertID256/weight0. N3 partition is[1,1,1,0], padded rows4; each rank owns64 experts with full I2048. Actual JSON records this layout. Lines1291–1293 perform SUM `reduce_scatter_tensor` with BF16 partials/reduced buffer. The actual NCCL reduction tree/order is not logged.
- Split: `flashinfer/fused_moe/cute_dsl/blackwell/moe_w4a16.py` lines82–90 allocate BF16 FC2 scratch; lines470–505 run FC2 into it then call `moe_unpermute`. The GEMM epilogue multiplies FC2 alpha then casts to BF16 (`moe_w4a16_kernel.py`2250–2255,2281–2286). `csrc/nv_internal/tensorrt_llm/kernels/cuteDslKernels/moeUtils.cu`160–207 loops top-k slots, skips nonowned slots, accumulates BF16 expert output×FP32 routing weight in float, then casts the **rank-local partial** back to BF16 before the collective.
- Mega: `tmem_epilogue.py`490–518 scales FC2 float accumulators and casts per-route results to BF16. `topk_reduce.py`70–111 loads those BF16 terms, iterates k=0..7, uses FP32 first multiply/subsequent FMA, then casts only the complete source-rank weighted sum to BF16. The active kernel tail invokes this reducer after its barrier (`megamoe_kernel.py`1530–1550). `apply_topk_in_fc1=false` and `in_kernel_fc2_reduce=false` are retained; this is not the optional atomic reduction mode.
- `_check_megamoe_output`1348–1383 fails on any nonfinite value or `abs(actual-reference) > .01 + .01*abs(reference)`, globally ORed/MAXed across ranks. RelativeL2 is descriptive and is not the acceptance condition. Two runs can share the same maximum absolute error yet differ in pass/fail because the violating element's reference magnitude differs.

With route terms z_k already BF16 and FP32 scores w_k, Split forms rank partials `BF16(sum_FP32(k owned by rank r, z_k*w_k))`, then combines BF16 rank buffers via NCCL. Mega forms `BF16(sum_FP32(k=0..7, z_k*w_k))` in source top-k order. Extra intermediate rounding and changed grouping are an established numerical-contract difference. **Whether they explain the actual N3 violating elements remains unproven**: r3 retained no output tensors, mismatch coordinates or per-route intermediates. Different expert GEMM/activation reductions could also change z_k; route, layout and staging mistakes must be excluded with captured data.

## Bounded diagnostic capture, proposed new run ID

Use a new diagnostic directory/launcher ID, retain r3 immutable, and run only N1/N3 EP4 allgather with the same source, data seeds, weight layouts, default knobs, live capacity and fixed threshold. No timing result is accepted. Reuse the already built r3 compiler caches explicitly, with a new initially absent knob-cache path; do not rerun the60-job matrix or enable autotuning knobs merely to get a passing point.

A setup-only wrapper can capture tensors without modifying production source:

1. At Split `moe_unpermute`, copy only valid expanded(token,topk) FC2 BF16 rows using its mapping, plus mapping/FP32 scores; omit padded garbage. Capture its BF16 output before `reduce_scatter_tensor`, and the actual BF16 collective result. Preserve gathered hidden states and route IDs for identity checks. Do this outside graphs/timing.
2. At Mega backend `compute` return, before workspace destruction, capture `workspace.combine_output[:local_n]` [localN,8,H], staged int64 IDs/FP32 scores/BF16 inputs, owned output and resolved frontend knobs. The shared backend workspace is available to this call, so no extra kernel variant is required.
3. At the original refcheck, save actual/reference tensors and exact failing coordinates, expected/actual/error/threshold, sign, counts per rank/token, maximum error-to-threshold ratio, finite checks and result hashes **before invoking the unchanged check**, allowing it to fail normally. Keep all ranks in the same collectives; no success-only barrier that could deadlock an empty or failing rank.
4. Independently align routes by global token/top-k/expert owner and check IDs/scores/input bits. Compare Split/Mega BF16 FC2 terms first. If terms match, replay global ordered weighted FP32 reduction versus rank-grouped BF16-rounded partials and compare the actual NCCL result. A higher-precision offline sum is a diagnostic oracle, not a replacement acceptance criterion; exact GPU FMA behavior needs its own faithful replay if bitwise proof is claimed. If terms differ, save the first affected route/hidden elements and investigate FC1/activation/FC2 arithmetic before attributing output error to communication.

This staged capture can distinguish per-expert math, rank-local rounding, collective arithmetic and routing/staging issues. It does not presume that the documented rounding difference is the root cause. No GPU, package, runtime or benchmark-source change was performed by this audit.
