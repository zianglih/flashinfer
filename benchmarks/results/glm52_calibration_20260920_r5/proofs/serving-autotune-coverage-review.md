# Serving autotune coverage: fixed-version evidence

**Finding:** W4A16 Split did run through FlashInfer startup autotune in all 16 serving cases. This does **not** establish dedicated large-N prefill tuning: the extra EXTEND pass defaults off and ordinary EAGLE explicitly skips it. Mega routed-expert autotuning is a separate API, not implicitly activated by the ordinary FlashInfer context.

## Interpretation boundary

Startup tuning is confirmed; dedicated large-N prefill coverage is not. The conclusion combines actual logs with the EAGLE early-return rule, rather than treating missing log text alone as proof. This review does not reconstruct per-tactic cached-N coverage or exclude every potentially reusable pre-existing large-N entry; progress messages can include cache reuse. It does not generalize to newer versions, prove native equivalence or attribute the serving performance difference to tuning. Mega cache contents and per-layer resolved tactics were not rescanned here.
