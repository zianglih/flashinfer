The new native signal is exposed predicate-result latency, not a proposed improvement to weight traffic. N3U TP8 MXFP4x8 T32 has114 FC1 operand-ready samples and117 FC2 samples, mostly on the branch consuming the query result. ## Source change and instruction window

Only the swap MMA role changes. Keep one carried `operand_ready` Boolean, initially false, alongside the existing consumer state. Every stage calls the existing `consumer_wait(consumer, operand_ready)`: false performs the original wait; true reuses an already successful acquire for that exact slot/phase. Immediately afterward, clone and advance a temporary view, then perform genuine nonblocking `cute.arch.mbarrier_test_wait` on the next full barrier. Its pointer comes through existing `producer_get_barrier`, which returns the full barrier; no barrier-storage offset is assumed. Keep all current SFA, gather, SFB, MMA, consumer release and consumer advance calls in place.

The temporary advanced view is used only by that query. There is no second persistent cursor, new helper, stage/tactic rule, public argument or buffer. The Boolean carries through the existing full/tail K sections and work-tile transitions without reset. An unused terminal query is permitted and discarded, avoiding a last-K condition. Empty work never queries. Existing iKET markers stay in place; if tracing is later used, the query is inside the SF-issue range, so that range is not a pure S2T duration.

In the captured FC1 loop the current query at0x34b0 is immediately consumed at0x34c0. Its early next-slot replacement could overlap four SF S2T instructions, eight MMA instructions, their descriptor arithmetic, and the separate gather wait. FC2's four later queries are likewise immediately consumed; each prior stage provides two S2T and four MMA instructions plus descriptor/release work. This is the useful window absent from the rejected end-of-loop W4 peek. It is an opportunity for compiler scheduling, not a guarantee that the compiler will preserve that overlap.

## Exact helper semantics

Installed CuTe4.8 bytes are captured in `audits/consumer-wait-installed.json` and `audits/barrier-init-installed.json`. `PipelineTmaUmma` inherits the ordinary `PipelineAsync.consumer_wait`: it invokes the full wait if the optional token is absent/false. `producer_get_barrier(state)` returns `sync_object_full.get_barrier(state.index)`. `cute.arch.mbarrier_test_wait` emits NVVM TEST; `consumer_try_wait` instead emits TRY and may suspend. A direct Mega-style TRY transplant could stall before issuing/releasing the current stage, particularly with one physical slot, so it is deliberately not used.

PTX TEST is nonblocking and its successful default acquire establishes visibility for the executing thread. It tests the current incomplete or immediately preceding completed phase. A false result grants no visibility and must retain the ordinary wait. [CUDA13.2.2 PTX9.2 wait contract](https://docs.nvidia.com/cuda/archive/13.2.2/parallel-thread-execution/index.html#parallel-synchronization-and-communication-instructions-mbarrier-test-wait-mbarrier-try-wait).

Each MMA lane keeps its own acquired token. Different lanes may enter the existing SDK conditional wait; all converge before the current SF/MMA body and advance state unconditionally afterward. No lane-dependent cursor advancement or elected-lane token broadcast is introduced. A per-thread successful acquire must not be replaced by an unqualified warp-uniform assertion.

## Phase/lifetime proof

Let the current logical consumer ticket be `c`, depth `S>=1`, physical index `c mod S`, and expected parity `floor(c/S) mod2`. After the current acquire succeeds, the temporary advanced view denotes ticket `c+1` exactly. Its full object is either incomplete for that generation or completed once; it cannot complete another generation until this consumer issues the corresponding release and the producer reacquires the empty slot.

- A true TEST is therefore not stale while current-stage MMA, metadata acquisition or accumulator acquisition runs: the producer cannot recycle that *next* slot without its matching future release. The cached token follows the same `consumer.advance()` and cannot be reused for another index/parity.
- A false TEST is only a hint. The next mandatory acquire executes the retained blocking wait regardless of whether the producer completes in the meantime.
- For `S=1`, the next view has the same physical index and opposite parity. Current completion already moved the full object into that new incomplete phase, but the producer cannot fill it before current release. TEST returns false without suspending; current SF/MMA and asynchronous release can proceed. The following fallback wait obtains actual new data.
- K-tail sections use the same carried state/token; no skip/extra advance occurs. Work-tile metadata may change the expert and valid rows, but the operand ring advances only in the common stage loop. The final speculative TEST touches an initialized object and needs no future producer progress. The token is simply unused if the next tile is terminal.
- CTA group, full-arrival bytes, separate gather completion/cluster acquire, accumulator lifetimes, PDL and all producer/consumer tails are unchanged. Only leader-CTA MMA executes this code, as before.

The CPU proof checks24,954 bounded generation/readiness states across depths1–64 and2,048 full/tail/work-tile streams; it supplements the algebraic proof and is not GPU correctness evidence.

## History and decision boundary

The bounded history search found no prior swap early full-barrier **TEST before current SF/MMA** implementation. The old `w4a16-producer-lookahead` candidate probed a different empty barrier before Gather4 and was rejected after9–11 extra static instructions with no robust gain. Old `w4a16-mma-plain-wait` removed a peek at the end of the MMA loop, with no useful work between the query and its consumer; that simplification was retained. Raw-ready W4 lookahead removal regressed and was rejected. MegaMoE's combined-pipeline mainloop has early TRY/status state, while its split-depth mainloop explicitly avoids doubling that machinery. These are cautionary precedents, not proof of benefit here.

This candidate adds source/control state and cannot be retained on instruction-count rhetoric or a neutral aggregate. Before timing: compile/resource review must prove TEST lowering remains nonblocking, useful separation from its predicate consumer exists, all mandatory fallback waits/releases remain, and any register/control growth is explicit. Exact gates must include depth1, both CTA groups, static/CLC, empty work, partial K/full-tail boundary, enough repeated work for phase wraps, PDL and the existing dtype matrix. Full relevant frozen-winner performance is required before retention, preserving losses and repeats.
