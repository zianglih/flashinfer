# One-CTA gather/full-barrier merge: ordering boundary

The current chain is SF copies/Gather4 → local completion acquire → proxy fence → gather publication → MMA acquire → SFB shared-to-TMEM copy. Source: `moe_swap_ab_kernel.py:3498–3579`, relay `:3020–3054`, consumer `:3202–3247`. The separate weight-full wait deliberately permits SFA copies before gather readiness. `_copy_sf` at `:2499` uses the existing `Cp4x32x128bOp` partition (`:2489`).

- **SF completion and proxy ordering are separate.** Each participating thread's `cp.async.mbarrier.arrive.noinc` covers its prior SF copies. Waiting for those arrivals does not remove the generic-to-async proxy requirement before `tcgen05.cp`. Direct completion onto operand-full therefore needs the existing proxy fence on the MMA path after the acquire and before SFB copying. Retaining an SF-only relay can keep the fence off MMA, but cannot release unified full until SF publication is complete. [PTX cp.async arrival](https://docs.nvidia.com/cuda/archive/13.2.2/parallel-thread-execution/index.html#parallel-synchronization-and-communication-instructions-cp-async-mbarrier-arrive), [TCGEN05 shared accesses](https://docs.nvidia.com/cuda/archive/13.2.2/parallel-thread-execution/index.html#tcgen05-memory-consistency-model-smem-access).
- **Early Gather4 completion does not itself require a second announcer.** PTX permits negative transaction counts. With one reserved weight arrival, early completions cannot finish the phase; the weight's atomic expect-and-arrive adds the complete expected byte total. Both arrival and transaction counts must then reach zero. All intermediate counts must remain in range. [PTX barrier contents and phase completion](https://docs.nvidia.com/cuda/archive/13.2.2/parallel-thread-execution/index.html#parallel-synchronization-and-communication-instructions-mbarrier-contents).
- **Counts must follow issued operations.** For the proposed group1 construction, full arrivals are `1 + min(route_tile,128)`: one elected weight arrival and the unchanged static SF participants, including threads whose copies are all predicated off. Gather4 expected bytes are the existing physical padded copy extent, not valid rows or logical K. The gather-local announce must be removed if weight announces those bytes; retaining both double-counts them. Weight A/SFA bytes remain unchanged. Installed SDK `sm100.py:343–384` and `helpers.py:458–469` confirm `producer_acquire` waits empty and elects one expect-and-arrive; its commit is a no-op.
- **Reuse and execution order remain necessary.** Both producers must retain empty waits before writes, with matching stage/parity progression. MMA releases only after both channel tiles finish shared reads (`:3293–3296`), through the existing TCGEN05 commit-backed empty barrier (`audits/installed-pipeline/sm100.py:327–341`). This also orders next-phase writes after a successful full wait. Keep the sole producer tail and final CTA join. The existing S2T-to-MMA ownership/election must remain unchanged; this proposal supplies no reason to add or remove its TMEM synchronization.
- **Do not extend local noinc mechanically to group2.** That instruction addresses CTA-local shared memory. Current group2 relay adds explicit cluster release/acquire publication (`:118–170`); neither equal counts nor an identical pointer offset replaces it. Initialization publication and cluster rendezvous remain unchanged.
- **Removing the relay loop has other contracts.** Preserve activation-warp startup dependency acquisition/launch signal (`:2759–2785`), even with no work; reduce CLC metadata consumer arrivals only if its `next_work` consumption is actually removed. Keep all threads in the final join.

Conclusion: no inherent group1 memory-order impossibility was found, provided those conditions hold. But the direct merge moves a proxy fence into every MMA K-stage and both merge forms postpone SFA behind gather completion. The existing split readiness is useful overlap, not an accidentally duplicated wait. History/native-cost assessment remains with the other reviewer; no performance benefit follows from this arrival proof.
