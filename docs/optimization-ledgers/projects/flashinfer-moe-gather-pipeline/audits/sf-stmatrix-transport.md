# SF `stmatrix` transport: no direct replacement at current ownership

Read-only on retained `2b8eb9d8`; no source edits, compiler/GPU runs, or stronger alignment contract. Close this narrow lead.

- **Exact mapping.** `moe_swap_ab_kernel.py:3473–3492,3514–3544` assigns warp lane `l` a whole4-byte word at `128*warp +16*(l%8)+4*(l//8)+512*word`, ignoring stage/outer-row offsets. For example, lanes0/1 write offsets0/16. Non-transposed `stmatrix.m8n8.b16` instead places each group of four adjacent lanes into one16-byte row: lanes0/1 write offsets0/4 relative to the same supplied row address. Arbitrary row addresses cannot repair that mismatch. The required register permutation would be `source_lane=8*(l%4)+l//4` per word; it is additional cross-lane work.
- **Transpose does not preserve the word.** CUTLASS's retained layouts in `3rdparty/cutlass/include/cute/atom/copy_traits_sm75.hpp:94–134`, `copy_traits_sm90.hpp:43–130`, and `copy_traits_sm100.hpp:211–260` give lane0 byte positions `{0,1,16,17}` for transposedb16 and `{0,16,8,24}` for Blackwell transposedb8, versus required `{0,1,2,3}`. Both need packing/permutation; `.x1/.x2/.x4` repeats the same per-register layout and does not change this. CuTe's `warp/copy.py:228–298` exposes these same atoms.
- **General width/alignment still blocks the proposed instruction saving.** Let `W=tileK/(4*sf_vec)`: current work is `W` predicated4-byte global-to-shared copies per owning lane/row block. Public `moe_swap_ab.py:147,343–362` guarantees only4-byte SF alignment/row granularity. `W` can be1 or2 as well as4/8; a legal row may not support one aligned wide LDG, and the final K stage can contain fewer live words. Under that full contract, a register route still needs the4-byte loads, plus permutation and matrix stores. A hypothetical aligned full-width LDG does not establish a general saving.
- **Tails and publication are not free.** `stmatrix` requires whole-warp participation and aligned matrix-row addresses; it cannot inherit the existing lane-specific `row< mma_n` issue mask or ignore-source zero fill. Explicit zero values/full allocated padding stores would be needed for invalid rows/K words. Its weak shared stores also do not replace the current `cp.async.mbarrier.arrive.noinc` completion mechanism; the gather/TMA join, generic-to-async visibility and two-CTA relay must remain correctly ordered. [CUDA13.2.2 PTX contract](https://docs.nvidia.com/cuda/archive/13.2.2/parallel-thread-execution/index.html#warp-level-matrix-instructions-stmatrix).
- **History boundary.** The earlier [SF transport audit](../../flashinfer-w4a4-split-dynamic-n/fc1-gather-20261028/optimization-next-20261029/sf-transport-audit/AUDIT.md) covered directTMA, widerLDG/scatter and Rubin's separate transform pipeline, but did not establish an actual STSM prototype/performance rejection. This note supplies the missing lane-layout obstruction. Existing FC2 `_bulk_stmatrix4` works because its TMEM-derived fragment already has native transposed ownership; FC1 SF does not. The recent SF-lane coalescing prototype also spilled, but that is separate evidence, not a proof that every redesigned mapping is impossible.

Conclusion: reducing four scattered stores to oneSTSM is possible only after changing/repacking register ownership and handling the full input/tail/publication contract. There is no concise instruction-saving substitution under the requested unchanged ownership/contract, so no prototype is proposed.
