# Routing publication: consumer boundary follow-up

Read-only audit at `49c91adf`. No kernel edits or new GPU runs.

The available evidence supports the wait discipline for the inspected consumers, but does **not** establish an export-wide contract sufficient to move the shared routing signal universally. Keep the current routing publication unchanged in this optimization round.

- **Visible CuTe consumers:** Hopper waits before reading live tiles and token maps (`hopper/contiguous_gather_grouped_gemm_act_fusion.py:633–637`); legacy Blackwell and Rubin wait before scheduler/map-dependent work (`blackwell/blockscaled_contiguous_gather_grouped_gemm_act_fusion.py:1579`, `rubin/blockscaled_contiguous_gather_grouped_gemm_swiglu_fusion.py:1731`). Current gathered W4 waits before role specialization (`moe_w4a16_kernel.py:1516`); swap uses its existing payload-role wait (`moe_swap_ab_kernel.py:2766`). This is consistent with preserving a full wait on every map reader while allowing only explicitly published metadata to run ahead.
- **Visible TRTLLM helpers:** `trtllm_fused_moe_dev_kernel.cu` places `cudaGridDependencySynchronize()` before map/payload access in activation (:105), permute (:617), and finalization (:685). These implementations do not depend on a late routing launch trigger for their data reads.
- **Generated FC1 path:** `trtllm_fused_moe_runner.cu:267–273` passes the token map and tile metadata directly to generated `PermuteGemm1`; `trtllm_batched_gemm_runner.cu:417–420` forwards `enable_pdl` to the external BMM launcher. The exported device implementations are artifact downloads, not tracked source (`flashinfer/jit/fused_moe.py:370–383`). A launch flag alone cannot prove the device readers' ordering.
- **Historical generated source:** the four archived PR2917 sources are bound to `aleozlx/flashinfer@64ed071e`. Three FC1 sources place a global dependency wait before `KernelState`, including its live-CTA read; their routed payload loaders also wait. The persistent TMA example has entry wait at :2872, `LoadTaskB` wait at :428, and route-map reads beginning at :452. The LDGSTS example has entry wait at :3900. The saved FC2 example instead has role-specific waits and early metadata reads; do not generalize a global-entry-wait claim to FC2.
- **Historical native evidence:** the three saved NVFP4 FC1 winners (tokens4/32/128) each have one unconditional entry `ACQBULK` before the first global read and before any branch: PC `0xf0/0x180/0x130`, first read `0x130/0x1c0/0x170`. The separately named `GetSmemSize` functions were excluded from this control-flow check. Saved SASS hashes match `selected-cubins.json`. These are artifact `8ee504.../batched_gemm-fdba669-16ba8ed`, not a demonstrated build of the PR2917 source, and not the entire current generated tactic set.

The current small-block routing paths already signal early and explicitly describe consumers as waiting (`trtllm_fused_moe_routing_custom.cuh:115–118,441–444`). Larger routing paths still document late publication after token-map stores, including a prior stale-data/NaN failure (`RoutingKernel.cuh:550–557,1229–1231`). Neither comment substitutes for a current generated-consumer inventory. No unsafe reader was demonstrated here, but current MXFP8/MXFP4x8, per-token, other architectures/tactics, and external public-routing consumers remain outside the bounded native evidence. There is no basis for removing the late-signal protection universally from this audit alone.

Machine-readable hashes, exact native symbols and source provenance are in `routing-consumer-boundary.json`. A future shared-contract change needs the current generated family/reader contract or a broader native audit; this round does not add a mode, readiness counter or fallback to work around that boundary.
