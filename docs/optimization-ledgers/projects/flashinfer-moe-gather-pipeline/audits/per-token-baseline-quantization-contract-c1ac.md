# PER-TOKEN baseline quantization contract

Current source: `c1ac8ce7341039db65195b99445fcdeb193cf226`. Read-only source/archive audit; no GPU execution. [Source bindings](per-token-baseline-quantization-contract-c1ac.json).

**Both benchmark arms perform fresh whole-row quantization between FC1 and FC2. TRTLLM PER-TOKEN does not substitute its ordinary fused FC1 block quantizer.** More precisely, each routed token-expert row gets a whole-row amax/FP32 outer scale, followed by a separate 4-versus-6 choice for each 16-element block—not one 4-versus-6 decision for the entire row.

| Boundary | CuteDSL PER-TOKEN | TRTLLM PER-TOKEN |
|---|---|---|
| Initial activation | Public CuTe quantizer; dynamic FP32 token scale and FP4/E4M3 payload | Same public CuTe quantizer, with linear SF layout |
| FC1 | Consumes input row scales; activated BF16 output, `quantize_output=False` | Consumes input row scales; runner selects BF16 activated output when FC2 per-token scaling is enabled |
| Between GEMMs | Explicit `nvfp4_quantize_per_token_cute_dsl` | Explicit CUDA `invokeNvfp4QuantAndPerTokenScale<__nv_bfloat16>` |
| Reduction | Whole intermediate row, then per-16-element 4over6 candidates | Whole intermediate row, then per-16-element 4over6 candidates |
| FC2 | Receives newly computed `intermediate_per_token_scale` | Receives newly computed `workspace.token_scales_fc2` |

## Historical comparison boundary

The [published baseline index](../publication-w4-tail-cutoff/completed-tables/baseline-index.json) identifies six supported PER-TOKEN groups: V3/V41F/N3U × EP/TP. All 78 saved rows explicitly record recipe wire23, both activation quantizations timed, and base fast math disabled. K3 TRTLLM PER-TOKEN is unsupported and remains N/A. The six exposed TRT runner/launcher/quantizer files in the source-binding receipt are byte-identical between historical git objects `e2728a29`/`d1767be1` and current `c1ac8ce7`; this is source identity, not a new timing or library identity claim.

Older generated fused-FC1 block-scale examples (`scripts/epilogue_codesign_audit/TRT_MAPPING.md` in the old project) and an older protocol with 4over6 disabled do not override this explicit per-token path. Ordinary **TRTLLM NVFP4** without per-token scales is a different contract and can quantize in the FC1 epilogue.

Consequently, eliminating CuTe's intermediate quantizer by using only tile-local maxima or fixed outer scales would change the benchmark's per-token contract. A legal fusion must preserve the full routed-row reduction, BF16 intermediate rounding, configured block selection and fresh FC2 row scales. The baseline offers no evidence that those semantics are absent or free; compare measured components and overlap before attributing the end-to-end gap to this stage.
