# Integer-carried FC1 payload join: peer source review

**Source review passes for `482b636a1714486e2ffb34c8ae005da3cef26f25f0ce034ba1eb59c6198d6276`.** Full-kernel compilation, exact results, resource counts, actual store widths and timing remain qualification boundaries. The isolated probe is not complete-kernel evidence.

The first frozen source `d2aaa0fa` had one concrete compatibility bug: the generic `activation_type=None`/FP32 fused FC2 path also takes the joined nongated branch, so the new Uint32 carrier reached `_blockscaled_atomic_add_pair`, which rejects integer types. The revised source recasts both carrier and target to `self.output_dtype` inside the existing fused-finalize branch. Removing only these two casts reconstructs `d2aaa0fa` exactly. No new policy branch is introduced. The repaired fused boundary still needs its own compile/numerical check; it is not exercised by unfused ReLU² calls.

- **Conversion and SF contract:** `_convert` has exactly the original `_store` AST after removing the payload destination argument and replacing its final store call with a return. Each 16-value fragment keeps identical scaling, rounding, SF write and conversion order. SF16 computes separate maxima/scales, while SF32 still shares the joint maximum and emits only the first half's SF byte. SF16 maximum work moves inside the existing validity guard; it does not change any stored valid value.
- **Payload representation:** Each converted 16-element fragment is bitcast, not numerically converted, to Uint32 words. Concatenating these words preserves top-half then bottom-half bit order. Copy width is derived from the total bit count: FP4 joins into 128 bits; FP8 into 256 bits; BF16/FP16 still requires two capped 256-bit operations. This avoids the packed-FP4 mutable register-tensor join that previously introduced a local depot, but only native whole-kernel artifacts can establish that the depot remains absent here.
- **Bounds and alignment:** Existing legal output channels are multiples of 128; each nongated warp base is a multiple of 32. Consequently both old half predicates agree, and a live base implies all 32 channels fit. The 32-byte base-pointer contract and row strides already guarantee natural 16/32-byte alignment for FP4/FP8. The candidate adds no API restriction, output padding or runtime full/tail policy. The existing general legality proof remains applicable, including wholly inactive right-edge CTA/channel tiles.
- **Gated and FC2 boundary:** Gated output still supplies 16 output-typed values to the same helper. The BF16/FP16 no-activation FC2 branch remains separate and still supplies two 16-element output-typed slices; its dataflow is unchanged at source. The FP32 generic FC2 branch is affected by the joined carrier representation, so it must not be called universally untouched. With the repaired atomic branch, its 16 pairwise atomic updates address the same channels in the same top-then-bottom order as the original two sets of eight.

`fc1-integer-store-peer.py` reproduces the conversion AST proof, exact revision reconstruction, integer payload bit-order checks and 33,792 alignment/guard cases for 4/8/16/32-bit output. The receipt binds the current source. No source edit or GPU run was made by this review.
