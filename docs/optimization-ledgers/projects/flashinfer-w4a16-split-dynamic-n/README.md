# Split CuTe DSL W4A16 dynamic N

Upstream PR: https://github.com/flashinfer-ai/flashinfer/pull/7196

Refactor the SM100/SM103/SM107 split W4A16 MoE kernel to issue BF16 MMA with a runtime token-axis N. Runtime-N helpers belong entirely to the split kernel; MegaMoE production remains byte-for-byte identical to the baseline. The user also authorized aligning the common W4A4/W4A16 deterministic finalizer to Mega arithmetic: first-slot FP32 multiply, later ordered FP32 FMA, no FTZ. The reusable exact test reference lives in shared utility `tests/test_helpers/w4a16_reference.py`; unfused split tests use zero tolerance through the same numerical pipeline as Mega tests. Parameterized SwiGLU and SiTU runtime arithmetic align with that shared contract.

- Source branch: `codex/w4a16-split-dynamic-n` in `flashinfer/`.

- Devbox: `w4a16-dyn-n-1024`, C2, namespace `ziangli`, eight B300 GPUs. Requested bare without a size override or queue override.

## Runtime N implementation

Runtime BF16 MMA N is rounded to 8 for one CTA and 16 for two CTAs. The existing route-tile capacity still controls buffers/TMA staging. For two-CTA MMA, the peer activation load moves from the capacity midpoint to the runtime midpoint. The epilogue skips wholly invalid N subtiles and retires the accumulator after the last active one.

The implementation retains N8/16/32/64/128/192 tactics and a static fallback for internal operand/layout configurations outside the advertised tuner. An injected empty private work tile still retires all pipelines; FC2 keeps its valid-token output predicates.
