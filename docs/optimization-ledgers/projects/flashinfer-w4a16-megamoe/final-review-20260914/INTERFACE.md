## Evidence

- Registration and ownership: the added precision is registered as `sm100_bf16_nvfp4_bf16_cutedsl` alongside the existing SM100 backend configs. Its implementation lives in `cute_dsl/megamoe/nvfp4_w4a16`. Vendored `src/` files are unchanged; primitive access crosses the existing package/shim boundary. W4A4 preprocessing is unchanged, and only byte-layout helpers are reused directly from that backend.
- Weight contract: canonical packed FC1/FC2 shapes and E4M3 block-scale shapes are explicitly checked. FC1 uses the existing 16-row gate/up interleave; returned K-major transpose views and flattened padded per-expert scale bytes match the W4A4 layout. Compared the padded-scale shape calculation with `quantization/fp4_quantization.py:block_scale_interleave`, including its 3D expert handling. FP32 per-expert alphas stay separate, default to one, and retain the post-accumulation contract.
- Global-scale scope: `MegaKernelBackend.supports_global_weight_scales` defaults false, W4A16 explicitly opts in, and common canonical-pack validation rejects either global-scale field for all non-supporting mega and split backends. The transformed-weight branch deliberately does not inspect an unused canonical pack. Direct preprocessing helpers retain their documented backend-specific caller contract.
- Input contract: BF16 activations, int32/int64 route IDs, FP32 routing scores, shape/capacity checks, and common input device are checked before staging. Activation quantization fields and `quantize_input=False` are explicitly rejected. Owned BF16 output follows the layer's common allocation path; unsupported borrowed output views reject via the existing capability.
- Staging: the fused copy path predicates live rows and invalidates the complete capacity tail with -1 route IDs. It preserves BF16 values and FP32 scores. Alignment, inner stride, aliasing, CUDA/device-copy eligibility, requires-grad views, empty inputs, first-use capture, and `FLASHINFER_MEGA_FUSED_STAGE=0` route to the established torch copies. Compile and launch cache keys distinguish device, hidden size, top-k, route dtype, addresses, layouts, and stream where required.
- Configuration and caching: `None` performs the existing capacity-keyed cache lookup, while an explicit dictionary bypasses defaults/cache. Factory construction and later `apply_knobs` use shared `with_knobs`, including derived M128/M256 one-/two-CTA consistency. The built-in W4A16 profile is separately declared. Invalid routing/reduction modes are rejected. Pool identity contains backend, EP identity, shape, clamp and knobs; automatic tuning disables workspace sharing and the existing layer prohibits mutable-auto capacity handles.
- Graph lifecycle: layer capture-readiness checks run before staging. W4A16 rejects absent compute compilation; actual clamp/knob mutations, symmetric release/allocation and compilation have capture guards. A separately lazy top-k reducer rejects a nonempty capture after empty-only warmup, while a valid empty capture remains supported. Reducer launch uses dynamic compact token shape, and the compute wrapper uses stable capacity tensors.
- Autotuning: private graph timing includes the fused compute and deterministic external routing reduction on staged input. Rank-ready capture consensus precedes replay, candidate scoring uses maximum rank medians, graph references are reset after synchronization before another candidate can free its workspace, and graph timing/cleanup errors stop the sweep. The final winning configuration is reapplied, then the backend performs its normal eager forward so public warmup leaves the winner compiled.
- Shared behavior: the PR only adds the explicit global-scale capability gate and W4A16 default dispatch to common code; existing W4A4/BF16/MXFP8 numerical paths and candidate policies are unchanged. `git diff --check 8c94f70f..HEAD` passed.
