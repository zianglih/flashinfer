# W4A16 MegaMoE final compute audit

Reviewed HEAD `7f1a093119f12b1f5b79d50bf6d0c951069224e5` against base `8c94f70f49fbe17adb5deae5b2b48ff467346863`, following repository `CLAUDE.md` and `docs/code_review_guidance.md`. Production source and Git state were not changed.

**Result: no actionable correctness finding or readiness blocker in the reviewed kernel scope.** Confidence is high for the explicit precision/indexing contracts and moderate for concurrency correctness: the source protocol is internally consistent, while a static audit cannot prove every device interleaving.

## Source evidence

- **Decode and TMEM ownership.** `megamoe_kernel.py:223` fixes exactly two decoder warpgroups within a 640-thread CTA. The inherited W4A16 `_setup_transform_partitions` divides both packed input and transformed output blocks evenly between those groups. Decoded BF16 operand tiles begin after the two accumulator stages; the 512-column allocation accommodates D3 at N64 and D2 at N128 without overlap. TMEM retrieve rendezvous counts 13 participating warps (four epilogue, one MMA, eight decoder). Scheduler consumer count is the corresponding 15 warps including both loaders. Constructor geometry restrictions agree with these counts.
- **Independent operand pipelines.** `megamoe_kernel.py:814` loads weights without input-readiness waits; the activation loader separately waits for dispatch or FC1 completion. Both producers and both decoder groups consume the same ordered scheduler records and preserve ring index/phase across work records. Only the work-local K count resets. The MMA consumer waits for both decoded A and activation B, then uses UMMA pipeline release for asynchronous operand lifetime. `_finish_transform_stage` releases raw SMEM only after all raw/scale reads have moved into registers; TMEM store completion still precedes transformed-tile publication. The added split-kernel hook preserves the original split ordering exactly.
- **Dynamic routed-token width.** The two-CTA nonleader TMA-B shift, runtime align16 N descriptor and unchanged token epilogue coordinates match the existing swapped MegaMoE policy. The admitted positive tiles have `valid_tokens <= N64/N128`; padding lanes are excluded from output stores. M128 one-CTA MMA does not apply the two-CTA shift.
- **Epilogue lifetime and completion.** `epilogue.py:277` and `:535` release each accumulator stage after its final TMEM scratch read and fence. The N128 case with only its first subtile valid releases in the explicit final-subtile else arm. BF16 global stores finish before the four-warp named rendezvous and release-counter publication. The shared flag tracker flushes on batch completion, phase transitions and terminal drain. FC1 publishes only in-bounds feature tiles; its threshold is the matching ceil-div CTA feature count. Dispatch return deliberately waits for the entire expert's FC2 output under its existing shared protocol.
- **Bounds and pointer width.** FC1 uses I%64 and per-CTA feature guards for cluster tails. FC2 uses H%32 plus token/hidden predicates for paired 16-BF16 stores; each adjacent pair has identical hidden validity. Direct and local FC2 destinations widen token coordinates to Int64 before stride multiplication (`tmem_epilogue.py:395`, `:439`). The token pool bound includes maximum valid routes and expert padding; task-counter capacity additionally includes each expert's partial tile.
- **Precision and determinism.** Both GEMMs use BF16 operands and FP32 accumulation. Expert alpha stays FP32 after the GEMM. FC1 applies alpha, clamp and SwiGLU before the BF16 handoff; FC2 applies alpha before its BF16 per-route output. The frontend selects the existing shared BF16 `TopkReduce`, whose source traverses top-k in fixed order, loads each BF16 term into FP32 and applies FP32 score multiply/FMA before the final BF16 cast. No TMA reduction, atomic numeric combine or in-kernel top-k reduction is enabled. Deterministic reduction order does not imply bitwise identity with split MoE or with different GEMM/compiler choices.
- **Termination.** All five CTA roles join the shared transport tail. TMEM deallocation follows all consumed accumulator work; the shared transport tail performs cross-rank output drain and counter reset before return. Counter/data region ordering preserves the phase counter and signal outside zeroed prefixes.

## Additional scheduler arithmetic check

`check_scheduler_model.py` extracts and executes the actual Python scheduler group/phase/expert advancement and tile-decode bodies, removing only DSL decorators/type annotations, against an independently generated lexicographic oracle. It covers empty experts/all-empty routing, partial token tiles, hidden/intermediate tails, greedy group boundaries, C1/C2 CTA coordinates, monotonic sparse claims, and static strides 1/7/66.

Result: **81,340 control paths and 451,728 valid work records passed**, including out-of-work sentinel checks. See `scheduler-model.json`. This checks source arithmetic and cumulative offsets; it is not a CuTe lowering, GPU execution, sanitizer or concurrency test.
