# Same-kernel compile-cache reuse: saved-source audit

Fresh DSL/driver directories are a chosen isolation rule in the current benchmark harness, not a numerical requirement established by the kernel validators. However, **reusing `CUTE_DSL_CACHE_DIR` alone is not a demonstrated way to avoid this Mega kernel's compilation**: the installed4.7.1 `CompileCallable` used by `cute.compile` unconditionally sets `compile_only=True` and `no_cache=True`. Mega and its reducer both call `cute.compile`. Keep the current trial unchanged; a later scorer-only trial can revisit isolation, but no setup-time saving or cache hit is established here.

The current general-path file helper (`cache_helpers.py:67–90,219–326`) uses the requested directory directly and a final `cute_dsl_<key>.mlir` filename. PID/UUID identify only a temporary publication directory; `os.replace` publishes atomically. CRC32 or parse/read failure becomes a miss; disk-write failure warns. There is no compile lease around misses, so concurrent ranks can duplicate compilation despite atomic publication. Environment getters are cached in-process (`env_manager.py:103–110`); set a later trial's environment before importing the DSL. These details apply to cache-enabled callers and do not bypass `cute.compile`'s forced no-cache setting.

## Harness and experiment boundary

- `candidates/cuda13_cross_version/run_stack_benchmark.py:177–185` chooses per-source/run paths for four cache categories. Current `scheduler_depth2/run_full13.py:145–157` reuses only the two completed native-extension roots and explicitly requires fresh DSL/driver paths. Source/preflight/helper, actual loaded function/resource, original numerical, provenance and timing checks remain separate.
- The older `run_cached_stack_retry.py:21–50,80–110,122–128` contains a same-source/stack four-cache reuse contingency for a failed attempt, with fresh knob/tactic files and a saved before inventory. This proves a prepared policy alternative, not a successful current4.7.1 reuse measurement; no completed manifest using that contingency was found in the bounded local search.
- `FLASHINFER_MOE_EP_KNOB_CACHE` must remain fresh for the scorer trial, along with rankings/tactics/output paths. Its persistent selector key contains workload/device/capacity fields, not the scorer or source hash (`shim/knob_cache.py:130–170`). Reusing it would mix selection evidence. This cache is not a compiled-binary cache.
- `CUDA_CACHE_PATH` is a separate driver cache. No driver cache-key implementation or current hit/saving was established. Do not infer its behavior from DSL keys or native-extension reuse.
- A later exact-kernel scorer-only trial could reuse an explicitly identified closed DSL/driver directory as an isolation-policy change while keeping fresh retuning/output paths and all actual loaded-source/resource checks. The inspected code supplies **no reason to expect the main `cute.compile` compilation to disappear from directory reuse alone**. Altering its compile API/cache behavior is a separate implementation change requiring its own investigation, outside this audit.
- Full13/100 primary CUPTI timings and fresh scorer selection remain unchanged. Whole-run minus timer-utility wall includes many operations; it is not a measured compile-cost estimate. No fresh baseline, cache experiment or latency rerun is requested or performed.
