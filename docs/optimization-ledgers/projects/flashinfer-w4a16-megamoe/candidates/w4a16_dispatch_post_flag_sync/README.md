## Narrow ownership proof

- **Publication is already protected.** The tracker starts at phase0, and every accumulate passes constant `Int32(0)`. For F>1, its only firing condition here is a full batch; that branch retains the all-lane full bulk wait and warp memory-ordering synchronization before accumulate. A partial batch only updates lane-local tracker fields. For F1, the existing full wait and warp sync still precede every immediate release.
- **Pull-buffer reuse stays with the same issuer.** Every input TMA and pool-store election has the same full32-lane mask. PTX elect selects the same leader for the same mask. That thread issues/commits the pool store and executes the retained READ wait on nonpublication iterations, completing its source reads before its own next input TMA can overwrite the pull buffer. Full waits are stronger on publishing iterations. No other lane writes this private shared buffer. This argument relies on issuer identity and the copy-completion guarantee, not on election providing a memory fence.
- **Intervening work needs convergence, not another publication edge.** After accumulate, phase/count advancement and expert/source mapping use registers or immutable global metadata. No lane reads another lane's tracker fields, no input-pool consumer runs in these dispatch lanes, and no next operation depends on observing the previous ready-counter increment. Full-mask mapping collectives and the next input election include the prior issuer before another TMA issues. Late completion of a release increment can delay compute readiness but cannot expose incomplete data: its preceding full wait/sync remain.
- **Ordinary stores keep their real ordering.** The routing-weight lane0 STG and provenance store are distinct from bulk copy completion. Both still precede the retained full-batch or tail warp sync before a rotating lane publishes them. Missing the intermediate post-tracker sync does not remove those later cross-lane memory-ordering edges. The moved routing-weight STG in this base is still before the publication branch.
- **Exit and reuse return remain protected.** F>1 retains its terminal full wait+sync before tail fire. F1 has already fully waited/synchronized/published every token and leaves no pending tracker slots. The final post-fire warp sync remains for both, before `dispatch_pull` returns phase/count state to inherited return/push. Empty destinations execute no input/store and retain that final synchronization. No mbarrier phase, buffer, counter, loop-state or work-count change is proposed.

This is restricted to the current owned BF16 path. It must be reconsidered if tracker phase can change and trigger a partial flush, election membership/issuer changes, another lane writes the pull buffer, a consumer reads tracker/counter output in the intervening interval, or prepublication/tail synchronization is weakened. Earlier overlap proofs conservatively kept this sync; this note supplies the narrower same-issuer and constant-phase argument rather than treating prior retention as evidence that it was necessary.

## Native requirements if selected

Use the existing three diagonal F4/N64/direct, F8/N128/reuse and F1/N64/direct cases, with matching retained controls from the eventual route outcome. Confirm full-mask input/store election and issuer READ completion before its next input TMA; unchanged full/READ waits, initialization, phases, ordinary-store placement, prepublication syncs and final tail; no new spill or early-result dependency and no recreated warp rendezvous. Record any register/control-flow changes. Existing large-skew full/partial/empty numerical cases remain relevant; no new matrix or helper is prepared here. Native deletion and timing benefit are unproven.

The official [elect contract](https://docs.nvidia.com/cuda/pdf/ptx_isa_8.8.pdf) supplies deterministic leader identity for an unchanged member mask. The [bulk wait contract](https://docs.nvidia.com/cuda/pdf/ptx_isa_9.2.pdf) distinguishes source-read completion from full write completion. Neither is used as a replacement for the retained warp synchronization that orders ordinary stores before release publication.
