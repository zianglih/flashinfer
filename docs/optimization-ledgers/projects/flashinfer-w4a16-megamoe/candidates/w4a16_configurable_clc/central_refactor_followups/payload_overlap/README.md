# Held central payload-overlap rebase

Source-only rebase of repaired `../../payload_overlap/source.patch` (`3ba84810fa00669026f5a576dbfc3559f0710c844a3b6ab9f3f64e39b6f17e00`) onto frozen central source `57e2d2793d99321aeebd7db4aa619e81759993a56a8c508cb126eb27f5942fd2`, manifest `a0bd502a4f038fad55fc262716b0a5342f093ea40e4cd598474aef2956990f52`. The original candidate and its failed-then-repaired barrier history remain unchanged. No primary source, installation, native compilation, or GPU execution was performed.

`source.patch` changes only the three owned central files `clc.py`, `clc_transport.py`, and `megamoe_kernel.py`. `base/` and `proposed/` retain exact source snapshots; `base-binding.json` and `rebase-checks.json` bind their bytes. Apply only against that declared base after an explicit experiment decision.

The original extra-storage forwarding hook no longer exists. The fitter now selects `self._clc_transport.pull_comm.extra_smem_storage_class()` when CLC is enabled; the actual allocation uses the identical selection in its constexpr branch. The ordinary path still selects the original four-warp transport storage. The obsolete proposed one-line `pull_storage_class()` wrapper is omitted. The fixed metadata and finish kernels allocate their own original four-warp storage. These are the only conflict resolutions beyond the central path/public import change. They preserve the original candidate's intended runtime behavior without adding an API or wrapper.

The reviewed protocol is retained:

- Fixed 128-thread metadata preparation and full-rank exchange finish before elastic compute starts. Payload pulling is removed from that fixed launch. Workspace capacity, metadata counts and return state remain alive until the existing fixed finish launch.
- Warp 8 owns CLC. Warps 9–11 independently claim finite virtual three-warp pull partitions; all WG2 threads perform the existing register decrease before their role split. The two decode WGs, five total WGs, numerical arithmetic and final 640-thread rendezvous are unchanged.
- `_PayloadPullTokenComm` derives all participant constants together: three warps, 96 threads and 96 experts per dispatch pass. Only its pull primitive and associated storage are used. Full prep, grid/rank barriers and cleanup remain on the separate four-warp transport instance.
- FC1 performs the existing acquire wait before activation TMA. The scheduler's existing readiness peek is retained; no compute result is required for a payload partition to complete. Thus waiting MMA/activation roles do not prevent the independently executing pull warps from publishing readiness. Unstarted or cancelled CTAs own no implicit partition; a claiming CTA finishes its finite work before exiting. Exhausting the cursor alone is not treated as global completion.
- Each local pull warp invalidates its own mbarrier from lane 0 after the inherited pull returns. That return follows its TMA/store waits, release flush and unconditional warp synchronization. The second 96-thread NB10 orders the next initialization and protects the shared partition scalar. Empty valid partitions initialize/invalidate once; exhausted claims do neither. The reviewed repair is AST-identical to the original candidate.

`check_rebase.py` passed syntax, patch applicability, Ruff check/format, source pins, scheduler/transport AST checks and direct storage-selection checks. It verifies that the current loop-rotated `clc.run` is unchanged and that all kernel methods other than `_fit_raw_stages` and `_compute_body` remain AST-identical. The original constructor/storage/partition arithmetic checks and repaired independent lifetime review are reused, not rerun. Native lowering, resource allocation, repeated partition behavior, cancellation/late CTAs, skew and graph replay remain untested for this rebase.

This candidate includes the already retained loop rotation and central wrapper cleanup. Tight-row launch sizing and activation-SF state cleanup remain separate. A future tight-row merge touches different kernel constructor/launch locations; an SF cleanup merge touches `clc.phase_work` and scheduler record fields, while this patch changes the workspace prefix and one storage scalar. Neither is included here. No universal vendor transport source changes are required by this rebase.
