No concrete source-level lost-work, early-tail, C1/C2 state-alignment or DSL blocker found. This is suitable for its own held native/runtime trial; it is not included in row metadata or another candidate.

- A successful pop always remains a nonnegative task and reaches `publish_claim`, including the final FC2 task. The terminal sentinel can only replace a negative pop result. The pending final owner's task cannot be lost merely because another worker observes `head == fc2_tasks`.
- `published == rows` retains the existing FC1-completion condition; `head == fc2_tasks` retains the existing FC2-claim condition. The latter is not an arithmetic-completion condition. A final claimant remains alive through its own claim publication, consumer execution, epilogue completion and local DONE/tail. Other clusters can retire earlier without taking responsibility for that task; fixed finish still follows completion of the whole compute grid.
- A queue reservation hole or a stale failed pop cannot terminate while tasks remain unclaimed: head then remains below the total. Observing the total means successful CAS claims have consumed every task from already-published slots. The existing acquire reads and publication rules remain unchanged.
- Exactly one outcome broadcast makes the task/sentinel decision uniform across both C2 CTAs and all owner-warp lanes. Its explicit returned `ds` is rebound before either publishing a task or taking the terminal branch. Each participant executes the same number of pipeline advances/releases. Removing the separate terminal broadcast changes phase progress consistently; the producer tail uses the final returned state. C1 is the same protocol with one CTA.
