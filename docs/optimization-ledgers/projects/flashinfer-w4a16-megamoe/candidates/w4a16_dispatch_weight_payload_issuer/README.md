## Source ownership proof

- The token loop index is shared by all lanes of one dispatch warp; distinct global warps stride through disjoint logical tokens. Expert-prefix updates are uniform. The source-rank mapping uses a common ballot, reduction, slot index and selected rank. The subsequent source metadata read therefore yields the same source token/top-k in each lane. `SymBufferDeviceBase.map(0, rank, 0)` uses that rank and common immutable offsets (`src/src/sym_buffer.py:91–117`). Thus `weight_addr`, the all-lane loaded weight, and `pool_token_idx` are uniform. Any elected lane stores the same value to the same scalar address that lane 0 previously used; exactly one elected lane writes it.
- Payload, provenance and scalar-weight destinations remain the existing distinct workspace regions. No index, pointer conversion, dtype, store width or allocation changes. The scalar value stays a local SSA value defined before election; it needs no shuffle, tuple, merged value or persistent-state serialization. The elected body returns no new value.
- The order remains input-copy completion → prior pool-write drain when F>1 → pool TMA → provenance STG → bulk commit → weight STG → publication/completion branch. Bulk commit does **not** commit the ordinary scalar store. Its correctness still comes from the retained warp memory synchronization before a rotating GPU-release publisher (`src/src/flag_batch.py:46–87,111–119`), just as for the existing elected provenance store.
- F1 retains a full wait plus warp synchronization before every publication. F>1 retains full wait plus synchronization before full-batch publication and before partial-tail fire; constant phase0 prevents an unprotected phase-change flush. Nonpublication iterations retain issuer READ completion before shared-buffer reuse; moving the scalar store to that issuer changes neither its shared-memory reads nor the copy barrier phase. Empty work performs no scalar store. Direct and reuse return share this dispatch body, with unchanged final synchronization and return/push logic. No dependence on the elected lane being lane 0 is required.
- The independent post-flag deletion remains a prerequisite, not an additional edit here. This proposal leaves its same-issuer scratch-reuse proof and all prepublication/tail memory-ordering edges intact.

## Native qualification remains open

Actual routing-weight b9db captures establish the starting issue: N64/F4 payload/provenance/commit at `11950/11960/11970`, then reconvergence and lane-0 weight STG at `119b0`; N128/F8 `13660/13670/13680` then `136c0`; N64/F1 `11910/11920/11930` then `11970`. Their main-path weight load uses write-dependency barrier5, first waited at the scalar store. The compiler's divergent election recovery already waits barrier5 before pool issue. These are b9db reference PCs, not captures of the post-flag or proposed source.

Using one existing issuer may remove separate lane-0 predicate/address/control work. It may also let the compiler predicate or sink the side-effect-free weight LDG into the election, change register allocation, or place a result dependency before pool issue. No instruction reduction, preserved native placement, or timing benefit is claimed. If selected later, reuse the three existing F4/N64/direct, F8/N128/reuse and F1/N64/direct fixtures and inspect actual first-result use/scoreboard waits, full-mask election, single scalar writer after commit, retained ordinary-store publication and tail ordering, resources and spill counts. No new matrix is needed.
