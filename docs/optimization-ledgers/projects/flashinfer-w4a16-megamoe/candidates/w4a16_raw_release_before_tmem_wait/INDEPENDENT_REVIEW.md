- **Default split behavior:** the new shared `_finish_transform_stage` contains the original conditional TMEM-store wait / SMEM proxy fence, then raw consumer release, then decoded producer commit, in the same order. The author's whole-module AST expansion check agrees with this independent source inspection; it was not rerun. There is no new public flag, shared scheduling branch or serialized state.
- **Raw lifetime:** the shared transform loop loads all scale fragments and packed raw fragments into registers and finishes decoding them before `store_transformed_a`. Mega's TMEM copy is the existing warp-wide `St32x32bOp` with repetition 8. Raw release follows this store issue, so the final warp rendezvous remains after the raw/SF reads; the asynchronous store uses decoded register data, not the recyclable raw shared-memory slot. The retained TMEM wait still occurs before advancing to the next transform, preventing register reuse before the stores complete.
- **Eight warps and multicast:** Mega still sets `num_transform_warps = 8`, with two independent four-warp decode groups. Its raw pipeline expects `mix.num_mcast_ctas_a * 8` empty arrivals and retains the same consumer thread indices and `(1, 0)` multicast mode. The saved installed DSL 4.7.1 `PipelineTmaAsync` implementation uses the supplied arrival count by default and selects signaling lanes independently in each warp for the participating destination CTAs. Moving the existing release call therefore does not let one warp or one multicast participant release the entire raw stage: every expected warp/participant arrival is still required. No new participant, arrival or phase is introduced.
- **Decoded lifetime:** the Mega override remains `raw release → fence_view_async_tmem_store → decoded producer commit`. The decoded-empty acquire is unchanged, and no MMA consumer can observe the new decoded-full phase before the store completion wait. `_MegaMixedInput` already requires TMEM, so the override does not remove a supported Mega SMEM path.
- **State and tail:** the release still uses the cloned current raw state, not the advanced state used for the next-stage peek. Raw/decoded advances, both FC1/FC2 call sites, zero-iteration behavior, drain/tail operations and scheduler ownership are unchanged. Earlier raw reuse does not depend on decoded consumption or MMA progress, so this reorder adds no producer/consumer wait cycle.

The relevant implementation sites are shared decoder `_transform_tile` / `_finish_transform_stage`, Mega `_MegaMixedInput._finish_transform_stage`, the raw/decoded pipeline construction, and the eight-warp transform role.
