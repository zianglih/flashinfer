# Current-head CUDA 13.0 measurement audit

**Result:** source, saved command and all eight recorded worker launches agree with the intended EP8 non-fused-finalize comparison. No benchmark change or rerun is required by this audit. Timing is still running; this is not a completed-results claim.

- **Source/launch:** `benchmark.sh` checks clean HEAD `7f1a093119f12b1f5b79d50bf6d0c951069224e5` and invokes the task venv Python through `-m torch.distributed.run`. All ranks 0–7 in `worker-maps.log` have the exact expected argument vector: both variants, all 14 global token counts 1–8192, EP8, automatic Mega knobs, non-fused split finalize, CUPTI graphs, warmup 3, 100 iterations and raw sample logging. H7168/I2048/E256/top-k8 come from the unchanged benchmark CFG.
- **Shared inputs and weights:** `_run_parallel_mode` creates one shared weight pair per token count and keeps it alive across both variants. `_create_shared_ep_weights` quantizes each canonical matrix once, then permutes packed bytes and E4M3 scales into each backend's layout. Global alpha is one for both paths. `_create_distributed_inputs` uses explicit per-rank seeded generators, making independently created activations, logits and routing bias identical for both variants; each forward repeats the same routing selector. This is a synthetic MoE workload, not a full model forward.
- **Split path included:** routing selection, BF16 dispatch plus routing payloads and invalid-route sanitation, local permutation/GEMMs/activation, separate `moe_unpermute` finalization, and all-to-all combine including its default output staging copy. `--no-fused-finalize` reaches `MoEFinalizeConfig`, then FC2 writes BF16 terms and the separate FP32-weighted unpermute path runs. There is no numeric TMA reduction in this selected finalizer.
- **Mega path included:** the same routing selector, public `MoEEpLayer.forward` input staging, fused dispatch/FC1/SwiGLU/FC2/return, and the external fixed-order FP32 routing reducer of BF16 per-route results. GPU graph replay includes the staging/copies and reducer. Python validation, allocation and scheduling overhead outside captured GPU activities are not part of the reported latency.
- **Timer:** benchmark `_run_distributed_iterations` calls shared `bench_gpu_time` with CUPTI, CUDA graph, cold L2, repeat 100, dry-run 0 and `aggregate_op=max`. `testing/utils.py` flushes a two-L2-sized buffer and synchronizes before each measured replay; flush launches are outside that replay's CPU correlation interval. It groups all correlated kernel/memcpy/memset activities and measures `latest_end - earliest_start`, preserving internal gaps and overlap. The 100 sample vectors are gathered across ranks and combined elementwise with MAX; the benchmark reports the median. Timing excludes host launch-to-first-GPU delay, trailing host synchronization, CUPTI processing, cross-rank result gathering, and sleeps. It is neither a kernel-duration sum nor wall-clock request latency.
- **Preparation excluded:** weight generation/quantization/layout preparation, runtime/workspace setup, compilation, autotuning, graph capture, warmups and L2 flushing. `--warmup 3` is the harness setting; the shared CUPTI utility additionally executes three pre-capture warmup forwards, one eager preparation call and five estimation replays, all untimed. Phrase this as “warmup=3, 100 measured samples,” not “exactly three total untimed forwards.”
- **Autotuning scope:** Mega explicitly evaluates the public four-candidate catalog on staged inputs with hot CUDA graph/event timing, scored as maximum of rank medians; final reported latency is independently cold-L2 CUPTI median of per-iteration rank maxima and also includes routing/public staging. Split uses its existing local MoE autotuner on a preserved copy of actual dispatched inputs; A2A is outside split tactic selection but inside final timing. Structured result evidence establishes 112 Mega rank/token winners, not 112 split selections. Different tuning objectives do not change the final measurement boundary.
- **Actual fallback stack:** all eight worker mappings show system CUDA 13.0 runtime/CUPTI, image NCCL 2.28.8/NVSHMEM 3.4.5 and the isolated CuTe 4.7.1 **cu12 native compiler 12.9** extension. `environment.json` confirms the real direct-BF16 decoder gate is false; split and Mega share that decoder. Installed pip package metadata for other toolkit versions does not establish loaded compiler/runtime versions. Report CUDA 13.0 environment plus native compiler 12.9 explicitly, not a native CUDA 13.0 DSL compiler.

## Qualifications for the refreshed PR table

1. Preserve the numerical topology difference: split casts each rank's weighted partial sum to BF16 before network combine; Mega accumulates all BF16 expert terms in FP32 at the source rank. Both select non-fused expert finalization, but outputs are not required to be bitwise identical. The command omits `--refcheck`; independent numerical tests are separate evidence.
2. This combined run executes split then Mega for each token count. Its paired columns come from one complete sequential sweep. It is not alternating A/B/A repetition, and no confidence interval or noise significance is established by 100 within-row samples alone.
3. Counts are global; 1/2/4 include empty source ranks. Retention remains 8–8192. Split reserves a 4096-token-per-rank capacity budget while launch work uses each row's actual ceil(T/8); Mega uses actual row capacity. These are existing backend/benchmark contracts, not padding every timed split row to 4096 live tokens.
4. Router logits are prepared inputs: routing **selection** is measured; the model's router projection/GEMM is not.
5. After completion, require parser success, normal process exit/`BENCHMARK_COMPLETE`, no traceback or CUPTI fallback warning, and the final saved source/environment closure. The parser validates the encoded method flags and samples, but does not prove a successful CUPTI implementation from a requested `timer` string alone. The saved worker library maps and successful initialization currently support CUPTI use; scan the complete log before publishing.
6. The old CUDA 13.2 table remains historical and has different compiler/runtime/node/source provenance. Replacing the CUDA 13.0 table with this current-head run does not produce a controlled CUDA 13.0 versus CUDA 13.2 comparison.
