# M256/N64 four-shape timing audit

N64 improves T64 by 4.87% in the adjacent comparison, but regresses T4096 by 9.93%. The T1/T8 changes are small (−1.03%/−0.62%) and near the observed control variation. These four observations do not support promoting N64 as the general default; M128 and repeat measurements remain separate work.

The candidate explicitly selects M256/N64/K256, two-CTA instructions and cluster(2,1,1), against the control's M256/N128/K256 default. The three-file proposal supports multiple geometries, so this experiment includes its geometry-dependent implementation together with the N64 knob selection. It preserves the preferred-five-stage fitter, two decode groups acting on the same K tile, and existing scheduling/return controls. Generated resources are separate evidence.

Common knobs: `{"epi_flag_batch": [2, 4], "flag_batch": 4, "group_hint": 512, "load_balance_mode": "atomic_counter", "token_back_mode": "epi_warps"}`. Candidate geometry: `{"cluster_shape_mnk": [2, 1, 1], "mma_tiler_mnk": [256, 64, 256], "use_2cta_instrs": true}`.

Real EP8 on eight B300 GPUs, H7168/I2048/E256/top-k8, global source tokens, BF16 activations/wire and NVFP4 weights. NVIDIA PyTorch image `nvcr.io/nvidia/pytorch:26.05-py3`, toolkit CUDA13.2.78, CuTe DSL4.7.1 with bundled CUDA13.3.27 compiler. Each arm uses three warmups and 100 CUPTI iterations, CUDA graph and cold L2. Reported latency is the median of per-iteration maximum-rank full-forward GPU activity spans. Setup, tuning, compilation and cache flush are excluded. Split retains `--no-fused-finalize`; its tuner reruns for every process/rank rather than replaying fixed choices.

The adjacent control starts 14 m 49 s before N64. This is one ordered pair, not a statistical confidence interval. Split spread includes process, tuner and ordering variation; it is not an error bar for Mega.
