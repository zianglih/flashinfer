## Historical optimization decisions

These rejected experiments used R1/store16 (`916461b3/7a48709e`) or R2 (`store16_no_raw_peek/85f18dc5`: **x16 plus raw-probe removal**), never current x8 `d453eb4/b522ae25`. Ratios are parent/candidate; >1 is faster. Target: EP4 uniform H6144, 256 tokens/rank; native decode: H7168, global T4–512 geometric mean. Ordered comparisons retain drift/AUTO-selection limitations.

`dispatch_exchange_counts_sync` spans local dispatch-grid rendezvous, CTA0 per-expert count publication, cross-rank publication and final local rendezvous, then the dispatch-to-scheduler NB9 arrival. It precedes token pulling and remains intact in current source.

- **Count-ready scheduling:** after acquiring completed packed expert counts, the scheduler could publish usable work before the full dispatch gate; immutable weight TMA/decode could run ahead, while activation readiness still blocked MMA and remote token pulls retained global publication. On R1, CTA1 on ranks 0/1 decoded 1.024/1.408 µs before the representative dispatch-sync end; ranks 2/3 did not. Original release-per-count variant target: **0.9675x**. A prefix-fence revision reached **1.0064x** in an initial R1 target trial. Added to actual R2, however, target **0.981613x**, complete EP4 decode **0.980290x**: rejected. EP8 was stopped incomplete and excluded. Its later codegen execution failed with SIGSEGV (cause unknown); exported **+80 static instructions** are compilation-only evidence, not an execution pass.
- **Parallel payload staging:** epilogue WG0 copied BF16 inputs while dispatch WG2 prepared routes, joining through NB11 before existing grid publication. This overlaps preparation *before* count exchange, not count-dependent work during the global wait. R1 trace overlap was 0.896–1.216 µs; initial target **1.0071x**. On R2, decode EP4 **1.001494x**, EP8 **0.979254x**; fresh fixed-target ABBA **330.499→331.650 µs (0.996529x)**. No demonstrated target benefit justified NB11 or **+8 static instructions**: rejected.

Other rejected directions: full predecode versus original002 (**0.7674x** unqualified pilot; stack/spills); FC1 fragment64 versus original002 (**1.0010x**, +16 instructions, no useful gain); Store32 versus R1 (**0.9973x** target, EP8 decode **0.9858x**, despite per-K savings); Store64 (register-allocation failure, no timing pass); removing both probes versus R1 (**0.9889x** fresh target, EP8 decode **0.9703x**); TMEM-probe-only removal versus R1 (**0.9923x** target). Static savings alone did not establish runtime benefit. R1 x16 itself was subsequently withdrawn at the user's request.
