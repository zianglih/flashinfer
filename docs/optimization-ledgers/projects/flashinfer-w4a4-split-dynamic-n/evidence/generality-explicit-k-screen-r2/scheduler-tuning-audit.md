# FC1 scheduler tuning: read-only integration audit

Recommendation: prefer one universal FC1 scheduler if the fixed C–A–A–C probe supports it. R2 is not retained. The early K3 static results make a universal static default the first option; the design below is only a fallback if another workload needs CLC.

- **Existing facility:** `AutoTuner.rank_tactics(k=2)` profiles the valid set, caches the winner and an in-process ranking, and returns a shortlist. Compound MoE runners already use it. `choose_one` itself is a flat exhaustive loop. `precompile_tactics` only moves preparation; it does not prune or rank candidates. No global autotuner change is needed.
- **Bounded fallback:** rank the current geometry/K candidates using one scheduler, then compare both scheduler values for the best two whole-chain candidates. At the current admitted set this is 160 + at most4 measured candidates, rather than320, excluding the existing optional autotune_v2 fallback race. The two shortlisted base candidates are deliberately remeasured alongside the alternatives; there is no second 160-candidate sweep. Only at most two additional FC1 kernel specializations are needed. The current 160 candidates contain at most 28 distinct FC1 and 28 FC2 geometry/K choices per format/configuration. These are static search-space counts, not measured compilation counts or wall-time estimates.
- **Timing boundary:** both passes must delegate to the unchanged runner's complete `forward`, preserving prepare, FC1, optional per-token quantization, FC2, combine, PDL, cold-L2 graph policy, and all caller kwargs. Do not rank isolated FC1/FC2 phases for this change: that would lose the startup/cache/PDL coupling we are measuring.
- **Important integration trap:** `choose_one` calls `get_valid_tactics(inputs, profile)` without forwarding caller kwargs, despite its broad doc wording. Blindly nesting rank there would lose `nvfp4_4over6` and `aux_stream`. A small private refinement-runner adapter must receive an explicit immutable copy of the call kwargs at the existing wrapper/functional selection sites, and pass them to nested rank. Its ordinary `forward` delegates to the original runner with the actual kwargs. No threadlocal, monkeypatch, or hidden global state. The adapter runs ranking lazily from `get_valid_tactics`, so a final-cache hit does not start the ranking pass again.
- **Cache/schema:** add only an optional internal trailing boolean `fc1_use_clc_scheduler` after the current K pair, normalized in the single parser. Keep outer-3 legacy and outer-4 K entries unchanged; their scheduler default follows the established behavior. Reject the extra field for Rubin and leave W4A16 untouched. Store the explicit boolean in the final compound tactic, forward it only through `_moe_core_impl` and the existing private FC1 launcher, and retain the public signatures. Version refinement cache extras separately; the auxiliary geometry operation name must not overwrite the final operation's winner. Ranked lists are process-local; normal persisted final selections remain sufficient for inference.
- **Safe dedup:** extract the existing launch-time CLC admission expression into one pure helper shared with candidate generation. If the requested CLC value resolves to static because the allocated grid fits, a restricted SM budget applies, or grid-Y exceeds the hardware limit, emit just the static candidate. Use only scalar/shape facts; do not read GPU routing metadata back or prune based on a benchmark/model/token heuristic. Keep resource feasibility in the existing shared planner; do not clone its formulas.
- **Limits:** top two is an explicit tuning-budget choice and can miss a geometry that ranks poorly with one scheduler but wins with the other. Synthetic balanced routing also remains a limitation of both passes. `rank_tactics(k=2)` handles only the nearest profile, so retain lazy per-profile refinement and the existing dynamic profile mapping. Before implementation, test cached/fallback execution, JSON legacy/Rubin compatibility, per-token recipe forwarding, and exact whole-chain callback equivalence. The causal probe may make this additional machinery unnecessary.
