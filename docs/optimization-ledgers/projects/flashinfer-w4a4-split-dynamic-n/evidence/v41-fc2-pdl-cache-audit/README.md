# FC2 startup and cache contract audit

Read-only at retained853; no candidate or timing launched by this audit.

The blockscaled shared core initializes pipelines/TMEM/weight descriptors before its all-role dependency wait at line1121. It then reads num_tiles and route metadata and only afterward begins any operand TMA. FC1's caller selects startup signaling; FC2 selects producer_exit signaling before ring drain. FC2's release fence republishes already-visible routing writes so the finalizer may preload metadata before its own wait. Expert output loads remain after that wait.

The weight A hint is retained EVICT_FIRST only for oneCTA/eight-K-step geometry. SFA, activation B and SFB remain ordinary policy. Prior `cache13_experiment` found B-LAST insufficient, and `pdl_handoff_cache_experiment` output-LAST/combine-FIRST regressed; neither is a fresh candidate simply because TRT uses a different tail. No cache-policy rewrite is justified by the current counters alone.

Existing W4A16 uses a more selective dependency boundary: only the activation-TMA role waits (moe_w4a16_kernel.py around1418), while independent weight/dequantization roles can proceed. Published archived TRT static FC2 source similarly has no dependency wait in LoadTaskA/LoadSfATask and explicit waits in LoadTaskB/LoadSfBTask; its epilogue also waits. That archived source is structural prior art, not the exact selected CLC cubin. The exact selected cubin independently proves five descriptor-prefetch instructions and actualN8; this audit does not infer its dependency order from undecoded SASS.

A concrete next candidate is a direct compile-time `prefetch_weights_before_wait` control, selected by FC2 but disabled by FC1, that preloads one existing A/SFA ring stage while preceding FC1 finishes. B/SFB and every dependent payload read must remain after the grid dependency wait. Do not add an operand stage or change geometry. Keep the existing A-FIRST hint so streamed weights do not displace reusable activations; test any hint change separately.

The required safety contract is explicit: publish completed routing metadata before FC1's startup signal, since FC2 needs expert IDs/limits to locate independent weights before waiting for FC1 output. Reuse the existing metadata publication approach rather than assuming transitive visibility. Peel/reuse the first producer stage without double acquisition/expect-tx or replaying the weight load. Preserve zero-route, idleCTA and twoCTA behavior and the final drains. This is a moderate pipeline change, not a one-line wait relocation. A bounded fixed-tactic T32/128/512 whole-chain C–A–A–C screen plus exact zero-route/partial-route gates can decide whether it merits further work. All dimensions and preload counts should follow compile-time resources; no model/token cutoff.

Important interpretation: current blockscaled FC2 weight traffic cannot overlap FC1 work because the global wait precedes all operand reads. Its overlapping kernel lifetime is mostly allocation/init/wait. Early weight prefetch would add real data overlap, with bandwidth/L2 competition near the FC1 tail as a tradeoff. NCU replay removes this context and is not a substitute for native pipeline medians.
