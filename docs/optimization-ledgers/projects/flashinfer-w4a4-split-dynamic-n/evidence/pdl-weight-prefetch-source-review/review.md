# PDL first-weight-stage prefetch: source review

No source-level synchronization blocker found in the first draft. This is a read-only audit of the source hash receipt beside this note; generated code and changing-input graph replay remain pending.

- **Publication:** the known split chain sorts routes, prepares input, then runs FC1. FC1 executes its dependency wait before the new GPU release and startup signal. The [CUDA13.2 PTX griddepcontrol contract](https://docs.nvidia.com/cuda/archive/13.2.0/parallel-thread-execution/index.html#parallel-synchronization-and-communication-instructions-griddepcontrol) permits a release fence before the launch signal to synchronize with dependent-grid start when both grids share the synchronization domain. The wait completes prerequisite grids and makes their memory operations visible. This supports publishing completed routing metadata through FC1 for this known default-domain chain; it does not authorize early activation reads.
- **Expected bytes:** early warp0 acquires the existing full A/SFA/B/(TMA-SFB) barrier transaction count at stage0/phase1 and issues only A/SFA. The main-loop producer starts at the same state and skips weight issue/acquire only for its initial static tile and K tile0. B and any TMA SFB complete the original byte count after the dependency wait. The cp.async SFB ring begins normally after the wait. No new stage/slot/storage is introduced, and prefetch alone cannot finish the full barrier because B bytes remain outstanding.
- **Roles/no work:** metadata preloads and A/SFA issue are warp0 only. Every role still executes the dependency wait. A CTA without live work performs no early acquire, proceeds through unchanged static empty-loop/tail behavior and reaches final synchronization. Persistent subsequent tiles acquire normally. Geometry remains static one-CTA nonfused scattering; the constructor rejects other scheduler/cluster/output organizations.
- **Standalone/default:** the private host and core knobs default false, and public FC2 remains false. Therefore existing standalone APIs retain their prerequisite wait before metadata consumption. True requires the caller to guarantee weights and metadata ready at grid start; scattering/geometry alone does not prove this. Known-chain opt-in should remain explicit if retained.
- **Per-token boundary:** the per-token split chain inserts quantization and SF-layout conversion between FC1 and FC2. Prove those intervening nodes preserve the publication precondition before broadening opt-in to that path. Default false preserves its current behavior.
- **Attribution:** factoring the weight-load JIT body and adding FC1 release may affect code generation even with prefetch false. Compare clean853, candidate false and candidate true to isolate the prefetch benefit. The source-level K/stage/storage/PDL completion policy otherwise remains unchanged.

Before timing, inspect generated PTX/SASS for only num_tiles/expert_idx plus A/SFA accesses before the FC2 wait, exactly one stage0 expected-byte acquisition, and no dependent B/SFB/routing-weight payload load hoisted across the wait. Exercise changed routes and inputs between graph replays, zero work and persistent work. No GPU jobs were launched by this reviewer.
