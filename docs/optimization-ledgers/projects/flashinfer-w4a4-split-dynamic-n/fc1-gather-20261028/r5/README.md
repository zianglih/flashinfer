# R5 CTA-local128-bit payload gather

Frozen kernel `80dc6ad61791e28776cc79e50bc4ab0828ddfa1b408734fe4c334d3fd8ea5fda`, patch `a1c3f3f330ad061bd2bf2feb0cc87079b841e7db59f237846817c683265b90a1`. The only production-file change owned by this revision is the experimental swap-AB kernel. The existing host gather contract remains unchanged. Scoped hooks passed; hardware qualification is separate and parent-owned.

R5 replaces FC1 Gather4 payload operations with128-bit cp.async issued by the existing128-thread gather warpgroup. Eight lanes copy one128-byte row. Vector tasks flatten nominal rows and Kchunks across the warpgroup. Each thread caches only its distinct original-row byte offsets before the Kloop. All nominal R4 payload rows are copied or zero-filled; there is no dynamic-N pruning. The physical B allocation/pitch is unchanged, including its unused N16 row padding.

For task `t`, row=`(t//8)%b_copy_rows`, Kchunk=`t//(8*b_copy_rows)`, columnbytes=`(t%8)*16`. A16-byte destination is formed from the absolute shared address using the existing SW128 XOR, then expressed relative to the B base. This preserves the historical requirement that a128-byte-aligned base need not be1024-byte-aligned. Source byte offsets retain Int64 multiplication. Each vector is predicated independently against mapped-row validity and logical Kbytes; false copies zero-fill. No invalid routing-map entry is read.

Payload and SF copies now precede the same per-thread local asynchronous arrival. Warp1's existing acquire/fence/elected cluster publication therefore makes both B and SFB ready for leader MMA. Weight TMA announces only A/SFA bytes in gather mode; their count and destination are unchanged. Both producers still acquire the existing operand-empty ring, which MMA releases after all operands are consumed. No new barrier, storage, warp, tactic or runtime option was added. FC2's false specialization reproduces the retained kernel and weight-loader ASTs exactly.

`source_proof.py` checks40 transfer geometries,4,008 live-row states,857,088 absolute-swizzled vector addresses, and470,208 logical-K vector boundaries. It checks source-cache selection and complete disjoint nominal-byte coverage. This does not replace GPU exactness, generated-code resources, or actual async memory-model qualification.

The comparison intentionally changes the copy mechanism, including its default cp.async cache behavior versus Gather4's TMA cache hint. It tests whether local LSU copies avoid the observed group2 Gather4 penalty; it does not isolate a single hardware instruction's cost. The prior13ca B200 cp.async payload experiment passed exact checks but lost prefill relative to Gather4. Its source/traffic evidence remains in `scripts/loader_experiment/README.md`; that historical result is not overwritten. Current R4 timing and staging evidence motivate this bounded recheck with the new dedicated warpgroup/relay schedule.
