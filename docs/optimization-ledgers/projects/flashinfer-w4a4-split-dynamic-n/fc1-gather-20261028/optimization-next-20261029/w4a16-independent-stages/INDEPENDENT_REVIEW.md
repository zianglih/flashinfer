# Independent review: W4 operand stages

Source-reviewed candidate `cf78403f1572bb8fe62f9ab5c3056d6d671bb82224631f572d127322887f44e2` on `ce4a7d8c`. No concrete source defect found. This is a source/alignment review, not a GPU pass or performance recommendation.

- **B storage and transactions:** every B depth use is switched consistently: layout (`moe_w4a16_kernel.py:488`), contiguous full/empty barrier arrays (1076), pipeline creation (1231), regular-TMA producer (1732), MMA consumer (1963), and Gather4 producer (2764). The B tensor stage coordinate always uses its own state. Per-stage TMA bytes and four Gather4 arrivals are unchanged. Full and empty barrier arrays remain adjacent, as required by `PipelineTmaUmma.create`.
- **Independent lifetimes:** raw A and scales keep their common raw state; decoded A retains its separate state. MMA indexes decoded A and B separately, releases both after the K atoms, then advances each ring once (1990–2050). `PipelineState.reset_count` resets only the logical K count, preserving index/phase; it does not realign rings at work-tile boundaries. No ordinal B stage is used for raw or decoded A.
- **Drain/termination:** both B producer paths call `producer_tail_all_stages` (1822,2875), which enumerates the actual pipeline depth and computes each physical slot’s phase from that ring’s next index. It handles unused slots and work counts shorter than the depth without reading A state. Raw and decoded drains use their own depths. No early drain or unchanged hardcoded tail bound was found.
- **CLC/PDL:** routing metadata is copied and its slot released before operand loops. Its fanout and scheduler cursors are unchanged, with no A/B-index correspondence. Gather FC1 still waits for routing publication before roles start; regular-TMA FC2 still waits only in the activation producer while weight work may run ahead. A larger B queue may change backpressure/performance, but introduces no new dependency bypass or circular wait.
- **Alignment check:** `independent_alignment_audit.py` examines actual struct-field order and native M128/CTA K128/256 layout extents, rather than repeating the allocator’s queue proof. In all144 supplied native configurations, the struct remains≤928B and its following tensor starts in the same1024B-aligned slab. Raw packed A, E4M3 SF and BF16 B extents are1024B multiples; output/finalize storage is unchanged. This arithmetic predicts no physical operand/header growth. The existing planner uses BF16-sized scale bytes although E4M3 SF storage is8-bit, leaving at least1168B conservatism in the checked configurations. It is therefore a conservative budget, not an equality with physical allocation.
- **Remaining qualification:** compare actual CuTe `cosize`, buffer addresses/stage strides and total **dynamic** shared memory; CUBIN static SHARED alone is insufficient. Exercise unequal/coprime wrap depths such as A2/B5, repeated persistent tiles, short K below B depth, partial K, one/two-CTA and regular-TMA FC2, plus CLC/PDL. The scope above does not prove arbitrary direct-constructor SMEM-A layouts or nonnative M geometry.
