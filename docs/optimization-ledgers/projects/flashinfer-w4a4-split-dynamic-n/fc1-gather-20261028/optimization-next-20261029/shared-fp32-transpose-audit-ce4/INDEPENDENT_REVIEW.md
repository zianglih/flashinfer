# Independent shared FP32 transpose review

Source: retained `ce4a7d8c`, swap kernel `77a5495c`. Read-only review; CPU mapping proof passed. This is feasible to qualify, not a speedup claim.

- **Mapping:** `independent_mapping_audit.py` derives native coordinates from the actual CUTLASS `Copy_Traits<SM100_TMEM_LOAD_16dp64b16x>` bit layout (`copy_traits_sm100.hpp:1050–1060`), independently of the proposal's formula. All512 words map bijectively to lane=token/register=channel. Sixteen scalar-store bank transactions and sixteen eight-lane128-bit-load transactions are conflict-free in the32-bank/four-byte model. Every vector load is16-byte aligned. Compiler lowering and actual bank counters remain unproved.
- **Explicit indexing:** the XOR uses source word-index bits4–6 and destination bits2–4. These overlap, so `Swizzle<3,2,2>` is illegal (`cute/swizzle.hpp:63`). Explicit scalar offsets and four contiguous aligned word slices are appropriate; do not introduce an invalid CuTe swizzle or silently scalarize the vector loads.
- **Lifetime:** four warp-private512-word slabs need8192B. Keep the128-word SF32 exchange separate. A faster warp can write its SF value into another warp's still-live payload slab before the SF named barrier; the existing per-warp rendezvous cannot prevent that. The CPU receipt includes an alias witness. Two full-warp barriers per serial fragment protect write/read and read/reuse, including the next fragment/token slab. Callers enter on warp-uniform token-slab conditions; lane predicates remain after all exchanges.
- **TMEM:** the shared helper performs no TMEM scratch write. Each STS consumes the corresponding loaded register, so the documented true-register dependency suffices for its value. The old helper's entry `tcgen05.wait::ld` need not be copied solely to protect a now-absent TMEM overwrite. Keep all caller load-completion fences and accumulator release boundaries unchanged. Do not infer general memory ordering from the register dependency.
- **Arithmetic:** gated ordinary activation remains before ownership conversion; per-token gated and ReLU2 remain after conversion. Moving only FP32 bits preserves existing rounding, SF32 pair ownership, SF16 reduction, quantization and output packing. Serial fragments must return independent register tensors before reusing the same private slab.
- **Integration:** one internal direct behavior set from `gather_input`, one shared helper selected through the epilogue's transpose method, and8704B reserved by the same static K/stage planner and final allocation. Regular-TMA/FC2 retains the old helper, scratch sizing and generated code. The common SF pointer can remain at its existing base while payload starts after512B, or vice versa, but every call must use the same nonoverlapping convention.

Expected cost is16 scalar STS sites, four LDS128 sites, two warp barriers and address arithmetic per fragment, plus8192B over today's512B scratch. Compare actual register/local sites, instruction count and planner-selected K/stages before launching. More shared issue work or lost operand stages could outweigh fewer TMEM round trips. Existing matched baseline spills must not grow. The appropriate next boundary is paired compile-only representative FC1 signatures and byte-identical FC2, followed by exact gates only if resources are acceptable.

Official semantics: [PTX bar.warp.sync](https://docs.nvidia.com/cuda/parallel-thread-execution/#parallel-synchronization-and-communication-instructions-bar-warp) orders shared communication between participating lanes; [tcgen05 ordering](https://docs.nvidia.com/cuda/parallel-thread-execution/#tcgen05-memory-consistency-model) guarantees true register dependencies without implying unrelated memory order. The current initial/final completion requirements are therefore distinct from the shared exchange rendezvous.
