## Geometry and resources behind the priorities

- Current swap runtime guards cover434 FC1 and430 FC2 compilations: **all LOCAL_SIZE_BYTES=0**. FC1 initial allocation is168 registers. Reopening register donation solely to remove old spills has no current evidence.
- V3 TP has256 local experts and FC2 logicalK256; N3U TP has512 experts/K640; K3 TP has896/K384; V41F TP has384/K576. Prefill winners therefore execute only1–5 reduction stages in FC2 despite hundreds of expert groups. This is a recurring geometry class, not a model selector.
- V3 TP MX winners are static, N128 at4K andN256 at8K/16K. Their FC1 allocated route rows exceed16-rounded live rows by40.8%,40.9%,21.7%. N3U TP corresponding excess is40.3%,15.6%,17.1%, across dtypes and mixed static/CLC winners.
- N3U EP W4A4 usesM256/N256/K512 at4K, thenM512/N128/K256 at8K/16K. Its larger-token residual grows even as padding falls, supporting inspection of delivery/reuse rather than a padding-only explanation. The older source-bound N3U iKET trace pointed to mainloop/epilogue waits, not startup; it is a mechanism clue, not current475 timing.
- Short-K SMEM stage planning is capacity-based. Reduction is already part of the host compile-cache key. A compile-time improvement could be general, but ring depth also supplies inter-tile run-ahead: measure which initialization/retirement is actually on the critical path before restricting capacity.
- TP16K useful FC2-write and combine-read traffic remains1792MiB each for V3/K3,1408MiB for N3U,960MiB for V41F, before final-output writes. These are logical bytes, not measured DRAM traffic. Removing standalone prepare does not remove this unfused contract.
