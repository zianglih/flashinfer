# Independent native-FC1 audit

Source: `6a48e87c41f2635f44e42d2c4afeaccc3b87d37be7d6b1be33ea8b685c0a073b` in `flashinfer-native-tmem-fc1-review`. Read-only repository review; no GPU launches. `independent_audit.py` and `independent-audit.json` bind the inspected source and 147 captured artifact files.

No concrete arithmetic, ownership, or synchronization blocker was found. Completion of the existing exact gate, including the two added diagnostic MX ReLU² oracle cases, remains a prerequisite to performance measurements.

- **Arithmetic:** the existing `_activate` packed-pair body is AST-identical; only fragment shape and iteration bounds change. For per-token inputs, one guarded lane=token alpha load is broadcast to the native token coordinate before multiplying up/gate and applying activation. `_quantization_params` is unchanged. All other existing methods except `_run_token_group` are unchanged, including cyclic traversal, pipeline setup, and FC2.
- **Scales:** reduce-scatter leaves one scale owner per token. Gated SF32 combines the same owner lane from adjacent 16-channel warps. Both 128-thread shared-memory barriers remain, and token/channel store predicates occur after the collective. Nongated SF32 reduces both unmodified 16-channel halves once, before half0 is scaled in place; the same inverse scale remains live for half1. SF16 reduces each half independently. Invalid tokens cannot contribute to a valid token's reduction.
- **Packed output:** the actual extracted transpose helper, with lane shuffles emulated on CPU, passed 16,384 element checks for each of 4/8/16/32-bit packing. The actual reduction helper passed both 16/32-channel forms, including all-NaN, zero, negative zero, and infinity inputs. This supplements the existing exhaustive symbolic mapping proof; it does not prove uncompiled numerical conversions.
- **Partial/cyclic slabs:** the existing slab selection, channel offsets, route/SF padding expression, and release-step selection remain unchanged. The native epilogue reads both TMEM halves, fences TMEM loads, then releases the same accumulator stage. Subsequent activation/scale conversion/stores use registers or the existing shared scale scratch, so they do not retain TMEM ownership. Skipped protected slabs retain the existing release path.
- **Captured code:** all 13 pairs have unchanged register/shared-memory resources and zero stack/local storage; no LDL/STL or PTX local loads/stores survive. Each kernel's two direct calls target the existing trap stubs, with no unknown indirect control flow in the saved CFG analysis. Both FC2 CUBIN pairs are byte-identical. The saved matrix covers FP4/FP8/BF16 outputs, N16/N128/N256, M512 reuse, gated/per-token/SiTU/GeGLU/ReLU², CLC, and K96. It is not an exhaustive tactic matrix.

The performance tradeoff is real. Per slab, uniform gated FC1 TMEM loads/stores fall from 7/3 to 2/0; per-token and ReLU² fall from 12/6 to 2/0. Most captured FC1 epilogues gain static instruction sites through shuffles, selects, and two 8-element stores in place of a 16-element store; one BF16 N16 case removes 153 sites. These counts establish the mechanism, not latency or end-to-end gains. No source rewrite or extra fallback is proposed from this audit.

Qualification update reported by the gate owner: the two MX ReLU² oracle cases passed. The broader 39-case gate stopped after 25 passes on M512/N128/K8 MXFP4×MXFP8 with 168-byte stack and 21 LDL/21 STL sites in control/MMA work. That combination is absent from the original 13-case capture matrix. A matched retained-control compilation is pending to determine whether the spill predates the candidate. The zero-local statement above applies only to the explicitly audited 13 pairs; performance remains gated.
