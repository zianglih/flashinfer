# W4A16 FC1 gathering: five-warpgroup design audit

Source inspected: `flashinfer-fc1-gather-review` at the existing fork PR8 implementation. This note proposes a new isolated experiment; no W4A16 source was edited or GPU validation run.

## Existing split contract and useful MegaMoE reference

- `flashinfer/fused_moe/cute_dsl/blackwell/moe_w4a16_kernel.py:335`: four WGs / 512 threads: epilogue warps0–3, control warps4–7 (MMA4, scheduler5, weights+scales TMA6, activation TMA7), weight transformation warps8–15 (two independent WGs). Epilogue increases to176 registers; control decreases to80; transforms keep launch128. Budget `128*(176+80+128+128)=65536` is already the full SM register file. A fifth WG cannot be appended with the old targets.
- `flashinfer/moe_ep/cute_dsl/megamoe/bf16_nvfp4/megamoe_kernel.py:248` is the requested five-WG reference: epilogue0–3, control4–7, dispatch8–11, decoders12–19, 640threads. Register targets at1247,1462,1486,1535 are respectively80,144,64,96+96. `frontend.py:372` explicitly compiles `--ptxas-options='-maxrregcount=96'`. Total `128*(144+80+64+96+96)=61440`; no hidden excess register pool is required.
- Recommended split mapping keeps existing role IDs to minimize diffs: epilogue0–3=144, control4–7=80, transform8–11=96, transform12–15=96, new gather16–19=64. Compile FC1 with96 launch registers. Keep FC2's current4WG launch and targets. This is a testable starting point, not a claim96-register transforms or144-register epilogue will remain spill-free; inspect PTXAS local stack and SASS local loads/stores before interpreting timing.
- Bound the existing transform predicate at `moe_w4a16_kernel.py:1813` to its eight warps: currently `warp_idx >= transform_start` would incorrectly run the new gather WG through the decoder. Audit every other open-ended role predicate. Use one uniform redistribution instruction per whole WG and perform donations before epilogue acquisition.

## Wrapper and dataflow changes

- Current `moe_w4a16.py:425–462` sorts routes then launches `prepare` to duplicate BF16 rows into `hidden_workspace`. FC1 reads that expanded tensor; FC2 reads the BF16 intermediate and reuses `hidden_workspace` for output (`:492–524`). Removing initial preparation does **not** remove hidden scratch, since FC2 still needs it for unfused combine.
- FC1 should read original BF16 `x` directly and gather through `permuted_idx_to_expanded_idx[row] // top_k`. Keep sort, route tile boundaries, expert metadata, gated weight layout, output contract and FC2 unchanged. No activation SF pipeline is needed for W4A16.
- Separate original-source row extent from routed output extent inside wrapper. Current `moe_w4a16_kernel.py:849` constructs activations as `(n,k,1)` where `n` is routed rows; the gathering branch must instead use original token count, while output/scheduler still use routed `n`.
- Current `_run_grouped_gemm` sets `num_tokens=0` and `top_k=0` for non-fused output (`moe_w4a16.py:316`). Those values must be provided internally for FC1 gathering. A dedicated internal compile-time `gather_input` controls source interpretation; do not infer gathering from fused output or activation type. Pass the existing routing tensor explicitly as the gather source, without repurposing finalizer semantics. Include the new compile behavior in `_kernel_cache` identity.
- Preserve W4A16 public tactics. FC1 gathering is an internal implementation change, not a new autotune axis. Preserve FC2 regular TMA and4WG configuration.

## Gather implementation and staging

1. Use the fifth WG for all source row lookup and memory issue. Cache four source IDs per participating warp/row group once per work tile; divide by compile-time top_k. Invalid routed rows map to an out-of-bounds descriptor row so hardware supplies zero. No extra preprocessing or global lookup scratch.
2. TMA Gather4 is the preferred first experiment. BF16 means each128-byte gathered row is64elements, so use a64-element descriptor tile rather than the quantized kernel's128/256elements. Distribute `(four-row group,K64 chunk)` tasks across **all four warps**, allowing all to issue even at small N. Reuse current four-warp task distribution (`moe_swap_ab_kernel.py:3641`) and keep source extent dynamic to retain a2D descriptor for one-token inputs (`:2347`).
3. Audit exact physical shared-memory address mapping before reusing the blockscaled helper: split W4A16's `mixed_input_utils.compute_smem_layout` (`moe_w4a16_kernel.py:465`) supplies the real B layout consumed by MMA. A128-byte swizzled Gather4 destination must address that layout's K64 slabs, stage stride and row stride exactly. Do not insert a transpose or extra copy to make a mismatched descriptor work. If this mapping is awkward, direct cp.async into the same layout is the alternative.
4. cp.async alternative: all128 gather threads issue aligned16-byte copies of eight BF16 elements, with mapping/predication cached per tile. Complete local async copies into an mbarrier, then publish the existing B-ready stage only after all participating copies finish. No register payload array is needed. This has finer instruction granularity than Gather4 but avoids a separate permutation and layout conversion.
5. Reuse B stage lifetime and MMA consumer release; do not synchronize gathered B with weight load/dequant completion. Current independent `a_load2trans`, `trans2mma`, and `b_load2mma` pipelines (`:1161–1204`) are correct resource boundaries. MMA needs both A and B just before issue (`:1970`); producers should remain independent.
6. Stage count stays derived from available SMEM/TMEM and actual sizes (`:2620–2793`). Account for any new barrier bytes. Avoid a model/dtype-specific fixed stage count. GatherB can initially use existing B stage count; tuning a separate B-depth is only justified if profiling shows the shared count is a bottleneck.
7. Two-CTA dynamicN needs the same runtime token partition as existing activation TMA (`:1665`), not the allocated staticN/2. Derive each CTA's source-row offset from padded runtimeN. Ensure leader MMA waits for both CTAs' gathered halves before issue and both halves are protected until UMMA release. The existing quantized Gather4 path uses local completion plus cross-CTA publication (`moe_swap_ab_kernel.py:3094–3120,3274–3278`); reuse its demonstrated ownership pattern initially. W4A16 has no activation scales, so a direct TMA transaction barrier may later remove that relay, but that is an unvalidated change requiring explicit CTA-group/barrier-address proof.

## PDL and synchronization hazards

- Existing standalone prepare is more than a copy: it waits for sort then publishes completed routing ancestors before signaling FC1 (`moe_swap_ab_prepare.py:97–105`). Current W4A16 scheduler and weight TMA intentionally run before their own dependency wait (`moe_w4a16_kernel.py:1458,1717`); only activation TMA waits (`:1638`). Removing prepare removes this routing-publication guarantee.
- First safe gather candidate: perform static barrier/descriptor/SMEM/TMEM initialization before PDL wait, then protect **all first routing metadata reads** in FC1, including scheduler's `num_non_exiting_tiles[0]`, not merely payload reads in gather WG. Keep weight/scale prefetch independent after scheduler metadata is ready. FC1 must publish completed sort ancestors before its early signal allows FC2 to use routing without waiting.
- A lean subsequent version can put sort wait in scheduler before metadata reads and in gather before reading global mapping, with tile-info publication carrying acquired scheduler data to weight/MMA/transform/epilogue roles. Explicitly preserve ancestor publication to FC2 before signaling. Do not assume a per-tile shared-memory barrier automatically publishes the whole predecessor grid's global routing arrays to FC2.
- FC2 remains regular TMA and its existing activation-only wait protects intermediate payloads, while weight TMA/dequant can run ahead. Finalizer overlap remains unchanged.
- Tile-info consumer count currently equals `threads_per_cta-32` (`:1219`). Increase only for roles that actually consume it. If activation warp7 becomes a completion relay, it must consistently consume/release tile info; if it becomes inactive, exclude it from the count. All128 gather threads must make matched consumer releases if counted. Audit both CLC and ordinary scheduler exits and zero-work termination.
- Current TMEM allocation barrier includes all512threads (`:363,1247`); new640-thread group must satisfy the same barrier or reduce its membership to only TMEM users as a separate proven change. Gathering should not add a late block-wide synchronization to steady state.

## Initial evidence and retention

Compile one representative one-CTA and two-CTA FC1 for each activation contract (SwiGLU, clamp, SiTU, ReLU2), inspect PTXAS register/spill/local-store evidence and stage counts. Use existing numerical tests for unchanged BF16 math; no new oracle is needed. Run frozen-tactic CUPTI C-A-A-C against PR8 W4A16 baseline, using all four model EP/TP shapes and existing token set, excluding1/2 for retention. Measure full end-to-end and FC1/prepare breakdown because removing prepare trades traffic for repeated per-output-tile gathering. Include both decode and prefill; expected upside is largest where standalone expansion is high, but original rows may be reread by many channel tiles. No speedup claim is established by this audit.
