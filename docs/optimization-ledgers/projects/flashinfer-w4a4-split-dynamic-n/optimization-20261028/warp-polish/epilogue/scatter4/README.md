# Expanded-layout FC2 scatter4 experiment

Frozen, rejected r2 source; the entire scatter4 family is now closed. Retained base `cb35c42f6143aa08546ee1c6c8d6e6913c6cf03f`, unstaged single-file kernel patch. Source hashes are recorded in `source-local.json`. No change to public APIs, legacy/Rubin/W4A16, expanded scratch allocation, route/scale metadata, accumulator math, combine, tactics or stage/capacity selection.

The existing bulk FC2 epilogue writes one128-channel BF16/FP16 row per `cp.async.bulk`. This candidate repacks its shared slab into two64-channel halves, each128bytes wide, and uses rank2 TMA scatter4. Four routed rows are written per half transaction:32transactions rather than64 per64-token slab (16 rather than32 per32-token slab). All four epilogue warps retain distributed issue ownership. The padded136-element capacity and stage stride remain reserved for a causal comparison; only128elements per logical row are now used.

Descriptor: rank2 expanded output tensor, box `[64,1]` in physical contiguous-column/row order,128B swizzle,16B atomicity. Two half-row transfers are required because CUDA tensor-map swizzling restricts the contiguous box width to the swizzle span. Each source four-row group is128B aligned. `stmatrix.trans` keeps its original register fragment and applies the same absolute-byte XOR as the hardware128B swizzle, including the nonzero source-base offset. Positive output-row upper bounds clip invalid routed padding; channel-coordinate clipping handles output tails. No negative store coordinates are generated.

Ownership and ordering: all128 epilogue threads complete stmatrix stores, async-proxy fence and the existing publication barrier before any scatter issue. Each issuing thread commits its own bulk group. The existing read-completion wait plus shared-stage join protects ring overwrite, and the final wait/join protects scratch reuse. TMEM reads, early accumulator release, overlap direction and skipped-CTA release are unchanged. No barrier or wait was added or removed.

`audit_static.py` checks20,480 physical address mappings, aligned scatter sources, complete/disjoint row coverage, and unchanged stage policies/route-scale metadata/FC1/scheduler functions. Python compilation and diff checks pass. The separate exact gate below supplies the GPU correctness evidence.

Completed exact gate: public benchmark closures with explicit existing tactics and source-paired output storage bits; config IDs4,5,6,7,11,12 cover all four modes, N128/256, one/two CTA, Swiglu/SiTU/Relu2, static/CLC, PDLoff/on, and balanced/skewed/empty/reactivated routing.96candidate +96control graph executions,96cross-source comparisons. Record all PTX/SASS and require identical shared stage geometry, combine geometry, and no spill regressions. Frozen-winner CUPTI full-chain timing completed after this gate passed. No sanitizer.

Initial semantic gate failure and correction: candidate32c2a60f compiled but failed the first cross-source exact comparison. The descriptor used `Swizzle(3,3,3)`, which CuTe interpreted as512 copy bits and a32-channel box; the raw scatter instruction therefore wrote half the intended row. A standalone copy probe isolated this without MMA/stmatrix. Correcting the descriptor to the byte-based `Swizzle(3,4,3)` produces1024 copy bits and a `(64,1)` coordinate basis, matching CUTLASS `tcgen05.make_smem_layout_atom(K_SW128, ...)`. The absolute-byte stmatrix XOR and physical shared layout were already correct. No broad layout or policy change was needed.

Corrected candidate d86d47a3 passes64 standalone byte-exact copy probes: BF16/FP16, all eight128-byte source-base phases, and four valid-row extents including positive OOB clipping. The initial failed gate/source/manifest/codegen remain under r1 names; the r2 snapshot contains the corrected candidate. The corrected full-chain gate passed all96 cross-source comparisons against the already-passed96-execution control, avoiding a redundant control rerun. All48 core-kernel pairs retain the same launch/shared/TMEM stage geometry and have zero local memory/stack spills. FC1 and combine resource/instruction counts are identical. The gate compiled64-token/two-stage bulk slabs;32-token layout mappings are statically covered, but no32-token full-chain gate was selected by these configs.


Codegen tradeoff: native `UTMASTG.2D.SCATTER4` halves dynamic store transactions but increases FC2 metadata/register pressure. Static PDL-off register counts for configs4/5/6/7/11/12 increase99→124,150→180,112→144,94→116,116→127,107→117, respectively; instruction increases range94–355. Neither source contains MATCH or local-memory/stack spills; later inspection found uniform-register-to-GPR spills in both sources and implicit issue arbitration despite the absence of MATCH. This candidate requires a clear end-to-end benefit; neutral timing does not justify its added implementation cost.

Matched screen: GPUs0/2/3/4 own V3/V41F/K3/N3U, respectively; each runs NVFP4 then MXFP with C1,A1,A2,C2 phases, tokens4/64/4096/16384, frozen native99f4 winners/routes,10 warmups and100 cold-L2 CUPTI graph samples. The observer records actual FC2 route N, bulk slab/stages and storage geometry so unchanged narrow decode controls remain distinguishable. The initial screen packaging attempt stopped before measurements because a helper file used only for observer hashing was missing; unchanged `arm_contracts.py` and `nested_timing.py` were deployed, failure receipts were preserved, and the same screen restarted. Kernel source remains d86d47a3.

Gate/probe/source/codegen evidence is archived locally in `gate-evidence.tar.gz` (SHA256 `1ae44f6b0128bf087fa9c75b63aeec7700d50ed97563494e585ba1517cbb551d`). Performance evidence was independently collected and checked under `../../scheduler/caac-audit/scatter4/verified/`.


Completed r2 screen:64 cells,48 benchmark processes,25,600 CUPTI samples; source/routes/frozen winners and FC2 geometry match across all CAAC phases. Overall geometric speedup +0.134%, unchanged narrow decode +0.002%, affected prefill +0.265%. All32 prefill cells select bulk64/stages2; all32 decode cells bulk0. First25/last25/last50 prefill diagnostics are +0.104/+0.318/+0.197%, respectively. V3 T16384 W4A4/per-token improve +0.980/+0.667%, but N3U MXFP4x8 T4096 regresses −0.559%; larger V41F/K3 MX T16384 gains vary by sample strata. This is insufficient benefit for retention. Full primary64-cell results and raw provenance are in `../../scheduler/caac-audit/scatter4/verified/RESULTS.md`, `cells.csv`, and `audit.json`.

R3 investigates a concrete codegen defect before closing scatter4: five coordinate R2UR/R2UR.OR conversions, PLOP3 arbitration and backward BRA.U.ANY serialize each lane-owned scatter command. Four warp-uniform groups with elected issuers, combined with once-per-tile sentinel initialization, can remove that issue arbitration without changing the layout or synchronization. The refinement has its own source/gate/screen artifacts in `../scatter4-r3`; r2 evidence and remote source are immutable.

The r3 and r4 refinements also failed retention. R4 reduced register/arbitration overhead but its verified64-cell overall change was only+0.0043% (prefill−0.0024%), insufficient for its added descriptor/metadata/layout policy. No scatter4 source changes were retained; see `../scatter4-r4/README.md`.
