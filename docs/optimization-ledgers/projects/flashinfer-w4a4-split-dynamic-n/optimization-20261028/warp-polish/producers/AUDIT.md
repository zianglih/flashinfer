## Candidates

1. **Role-owned TMA descriptor prefetch** (`descriptor-prefetch.patch`, seven added lines). Warp0 prefetches A/SFA; warp1 prefetches B/SFB before pipeline/TMEM initialization and the payload dependency wait. Descriptor addresses are immutable by-value kernel parameters, not predecessor payload. Each producer performs exactly the descriptor work it later needs; MMA, scheduler and epilogue receive no additional work. No synchronization, pipeline state, byte accounting, memory layout, tactic or public argument changes. Existing Rubin gather/finalize and W4A16 kernels already prefetch descriptors during startup. The fixed prefetch policy applies to every supported dtype, N, CTA group and schedule. This is a hint, so benefit requires measurement; warming descriptor caches could be neutral for already-warm launches.

2. **One activation cache policy for payload and scales** (`activation-sf-cache-policy.patch`, independent of candidate1). The public wrapper already selects `evict_last` for activation B. The new always-TMA SFB helper hardcodes zero, so SFB remains at normal priority while B is retained. Pass the existing private compile-time `activation_cache_policy` through this helper to its existing `.L2::cache_hint` operand. There is no additional TMA transaction or barrier, no new policy selector or axis, and no arithmetic/layout change. This restores consistent input-pair priority under weight prefetch. It may increase L2 pressure; retain only if the four-model/all-format screen supports it.

Retained-r2 PTX confirms both omissions rather than relying only on source inspection: no descriptor-prefetch instruction exists, and `config0-clc1-fc1-pdl1.ptx` lines484/495 use the evict-last immediate for B versus zero for SFB. Descriptor prefetch and scale policy must be measured independently before combining.

## Synchronization and lifetime findings

- One shared operand ring is already minimal: two independently elected producer arrivals announce disjoint weight and activation byte counts; both must finish before the single MMA full wait. Two CTA copies complete the leader's group-total transaction count. One UMMA empty arrival follows every channel MMA. Separating full rings would add MMA work, while sharing unrelated accumulator/metadata phases would unnecessarily couple consumers.
- Keep the weight-role operand tail. Installed CuTe4.8 `PipelineAsync.producer_tail` explicitly waits all empty stages because separate empty-arrival completions are not guaranteed ordered. Last accumulator readiness proves operand reads finished, but is not by itself proof that every earlier asynchronous empty-barrier arrival has retired before CTA shared storage disappears. An all-stage dangling-arrival proof is needed before deleting that tail.
- Keep both producer states persistent across tile boundaries. CLC terminal metadata and static end-of-grid filtering enumerate the same tiles/K stages in both roles. No valid-token or dtype predicate may skip one role's arrival.
- Keep the activation dependency wait before its first B/SFB transfer. Weight, MMA and scheduler may run before it only because prepare publishes immutable routing first. Keep deferred dependency waits on nonpayload roles even on empty/follower paths. The FC1 activation startup release and FC2 weight producer-exit release retain their ancestor-publication owners.
- Potentially defer activation's one payload wait until after its first metadata dequeue; this only exposes a few instructions and moves FC1 successor signaling later. Do not add a first-iteration branch or duplicate a producer loop for that small speculative benefit. Descriptor prefetch cleanly overlaps useful independent startup work without changing the signal boundary.
- Keep group2 full-ring completion remapping, scale S2T on MMA, the initial shared-barrier publication/TMEM allocation join, final CTA join and peer TMEM free handshake. They guard different resource lifetimes. S2T cannot safely move to a TMA warp without another scale-slot ownership protocol.
- Current producer acquire/copy helpers contain repeated warp elections. Removing them through direct PTX or nested elected-only producers would require changing the SDK copy contract and CLC consumer participation; it is not a safe line deletion. Candidate patches preserve all 224 CLC metadata consumers and their immediate releases.
