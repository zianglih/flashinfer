# Sole operand-announcer independent review

Candidate `flashinfer-operand-announcer-review` at retained `cb35c42f6143aa08546ee1c6c8d6e6913c6cf03f`, final Ruff-formatted kernel SHA256 `5d3b3b003b37052671aa362bb2d41166e64dca7e12ae14ab11f6da838a3c9bd4`. Read-only source, SDK and protocol audit. Runtime/codegen gate belongs to the producer agent onGPU1.

**No protocol blocker found.** This removes one elected full-barrier arrival per K-stage and leaves activation loading independent of weight announcement. It does not merge the producers or add a producer rendezvous.

- **Announcement and wait:** The capturedSDK4.8 `PipelineTmaUmma.producer_acquire` first executes `sync_object_empty.wait(index, phase)` and then conditionally announces only in the leader CTA. `arrive_and_expect_tx` elects one thread. The candidate preserves that path for weights, changes expected arrival count2→1, and replaces only the activation acquire with the identical local empty wait. No try-acquire token was used, so no alternate wait behavior is lost.
- **CTA group2:** Each CTA retains its local A/SFA and B/SFB transfers. Native group2 atoms retain their barrier routing; the unchanged raw SFB helper clears the CTA-rank bit to route both local SFB completions to the leader. The leader weight warp alone announces the sum for both CTAs. Follower weight A/SFA can complete before that announcement, as can either activation producer; all are protected by the pending arrival count1. The follower's local full barrier is not waited or announced, as before. Both local empty barriers remain required.
- **Transaction count:** Let `W = channel_tiles*(128*tile_k*weight_bits/8 + sf_stage_bytes)` and `A = b_copy_rows*tile_k*activation_bits/8 + sfb_stage_bytes`. The new count is exactly `cta_group_size*(W+A)`, equal to the sum of the former two announcements. SFB is replicated full-N in each CTA, so it correctly remains inside the CTA-group multiplier; B's rows are partitioned and `b_copy_rows=route_tile/cta_group_size`. The dynamic live-token count does not shrink issued TMA extents. MXFP4x8 may reserve an8-bit-per-element shared weight layout for hardware unpack/padding, but the announcement keeps the same4-bit payload count and unchanged TMA format as the validated control. Counting expanded shared allocation instead would change the established transfer contract and is not part of this patch.
- **Early completion:** Before announcement the pending arrival remains1, and transaction count can be negative. After the atomic weight arrive-and-expect, pending arrival is0 and transaction count equals total bytes minus completed bytes. Full completion requires both counters0, so it cannot occur until all operand transfers complete. Producer's exhaustive subset proof covers early follower/activation completion and all later mixtures. The largest enumerated group count425,984 is within the signed transaction-count limit1,048,575 in either direction; it also covers a conservative superset of realizable geometries.
- **Reused phases:** A full-barrier phase completes before the leader MMA's successful full wait. Only after consuming both channel tiles does its group2 commit release local empty barriers. Thus either producer's next use of the same stage is ordered after that successful full wait and after the full barrier reset to next phase/arrival1. Both producer states retain identical index advancement and parity flipping. Neither producer can lap an unconsumed stage, including when activation or follower weight runs ahead. This inductive relationship applies to arbitrary K counts and ring wraps, not only startup.
- **Initialization, tail and PDL:** Warp0 barrier initialization and the existing TMEM/cluster rendezvous are unchanged. Inherited `producer_tail` only waits on every local empty stage; it does not add another full announcement. The existing single weight tail remains valid because empty release depends on all operands. All PDL payload waits, ancestor publication, CLC metadata release counts, final CTA joins and peer TMEM deallocation stay unchanged.

The source diff has exactly three semantic changes and one ownership-comment update. Public signatures, tactic enumeration, layouts, cache hints, TMA calls, MMA instructions and stage selection are unchanged. Required codegen checks are one elected leader arrival with the summed bytes, disappearance of the activation arrival, unchanged empty waits and group2 release, and no spills. No performance claim follows from this review alone.

## Source basis

`producers/next-audit/sdk48-PipelineTmaUmma.py` is the captured installedSDK source. The local CUTLASS `pipeline/helpers.py` and `pipeline/sm90.py` supply the election, phase construction, empty wait and tail implementations. `producers/next-audit/verify_static.py` restores the three original AST changes and enumerates478 transfer geometries/1,693,696 counter states; this reviewer inspected that script and its proof rather than duplicating its test.

[CUDA13.2.2 PTX mbarrier semantics](https://docs.nvidia.com/cuda/archive/13.2.2/parallel-thread-execution/index.html#parallel-synchronization-and-communication-instructions-mbarrier-contents) permit signed transaction counts and require zero arrivals plus zero transactions for phase completion. Reuse must follow a successful completion wait, which the MMA/empty-release chain supplies. [The tensor-copy contract](https://docs.nvidia.com/cuda/archive/13.2.2/parallel-thread-execution/index.html#data-movement-and-conversion-instructions-cp-async-bulk-tensor) allows group2 copies to signal the local or peer CTA barrier and counts copied bytes. FP4 padded regions are uninitialized padding, not additional payload.

## Independent exact/codegen gate audit

`check_gate.py` independently verifies all 724 manifest hashes, source identity, all 176 paired final-storage-byte replay hashes, and all 88 compiled geometry pairs. Both CTA group sizes, CLC modes and PDL modes are covered. Every generated full-ring initializer changes from count 2 to count 1; each combined operand expectation exactly equals the prior A/SFA plus B/SFB expectations, including packed FP4 payload bytes. No local-memory spills; shared, stack and local resource totals are unchanged. PDL-disabled kernels still contain no `griddepcontrol` sites.

Across the paired kernel images, `SYNCS.ARRIVE.TRANS64` static sites decrease 1464 → 1112. Register deltas: 81 unchanged, four −2, one −1, two +2. These are static code and resource counts, not dynamically executed instruction counts.

One codegen caveat is explicit: config 7 FC2 (`w4a8`, N128/M128, K=2304 / tileK128 = 18 iterations) changes from a 2-way-unrolled activation loop to 18 fully unrolled iterations. In control `config7-clc0-fc2-pdl0.ptx`, block `BB0_36` executes two activation waits, advances K by 2, and branches until 18. Candidate contains immediate K offsets 0 through 17 and no activation K-loop backedge. It therefore gains 16 static wait sites in each CLC/PDL combination, while executing the same 18 empty waits per tile. Static PDL-off/on register use rises 94 → 96; CLC PDL-off falls 96 → 94 and CLC PDL-on is unchanged. Do not describe every generated wait count as unchanged.

The matched CAAC screen is the separate performance check; the codegen gate does not justify an end-to-end speedup claim.
