The only r2 change is the bulk FC2 tail: every slab containing at least one valid row uses the existing ordinary TMA store. Wholly invalid slabs are skipped. The four host files, tuning choices, allocation sizes, pipeline stage calculation, scale rounding and full-slab body are unchanged from r1. Unused `output_tensor` forwarding is removed from the two bulk helpers.

The route owns `route_tile` padded rows, and a slab's row interval stays inside that tile. Both CTAs store separate 128-channel regions; the TMA descriptor clips the global channel boundary. Combine reads only the inverse-mapped valid rows. Padding values are deliberately unspecified and unobserved: dynamic-N may leave some allocated accumulator columns unwritten, and those columns are copied only into ignored padding. Scale/conversion is pointwise and the native STMatrix layout preserves token ownership, so invalid values cannot influence valid rows.

For the overlapped N256 accumulator windows, reverse traversal first consumes the last 64 columns and forward traversal first consumes the first 64 columns. The existing full-slab read fence/release remains in exactly that position. If the release-boundary slab is wholly invalid, explicit release is retained. All subsequent reads are outside the next accumulator's overlapping window. Per-issuer shared-stage waits, publication barrier and final drain remain unchanged; skipped slabs can cause a conservative wait but cannot omit a needed wait.

`protocol_audit.py` checks 3,088 route/slab/CTA/direction/valid-count combinations, proves exact-once valid-row coverage plus bounded padding writes, and verifies the full nonempty-slab body AST is unchanged. Scoped pre-commit and whitespace checks pass. This is source/CPU qualification only; runtime exact/codegen qualification is pending. It does not claim initialized padding, sanitizer qualification, or unchanged device instruction counts.

The narrow N16/N64 SIMT paths are unchanged. Therefore this edit removes the source duplication responsible for the r1 bulk-tail code-size growth, but is not a proposed explanation or fix for the r1 N3U TP4 MXFP4x8 decode regression.
