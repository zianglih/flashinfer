# Padded routed FC2 device implementation

The unstaged kernel change is based on `61249e0bbd40dd2c6e583e4e48ff95e055a3c7f8`. Kernel SHA256: `ff6993cbaf412222b15ac5bc27ae421fbbcc30c7b1520475c0e35b7d2033620f`.

- Unfused FC2 output has the same padded row extent as the routed input. Every destination is `route_start + token_offset + lane`; only fused finalize maps back to original tokens. Compact prefix/indices, constructor flag, pointer parameters and route-start forwarding are removed.
- Complete valid epilogue slabs use the existing ordinary 2D TMA stores. The final partial slab reuses `_run_token_group` and its predicated vectorized SIMT stores. Entirely invalid groups are skipped. No per-row bulk copy or unswizzled shared-memory store remains.
- The full slab uses the same TMEM load, packed scaling, output conversion and SW128 STMatrix mapping. Removing the old per-row bulk layout also removes its eight unused padding elements: shared allocation and the capacity planner now use `tokens * 128 * stages` elements. This can naturally change automatic operand stages at a shared-memory capacity boundary; no threshold or tactic axis was added.
- Per-token scale indexing and output-scale rounding remain in the existing metadata arithmetic. Uniform-scale paths do not build unused row/scale arrays. Fused output still reads the route mapping and routing weights; FC1 math/quantization methods are AST-identical.
- Forward/reverse accumulator overlap releases exactly once, after all live reads in the protected first 64 walk columns. A partial final 32-row subgroup releases after its TMEM transpose; a missing final subgroup performs the existing explicit fence/release. Partial SIMT stores use TMEM scratch only, so outstanding shared-memory TMA reads remain untouched.
- TMA full slabs form a contiguous interval in either traversal direction. `wait_group(stages - 1)` plus the existing epilogue barrier precedes shared-stage reuse, and the final drain/barrier remains. Two-CTA channels still have independent 128-channel ownership and unchanged collective accumulator release.

`kernel_protocol_audit.py` exhaustively models 1,544 valid-count/slab/direction combinations, including 0/17/31/32/33/63/64/65/127/128/129/255/256 boundaries, and verifies exact valid-row coverage, one overlap release, reuse safety and SW128 bounds. This is a source protocol check, not runtime qualification. Scoped pre-commit and `git diff --check` pass. GPU compile/exact/performance qualification remains pending; no sanitizer or GPU run was launched by this implementation task.
