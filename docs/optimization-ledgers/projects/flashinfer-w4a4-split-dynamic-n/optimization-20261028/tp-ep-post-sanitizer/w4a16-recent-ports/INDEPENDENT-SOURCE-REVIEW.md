# Independent review of the two W4A16 ports

Read-only review of both isolated kernels against `fd72759b15b8d417d6c791c0382f90d14262a8e4`. No source-level blocker found. GPU qualification remains source-bound to each gate.

**Packed FC2 alpha multiplication:** the new branch runs only for the non-gated, non-fused-finalize epilogue. It performs the existing single FP32 alpha multiplication with packed RN instructions before the TMA/SIMT layout split, then both stores retain the same BF16 conversion. `retile` is a value permutation, so moving the multiplication across it does not change the arithmetic order. Gated FC1 never enters this loop; Relu2 retains its own existing packed multiply; fused finalize retains its original alpha/routing-scale treatment. The source adds no memory operation, barrier, allocation or tactic. The fragment pairing is already used by the adjacent Relu2 path and should be qualified at the smallest N/SIMT geometry, including both weight layouts and scale updates.

**Static K-tail MMA:** `wrapper.k` is `cutlass.Constexpr[int]`; both weight-tensor K and MMA stage geometry are static. The outer section loop is `range_constexpr`, and the full-stage loop explicitly retains `unroll=1`. Each full stage issues the original atom count; only the final partial stage uses the constant ceiling of its logical K divided by the existing MMA atom width. Both dynamic-N and static-N issue loops use that compile-time count, with no new runtime atom predicate. Each consumed stage still waits, issues, releases and advances exactly once. The tail-only case starts at K-stage0, retaining the first-atom accumulator initialization, and the existing readiness peek crosses the full/tail boundary unchanged. Producer loading, dequantization, TMEM storage and releases are untouched. Full-K-divisible variants should remain code-identical; partial cases need codegen confirmation of the expected atom reduction and no new spills.

**Combined qualification:** the source edits are disjoint but share one compiled kernel, so independent passes do not prove combined compiler resource behavior or additive timing. If both are retained, qualify the merged source with the existing paired exact/codegen harness, including a partial K (notably V41F TP4 K576), full K, smallest SIMT output and TMA output, old/new weight layouts, and representative PDL/CLC and two-CTA cases. Check resource/spill counts again. Measure the combined source against the common control before claiming combined performance; keep the separate32-cell screens as causal attribution.
