## Isolated candidate: carry an operand-readiness probe

Active review checkout: `../../flashinfer-mma-ready-peek-review`, independent `.git` and Git common directory inside this project, based exactly on `d1767be1`. Only the kernel file is modified, **11 inserted / 1 deleted lines**, unstaged. No canonical, sanitizer, public API, tactic, producer, storage, register-budget, or cache-policy edits.

Source precedent: current SM100 MegaMoE `moe_ep/kernel_src/sm100/next_cutedsl_megamoe/src/sources/kernel_src/blackwell/inference/mega/block_scaled_swap_ab_fc12_mainloop.py:1089–1118` probes operand readiness before accumulator acquire, then probes the next operand stage before current S2T/MMA issue. The split kernel currently begins with a blocking operand wait after accumulator acquire and repeats it after each issued stage.

Candidate changes only that MMA-side sequence:

1. Clone the current operand-consumer state, advance the clone once, and probe the current state before accumulator acquire.
2. Pass the probe token to the existing `consumer_wait`; unsuccessful probes retain the original blocking wait.
3. Probe the next state only when another K tile exists, then issue the unchanged scale copies, MMAs, and shared-stage release.
4. Advance both state trackers and carry the next token. Reinitialize the lookahead from the real consumer at each persistent work tile.

**Ordering proof:** the token is valid only for the exact `(slot, phase)` tested. A successful full-phase probe has observed all operand completion; no producer can recycle that generation until this same MMA consumer issues its unchanged empty release. A failed probe skips nothing. Looking ahead does not acquire or release a slot, announce bytes, access operand payload, or issue work. For a one-slot ring the next probe addresses the opposite phase and can simply fail until the current slot is released; it cannot authorize reuse early. The terminal `True` sentinel is never consumed, because the K loop ends and the next persistent tile obtains a fresh probe. All leader/follower participation, PDL, S2T ordering, output arithmetic, and tails remain unchanged.

**Expected benefit / uncertainty:** overlap barrier-readiness checks with the accumulator stall and current-stage issue, potentially reducing control bubbles. This is not guaranteed to remove instructions: false probes add a test and branch, plus a small state live range. TP's short reductions may expose that overhead more strongly; no dtype/model exception should be added to conceal it. Existing W4A16 dual-ring readiness experiments were neutral/regressive, so the MegaMoE precedent is a reason for a bounded trial, not a performance claim.

Source-only checks are recorded in `mma-ready-peek-static.json`: whole-module AST equality after removing only the probe statements and restoring the original wait call; clean canonical source/index; one unstaged candidate path; project-local independent Git metadata; `git diff --check`; and 1,188,864 symbolic state transitions over ring depths 1–16, K-tile counts 1–128, and nine persistent tiles. `check_mma_peek.py` imports no FlashInfer/CUDA code. It does not prove emitted memory ordering, spill behavior, runtime correctness, or speed.

After the full sanitizer completes, first inspect actual CuTe 4.8 compiled output and exact replay on single-/two-CTA, static/CLC, short/long K, partial/empty/reactivated routes, and both PDL states. Verify successful-token bypass refers to the intended generation, all original arrival/release counts remain, no spills, and unchanged allocations. Then use paired same-route/same-tactic CUPTI comparisons across both TP and EP before a fresh-tuning retention decision. Do not change producer-side readiness in the same candidate.

## TP-specific observations, without problem-specific policy

Replacing EP with TP changes all four models' work geometry: all experts become local and FC1 channels / FC2 reduction shrink. Current local intermediates would be V3 256, V41F 576, K3 384 and N3U 640. The stage planner derives capacity from actual layout sizes (1498–1758), and the rings intentionally persist across output tiles. Therefore `min(num_stages, k_tiles)` is **not** a justified general storage cap: it can remove cross-tile weight prefetch. Profile producer-empty, MMA-ready, accumulator-empty, and scheduler ranges before changing that policy.

V41F TP4 exposes a genuine current support boundary: SF32 `can_implement` requires `k % (4*sf_vec_size) == 0` (1843), rejecting FC2 K576. Unified CuTe MX weight preparation also requires intermediate alignment128 (`prepare.py:2627`), as do TRTLLM's MX preparation helpers (531–543 and 844–848). The current benchmark policy skips configurations supported by neither non-swap CuTe nor TRTLLM, including K3 MXFP8 and both V41F TP4 MX formats; do not silently change logical dimensions to populate those cells. The scheduler agent owns compile-time partial-K handling toward SM103 NVFP4 K96, separately from this readiness candidate. TRTLLM low-level block-scale APIs expose `valid_intermediate_size`; old CuTe does not have that logical-versus-physical dimension parameter. If a padding adapter is considered later, it must separately pad gate/up halves and FC2 columns from the same original weights, preserve scale-block semantics, and label logical versus physical dimensions.

## Prior evidence that closes tempting repeats

- **Protected-prefix output deferral is closed.** The older `scripts/pipeline_acc_overlap_audit_20261027/README.md` said unimplemented, but later evidence supersedes it. `scripts/perf_round_20261027/epilogue-overlap` achieved earlier release with 184-byte stack / 83 LDL / 32 STL sites. The resource-policy composition was subsequently neutral except a small per-token cell (`register-overlap-v2/decision.json`). A later spill-free bounded version in `old-cute-comparison-20261027/fc1-prefix/README.md` averaged −0.93% over four completed brackets, including −2.54% N3U per-token4096. Do not recreate any of these.
- **The per-token single-transpose design is a different rejected mechanism.** It adds native-token scale shuffles and delays the newer release point through activation. `optimization-20261028/warp-polish/producers/next-audit/CLOSED_LEADS.md` preserves the distinction.
- **Shared operand announcement is already retained.** `optimization-20261028/warp-polish/producers/next-audit/RETENTION.md` records one fewer full-barrier arrival per K stage, with actual independent producers and complete group byte accounting. No second announcement remains to remove.
- **W4A16's independent operand rings are justified by transform lifetimes.** `w4a16-perf-20261027/sync/audit.md` explains why packed W/SF, transformed W, and activation rings have different depths/last users. Importing that extra ring structure into blockscaled MMA would add control without its dequantization dependency.
- **FlashMLA validates explicit ownership and teardown, not arbitrary early cancellation.** Pinned `references/flashmla` commit `395cb3af...`, core-attention `kernel.cuh:1188–1212`, retains response empty/full completion and a two-CTA terminal drain. The local `scripts/clc_reference_audit_20261026/flashmla.md` and subsequent elected-owner/request-ahead ledgers document why those patterns are not free wins for short MoE jobs.
- Descriptor prefetch, SFB multicast, extra SF publishers/rings, metadata-depth axes, request-before-metadata-acquire, TMEM-startup participant splitting, K96, runtime K-tail MMA predication, SF32 double-buffer scratch, scatter4, and deferred output drains already have negative/neutral evidence. Preserve the closed-lead links in `old-cute-comparison-20261027/wide-prefill-stage-audit.md` and `optimization-20261028/warp-polish/SYNCHRONIZATION_AUDIT.md`.

Current MegaMoE also illustrates a larger, structurally different overlap design: preload raw protected accumulators, release immediately, and borrow a disjoint accumulator subtile as transpose scratch (`block_scaled_swap_ab_fc12_epilogue.py:1705–1765`). That is not the rejected transformed-prefix buffering. It would require a new scratch-ownership proof and substantially more live raw registers (up to protected-columns + one32-column scratch slab per lane). No source change or trial is proposed here; only revisit if traces show the retained in-place transpose dominates and the small readiness candidate is exhausted.
