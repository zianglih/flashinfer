# Independent K96 host/storage review

Source-only review: host SHA8425b33e4a074e2a14f5dcda7e12d05df2e09952358dbe05964e773e55abe33f, kernel SHA1f65f34354afbfb97183f422f24366ba2f113174d5b26f21cdea5f0082b835a1 (r1 with formatting). No blocker found in capability dispatch, stage ownership, or the alignment/capacity accounting. This does not qualify generated descriptors, scale placement, numerical behavior, or performance.

- The private launcher capability is SM103 + FP4×FP4 + SF16. Existing device-index/dtype/SF cache fields determine that choice, so it adds no independent tactic axis or new public contract. Legacy/Rubin/W4A16 are untouched. The constructor rejects unsupported explicit K96 operand types.
- The1024B operand alignment reaches both automatic K-step selection and final stage/scratch sizing. Every admitted FP4 K256/K512 A/B/SFA/SFB slab is a multiple of1024 bytes, including N16 with two CTAs and the M512 channel reuse. Therefore only the first A slab needs new alignment padding; B and the end of the struct remain aligned. `_pipeline_metadata_bytes` reserves1024 beyond the rounded header, covering the TMEM deallocation barrier and worst-case A padding. An independent arithmetic field-layout model checked34,560 combinations of geometry, stages, accumulator depth, CLC metadata depth, and scratch size; its actual extent never exceeded the planner. See `k96-r1-independent-proof.json`. Actual CuTe struct/layout lowering still needs the compile gate.
- The mixed plans preserve acquired-stage ownership: K256 emits96+96+64; K512 emits96×4+64×2. For every64-aligned partial extent, the static sequence covers exactly that extent, all SF indices remain within the existing stage allocation, and `next_src` names a256-value segment inside the same acquired stage. Both channel tiles still precede the original single operand release. No producer arrival, barrier count or lifecycle changes.
- Raw descriptor addressing follows the earlier tested canonical-K-major probe and CUTLASS absolute-LBO constructor. Current K256/K512 FP4 layouts use a128-byte K slab; start offsets are multiples of32values/16bytes, while first stage and subsequent slab origins are1024-byte aligned. The gate must still inspect the actual generated descriptor's absolute-LBO/base-offset bits and SW128 lowering, especially the K192→288 crossing in a K512 stage.
- The single-SF iteration view follows the established dense CUTLASS view-building pattern while retaining the current public global layout and original S2T copies. SFA is one128-row block per local MMA channel tile; SFB uses the full logical row-block count, including two blocks for N256, consistent with the current two-CTA local-scale copy contract. The extra M512 SFA bank is rebuilt from its existing independent iterator. This is plausible by source, not a proof of the lowering's row/bank addressing. Required exact/codegen cases are N256 one/two-CTA, M512 with its valid N≤128, both K256/K512, tails192/384, dynamic partial N, and varied scale bytes. Check both SFB row blocks and nonzero SF data-ID offsets.
- K96 changes native accumulator update grouping. The current K64 oracle cannot establish bit exactness merely by algebra. The producer-owned reference extension and adversarial exact gate remain prerequisites; preserve one shared reference implementation and zero tolerance.

The rejected MMA readiness-peek change is not present in this candidate. Its review copy has been removed, and its local results/probes/evidence remain separate.
