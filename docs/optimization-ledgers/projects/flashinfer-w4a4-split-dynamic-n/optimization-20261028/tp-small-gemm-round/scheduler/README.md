# CLC route-ticket audit and candidate

Base: `1054743780dda2919c1424124c1e3258248b8c19`. One active review checkout: `flashinfer-scheduler-ticket-review`. Only the blockscaled swap-AB kernel is changed; ordinary scheduling, tactic enumeration and W4A16 remain in scope-preserving control paths.

The CLC scheduler already has `(route, channel)` coordinates but publishes a linear tile identifier. Weight, activation and epilogue roles reconstruct route by constant division; weight and epilogue also reconstruct channel by remainder. The metadata allocation reserves four int32 words, while only three are used. The candidate publishes route in the fourth word, then reconstructs channel using multiply/subtract. This is a per-ticket instruction reduction hypothesis, particularly relevant to short GEMMs with non-power-of-two channel tile counts. It is not yet a measured bottleneck attribution or speedup.

The static path retains the original quotient/remainder expressions. Weight channel indexing is explicitly computed outside its K loop; other TMA operands, descriptors, byte counts and stage lifetimes are unchanged. The scheduler still acquires metadata before cancellation, publishes one work item per ticket and drains the same response ring. Every consumer reads all required fields before its existing release. Terminal tickets still carry tile=-1; their unused route value never indexes payload. Storage size/alignment, arrival counts, queue depth and MMA/epilogue barriers are unchanged.

Prior directions deliberately excluded: deeper CLC metadata queues, request-before-acquire, centralized static metadata, elected per-warp consumer broadcasts and MMA readiness peeks already regressed or added work in the local ledger. References: `CLC_GENERALITY_2026-10-27.md`, `scripts/clc_regular_tma_experiment/AUDIT.md`, `scripts/clc_metadata_single_owner_20261026/consumer-publication-audit.md`, `optimization-20261028/tp-ep-post-sanitizer/mma-peek-gate/RESULTS.md`, and `optimization-20261028/warp-polish/SYNCHRONIZATION_AUDIT.md`.

A possible SF-copy/accumulator-wait reorder is not implemented: the SF TMEM lifetime and previous MMA completion require an explicit ordering proof. Existing aggregate barrier-stall counters do not justify removing or moving that wait.

Qualification plan: source-paired exact graph replays and native code comparison on primary GPUs1–2, fixed explicit existing tactics, PDL on, static and CLC. Four scaled formats at H768/I640 exercise TP-like channel counts3/5/10, partial K and one/two CTA; an H384/I2304 mixed-format control exercises a longer EP-like reduction. Count integer instructions and shared metadata loads/stores, registers and both uniform/local spills. No sanitizer, AUTO, timing or public changes in this stage. Root coordinates any subsequent frozen-winner timing.
