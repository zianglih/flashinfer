# Compact FC2 affine-tail index candidate

Base: `1054743780dda2919c1424124c1e3258248b8c19`. The candidate was rejected after repeated prefill slowdowns; its isolated source copies were removed after verification. Canonical and the shared control are unchanged. Only `_run_bulk_direction` tail row addressing changes. No new tactic, public option, dtype/model/shape policy, arithmetic, shared-memory layout, barriers, accumulator release or output allocation changes.

The compact layout already guarantees output row `tile_prefix + tile_local_row`. The previous tail path nevertheless prepares one output-row register per32-token group, selects a group, and broadcasts its lane with a warp shuffle. The candidate derives the issuing lane's final row directly. Expanded output retains the original routing-map path. Per-token scale lookups and rounding remain unchanged. The now-unused compact output-row array can be eliminated by compilation; emitted instructions and resource use decide whether that occurs.

`ownership-proof.json` checks18,048 live tail row cases across N128/256, slab32/64, every live-token count and every issuing warp/lane. Invalid lanes remain under the existing predicates. This is distinct from the rejected common-STMatrix rewrite, which changed address/expression merging and grew registers, and from scatter4, which changed store issue ownership. Neither is repeated.

The historical d1767 profiles show low TP FC2 tensor utilization (~20% for K3 MXFP4x8), significant output traffic and long-scoreboard waits. Those profiles predate retained compact2D-TMA output; they motivate investigating output instruction overhead but are not evidence of a current bottleneck or a performance gain. Current integer-MMA gate artifacts also show MX FC1 uniform-register spills (12/12 MOV.SPILL/R2UR.FILL sites for M512N128;8/8 for M256N64), despite zero local/stack storage. This candidate does not target FC1 and must leave those streams/resources unchanged.

Qualification uses the maintained source-paired exact/graph/codegen helper, updated for the current private output-workspace and integer native-MMA contracts. Initial eight configurations span four formats, N64/128/256, M128/256/512, static/CLC, PDL off/on, short K384, balanced/skewed/empty/reactivated routing, and compact prefix/index invariants. Persistent native C++ cache targets are reused with separate control/candidate workspace roots and private compiler directories.

The main gate and supplemental 32-row, one-stage scratch gate passed: 192 paired exact replay comparisons, 96 GEMM pairs and 10 combine pairs. All 40 affected FC2 pairs remove 12–98 non-NOP instructions and 2–16 shuffles, with unchanged or reduced registers (up to 24 fewer). Uniform-register spill/fill counts are unchanged; local and stack traffic remain zero. Unaffected instruction streams and resource counts are identical. `gate-audit.json` binds the independently verified 922-file archive and raw artifacts. The initial supplemental harness requested a depth that still realized 64-row scratch; it failed on unchanged control before candidate compilation. That attempt remains archived, and the corrected harness derives an existing explicit depth that realizes 32×1 scratch. There is no production policy change.

The 144-cell timing screen uses four models in EP and TP, tokens 4/64/4096/16384, all supported format arms, and unchanged W4A16 as a sanity arm. It freezes the retained 83df winners and routing, performs C-A-A-C with 10 warmups and 100 strict cold-L2 CUPTI samples per phase, and aggregates the paired pass medians geometrically. No retuning, external-baseline rerun, or sanitizer is part of this experiment. `launch_perf_remote.py`, `run_perf.py`, and `audit_perf.py` preserve the exact launch and verification contract; timing results remain separate from the exact/codegen gate.
