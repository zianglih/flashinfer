## Final ownership and synchronization

- **Bounds:** `moe_swap_ab_prepare.py:153–185` publishes one immutable map per live expert/output. Each map retains the allocation base and clips the row dimension to the expert's absolute end. Consumers retain absolute routed-row coordinates, so a lower-bound map or per-expert base alignment is unnecessary. Zero-route experts have no consumers. Output channel dimensions clip two-CTA channel tails too.
- **Publication:** `moe_swap_ab_output.py:37–57` copies the template, synchronizes its warp, updates the map, synchronizes field writers, then uses `tensormap.cp_fenceproxy...sync.aligned` to publish it. Shared scratch has explicit 128-byte alignment. No trailing warp barrier is required after this synchronous copy/release, and immutable entries need no hot-path update or TMA-drain protocol.
- **PDL:** prepare signals dependents early for weight startup, but the signal precedes descriptor publication. Swap-AB's epilogue has its existing startup dependency wait, so it safely acquires a new expert map **before** accumulator wait (`moe_swap_ab_kernel.py:2803–2815`). W4's activation producer is the only role with that dependency wait (`moe_w4a16_kernel.py:1658–1673`); its epilogue therefore acquires **after** accumulator readiness (`:2205–2217`). Hoisting W4 acquisition without another ordering mechanism would be incorrect.
- **Acquisition:** both kernels cache the most recently acquired expert per CTA. Only store-issuing epilogue warps execute the fence. CLC may change expert order; changes refresh the pointer/fence. Repeated acquisition for the same consecutive expert has already been removed. Reacquiring when a different expert returns is conservative and avoids an expert-sized cache or new policy.
- **Swap-AB fragment mapping:** N16 uses `Ld16x256bOp(Repetition(2))`, eight FP32 values/lane for each 16-channel half. Both halves cover 32 channels/warp. Two `stmatrix.x4.trans` groups select words `(0,1,4,5)` then `(2,3,6,7)`, covering 32x16 half values. Per-token scaling selects the correct 32-token register group and shuffled lane even when the output slab is N16 (`moe_swap_ab_kernel.py:1081–1176`). Runtime gates now cover these paths.
- **Shared/TMEM lifetime:** retain fences before releasing TMEM ownership, read-completion waits before overwriting shared stages, and async.shared publication before TMA reads. These protect different hazards. Swap-AB already waits immediately before stage reuse (`moe_swap_ab_kernel.py:1135–1138`), not before its next TMEM/register work. W4's inherited placement is discussed below.

## Resolved wait placement and remaining performance opportunities

1. **W4 stage-reuse waits moved later in source04.** In source03, both gated and non-gated TMA paths committed, immediately acquired, and then barriered all epilogue warps (`moe_w4a16_kernel.py:2404–2406,2580–2582`). CUTLASS `pipeline/helpers.py:767–769` implements acquire as `wait_group(num_stages-1, read=True)`. The old full-tile path already paid this; the new FC2 path pays it for tails that previously used direct SIMT. Waiting immediately before the next shared write permits overlap with next-tile TMEM reads and register processing. The minimal `w4-late-store-acquire.patch`, now applied as the isolated **source04 experiment**, moves rather than removes the wait/barrier. Its separate note explains first iteration, one-stage behavior, final draining, and why the publication/reuse barriers cannot be merged. No tactic, first-iteration branch or shape-dependent branch is introduced; the existing issuing-warp guard is repeated at the relocated acquire site. The bounded paired run recovered 4.97% at TP V3 T64 and 0.55% at T16384 versus source03. The T64 case still trails historical R2 by 14.94%; the full W4 screen is reported separately.

2. **Descriptor initialization does more generic work than the contract changes.** Prepare constructs a correct template for the current output allocation, then `initialize_output_descriptor` calls generic `update_tma_descriptor` for every live expert and output. That API updates the base, dimensions and strides (`CUTLASS cute/nvgpu/cpasync/helpers.py:860–883`), although this prefix-bound contract changes only the row extent. W4 publishes two maps per live expert, serially in each owning warp, before that warp starts payload copying. This is extra startup work relative to R2; its importance grows with active experts and small expert GEMMs. Inspect generated prepare PTX before implementing a row-extent-only replacement, so any reduced helper remains correct for the actual descriptor rank. The required warp publication barriers are not redundant.

3. **Prepare specializes on irrelevant W4 K values.** W4 passes the complete GEMM `(M,N,K)` tactic into `output_specs` (`moe_w4a16.py:469–490`), and prepare includes it in its compiled-kernel key (`moe_swap_ab_prepare.py:374–394`). CUTLASS `compute_epilogue_tile_shape` reads only `cta_tile_shape[:2]` (`blackwell_helpers.py:246–249`). Canonical output geometry in the private spec would avoid prepare recompilation for K-only tactic changes. This affects optimization/compile iteration cost, not the CUDA-graph device timing outlier.

The descriptor contract also replaces predicated direct global stores on partial W4 FC2 tiles with shared staging, fences and TMA issue. That is an actual instruction-path tradeoff, not a correctness defect. It may be pronounced for TP's many small expert GEMMs; do not restore a shape-specific fallback based only on one timing cell. Descriptor allocation and Python template setup are outside captured device timing and cannot explain a CUDA-graph latency regression by themselves.

Fresh source-paired C-A-A-C reproduced four TP regressions, as recorded in `RESULT.md` and `full-gate-03/confirm-analysis.json`: V3 W4A16 T64 154.777µs → 190.841µs (-18.90%); V41F W4A4 T4096 -9.04%; K3 PER-TOKEN T64 -6.86%; V3 MXFP4x8 T4096 -6.01%. This confirms regressions rather than attributing them to the earlier time-separated screen or missing capacity. The source audit found no new operand-pipeline stages, C-stage allocation, extra GEMM synchronization objects, or spill evidence that independently explains the whole W4 gap. Source04 isolates wait placement and will need its own paired performance result.

## Resolved issues and cleanup

- FP32 originally used a composed-layout swizzle (PISL) on element offsets instead of pointer swizzling (PDSL) on byte addresses. Increasing SMEM alignment to1024 did not solve it; bounds were already correct. Final03 uses `cute.recast_ptr(..., Swizzle(3,4,3))` plus a plain layout, preserving alignment; the direct gates now pass. A special MMA-only `(2,5,2)` layout was not needed.
- Removed the unused `route_tile` parameter from `bulk_output_element_bytes` and the unreachable unfused SIMT fallback in the post-bulk branch. FC1/fused helpers remain needed. W4's ungated SIMT-tail partition and predicates are removed; fused-finalize predicates remain.
- W4 same-expert acquisition reuse and issuing-warp restriction are implemented and validated.
- No remaining source cleanup of comparable value was found. Empty output-spec tuples produce nonfatal CuTe JIT argument warnings in direct descriptor-free FC1 tests; these are not a measured device bottleneck and did not justify a second interface path.
