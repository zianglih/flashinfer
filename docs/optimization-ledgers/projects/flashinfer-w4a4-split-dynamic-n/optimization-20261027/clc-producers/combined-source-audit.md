- **Weight metadata and startup PDL.** The new neighbor queries read the same routing metadata already required by pre-wait `first_expert` and scheduler work. Prepare still waits for completed routing ancestors and publishes those ancestors before launching dependent weight work; activation payload/SF remain protected by the later GEMM dependency wait. The cache query reads no activation data. Startup invocation is guarded by a valid tile below `num_tiles * total_m_tiles`; normal invocation occurs only inside a valid work tile. Thus neither calls the helper with zero route count. Both eager neighbor loads are bounded by `min(route+1,num_routes-1)` / `max(route-1,0)`, including first/last/singleton routes.
- **Cache hints and operand phases.** Weight payload and SFA receive the same per-work-tile hint in startup-prefetched and regular stages. Each TMA retains its original expected-byte count, completion barrier, stage index and empty-stage dependency. No new wait or release is introduced. Hint data depends on current routing metadata, so removal of the former static SFA policy from the compilation key is appropriate; the kernel evaluates the actual route on every replay. Activation eviction policy is unchanged.
- **Sparse producer participation.** Only TMA-SFB with a separate epilogue loses producer warps1–3 from tile/K work. Narrow cp.async scales still have all128 producers; internal inline epilogues still have all four producer warps. CLC metadata arrivals count exactly producer+epilogue+MMA participants. The explicit epilogue lower bound prevents idle producers from entering that branch. Physical warp roles, TMEM lane ownership, allocation/retrieval, startup PDL and final CTA joins are unchanged. The new weight-hint work was already guarded by warp0, so excluding idle producers creates no hint-publication dependency.
- **Prepare scale preload.** Every SF register entry is initialized for each routed row; valid SF words load before payload copies and store afterward at the unchanged canonical offset. Invalid/padded rows still write zeros. Both source payload and source SF are already ancestor-ready before this relocation. No shared memory or inter-thread handoff is added. The `sf_blocks == 0` W4A16 preparation specialization does not instantiate the new register fragment or SF loop.
- **Scope and interfaces.** Removed weight-policy arguments are private implementation arguments; current repository call sites are updated. Public API, tactics, default legacy dispatch and surrounding architecture implementations are unchanged. No original license/doc rewrites or unrelated changes appear in these three files.

The main residual is performance, not an identified control/phase hazard: retained-normal weights and scales change L2 competition with activations, and the CLC cleanup is neutral in its isolated five-cell screen. The combined full matrix is the appropriate retention gate. No additional source changes are requested by this audit.
