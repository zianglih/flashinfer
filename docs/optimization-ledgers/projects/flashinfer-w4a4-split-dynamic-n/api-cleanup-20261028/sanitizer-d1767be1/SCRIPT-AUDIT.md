## Compatibility with the cleanup

- **Tactics:** the worker obtains `runner.get_valid_tactics(inputs, None)` and executes each returned tactic directly (script lines 602–651). The blockscaled catalog now emits only the strict five-field `(route_tile, gemm1, gemm2, k_steps_pair, shared_clc)` format. The script contains no stale three/four-field fixtures, version prefixes, or independent FC1/FC2 CLC assumptions. W4A16 uses its separate unchanged catalog. Shape filtering remains the runner's responsibility; the 360 blockscaled / 23 W4A16 catalog sizes are not incorrectly treated as per-shape execution counts.
- **Compile interception:** `getattr(program, "__self__", program)` handles the current bound GEMM `kernel.wrapper` methods and directly callable prepare/finalize/quantizer instances. Module/class identities match their moved implementation files. `FLASHINFER_CUTE_DSL_DISABLE_CACHE=1` still reaches `compile_fn()` directly in `jit/cute_dsl_core.py:332`, so exported-object cache hits cannot bypass this hook. The hook preserves existing options, appends O3/PTX retention, validates PTX entry names, and requires every expected class to compile. Recompilation during graph capture or distribution changes fails the worker.
- **Public preparation / runner arguments:** `CuteDslConfig.prepare_weights(..., swap_ab=True)` still returns the tensor keys the worker consumes. It does not depend on the removed prepared-weight mode tag. W4A4, per-token W4A4, MXFP8, MXFP4×MXFP8 (`w4a8`), and W4A16 input positions match the current runners.
- **PDL and graphs:** the wrapper's current default is explicitly `enable_pdl=True` (`fused_moe.py:1039`), forwarded to each runner, routing, GEMMs, per-token intermediate quantizer, and finalizer. Persistent graph resources remain alive through the wrapper. Each tactic warms before capture; random and skewed routes then mutate the same buffers, with eager execution and two graph replays per distribution. This exercises changing routed row counts/padding without recapture. The script does not turn off PDL or synchronize between internal pipeline stages; its device synchronizations are between complete invocations/replays.
- **Native filters:** current `moe_sort` calls `routingDeepSeek::run` with precomputed IDs/weights (`csrc/moe_utils_binding.cu:357–437`). Its routing kernels retain the `routingIndices` / `routingInitExpertCounts` name substrings. The script checks matching compiled ELF function symbols and O3 native flags. Owned CuTe kernel filters likewise match checked PTX entry names. There is no stale legacy prepare/finalize filter.

## Evidence boundaries to retain in the final report

- **TMEM:** memcheck deliberately uses `--check-tensor-ops no` and passes `--ptxas-options='-g-tmem-access-check'` to both GEMM classes. The script records this compiler request and retained PTX hashes/entry names. It does **not** inspect cubin/SASS to prove emitted guard instructions, nor is this equivalent to enabling Compute Sanitizer's full tensor-operations checker. Preserve compiler/cubin evidence if claiming emitted guards; otherwise describe them as requested compiler TMEM access guards with the tensor checker disabled. The script's stated 2026.3 peer-barrier false-positive rationale was not independently reproduced in this source audit.
- **Filter evidence:** symbol/PTX checks prove matching compiled entries exist. They do not count launches instrumented by Compute Sanitizer. In particular, compiled `routingInitExpertCounts` presence does not prove that path executed at these token counts. Native routing paths requiring larger inputs, including the separately allocated expert-count buffer above 1024 tokens, are outside this matrix.
- **PDL scope:** this is PDL-on coverage only. Initial input quantization happens once before the per-tactic warmup/capture, so the benchmark's quantizer→FC1 captured dependency chain is not exercised. The per-token FC1→quantizer→FC2 chain is inside the captured MoE call. Ordinary NVFP4/MXFP8 input quantization, weight preparation, and unrelated PyTorch setup kernels are outside the owned-kernel filters; the per-token quantizer class itself is included.
- **Other exclusions:** no numerical assertions (covered separately), no SiTU/SwiGLU variants or the four performance model shape matrix, no W4A16 FP16 activation arm, no PDL-off, default `tactic=-1`/automatic-K policy, manual tactics outside the generated catalogs, legacy non-swap mode, atomic fused finalize, top-k-in-FC1, true distributed communication, Rubin, 4over6, or strict quantization. This is the complete tracked **manual script matrix**, not every API combination.
