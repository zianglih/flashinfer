# W4A16 producer cursor invariants

Applies to v1 and v2; v2 only caches per-work-tile A address slicing.

Let A and B be the total number of element stages issued by the elements warp (the two producer states' counts). Let F be the next metadata index not yet copied by the fast A cursor, S the next metadata index not yet copied/released by the B cursor, and N the existing metadata ring depth.

1. `A >= B` always. B issues only after the prefetch loop. If A equals B, the A acquire is mandatory even when try-acquire reports not ready; afterward A is ahead by at least one stage. Optional prefetch can stop only once A is ahead, or on terminal work (which the B loop never executes).
2. `S <= F <= S + N`. Before a fast metadata read, the code checks `F-S < N`; reading advances F once without releasing that slot. On a B metadata read, if F equals S, B's already copied work item is also copied into the fast cursor and F advances before S advances. Otherwise the fast cursor already copied that work item. B then releases the slot once and advances S. Thus no release invalidates the fast cursor's current K-stage metadata.
3. The fast cursor caches its current work item throughout its K stages. Therefore a released metadata slot may be recycled without changing those stage addresses. V2 additionally caches the corresponding A tensor slice. On every later work-item transition the cached work and slice are updated together.
4. If A equals B at the next B-stage issue, the current A work item must be the current B work item, and its K index is the next B K index. The fast cursor cannot require unavailable future metadata in this case. At a tile boundary, B's metadata copy explicitly seeds the fast cursor when it has not reached that item. An optional metadata try-wait or full lookahead window can stop prefetch only when the A cursor has already progressed beyond the B stage needing issue.
5. Blocking on raw-A empty when A equals B is safe: every older B stage was already issued, and all older A stages were issued. The independent scale warp, transform warpgroups, MMA and epilogue can consume that older work and release a raw slot without the elements warp issuing another B stage. Conversely, when A is ahead and a raw slot is unavailable, the code stops A prefetch and issues B instead of blocking on A.
6. B's own empty-stage wait is safe after A prefetch: all older A and B stages are issued. Any newly freed A slots while this B wait is pending are a possible scheduling/performance tradeoff, not a wait cycle. Existing independent raw-A and B rings are retained.
7. Ring phase/index checks remain the CUTLASS pipeline checks; the count differences only bound lookahead. Counts are no longer reset per work tile, while physical indices/phases still advance exactly once per K stage. Metadata advances exactly once per work item. Standard producer tails still wait all stages and do not use the old per-tile count for readiness.

Startup/PDL: initial B metadata is copied and released exactly as in the old activation warp. The fast A cursor first caches that same item. Before the first B transfer, opportunistic prefetch exhausts currently usable raw slots/metadata, then performs the original dependency wait and startup signal. A short K can cross work-item boundaries; no fixed prologue count assumes K exceeds stage depth. A zero-work CTA skips transfers but still performs the dependency wait/signal. For group-two MMA these are per-CTA invariants; all previous operand stages are issued by both CTAs before a raw-slot wait can require their common MMA release.

The six-case GPU smoke of v1 subsequently passed exact checks with K128 cross-tile lookahead, CLC/static, one/two CTA, PDL on/off, both layouts and partial K, with zero local-memory bytes. That evidence exercises the proof boundaries but is not a general exhaustive liveness proof or performance result.
