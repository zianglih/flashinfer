# FC1 channel-pair reuse (NB2) feasibility and isolated prototype

Frozen source: 7829fc00. The older W4A16 PR1 assessment proposed two independent
output tiles sharing an activation tile; it is distinct from cooperative
M256/two-CTA MMA. The local ledger rejects reducing raw/expanded pipeline depth
merely to add accumulator storage, so the current blockscaled path needs a new
resource calculation rather than importing the old BF16-dequant implementation.

The current core has weights on A/output-channel M and activations on B/runtime
N. Reusing B therefore means two M-channel tiles, each with its own accumulator
and SFA, per routed-token tile and per K stage.

CUTLASS's SM100 tutorial shows the applicable lifetime contract: issue all MMAs
reading an A/B stage before the UMMA completion arrival releases that stage.
The prototype retains this rule and places the existing stage releases after
both MMAs. It uses existing software operand reuse, not Rubin's B collector.
Primary reference:
https://github.com/NVIDIA/cutlass/blob/main/examples/cute/tutorial/blackwell/03_mma_tma_multicast_sm100.cu

## Initial resource/ownership audit

For FP4 M256/N128/K256, per CTA and per K stage:

- A0+A1: 32768 bytes; SFA0+SFA1 at SF16: 4096 bytes.
- Shared B: 8192 bytes; full-N local SFB: 2048 bytes.
- Total 47104 bytes/stage, four stages = 188416 bytes (184 KiB), before small
  barriers/epilogue scratch. Group-2 SFB ownership stays unchanged.
- Two N128 accumulators use 256 TMEM columns. Two disjoint 16-column SFA regions
  and one 16-column SFB region need 304 columns total, fitting the existing
  512-column allocation size.
- This changes two independent accumulator stages into one compound tile with
  two accumulators. It trades inter-tile epilogue overlap for half as many B/SFB
  loads per output channel and must be measured.

`nb2_core.py` is generated by `build_nb2.py`. It activates only for FP4×FP4 FC1
M256/N128; other dtype/tactic/FC2 paths retain the frozen baseline behavior.
Weight and SFA layouts contain twice as many physical slots; each logical K
stage selects slots `2*stage` and `2*stage+1`. B/SFB keep their original single
slot. Both SFAs have disjoint TMEM targets, and both MMAs complete before the
existing AB/A/relay releases. The fused epilogue runs twice with independent
accumulator pointers and M offsets. Existing channel predicates cover a final
partial compound tile. No gathered activation payload stage is added.

Initial exact smoke covers E4M3/SF16 FP4, E8M0/SF16 FP4, and E8M0/SF32 MXFP4;
M256/N128 two-CTA; short K; per-tensor quantization and per-token BF16. Output
and SF allocations are reset before each candidate so missing writes are
observable. Native routing and odd output-tile tails follow if this passes.

## Cross-format and follow-up controls

The all-format variant uses the same128-byte physical operand row for FP8 K128
and TMA-expanded mixed FP4-weight/FP8-activation K128. At SF32 its per-stage
scales are smaller, so five stages can fit. `build_nb2_variants.py` preserves the
measured restricted module and generates all-format four-stage, SF32 five-stage,
and wide-K/two-stage NB2 controls. It imports the sibling's frozen composed core
SHA256 `eb75bd7feafaaab6365e87039432a589acd5d617f856a62ee420fb8ece9b1a46`
for the single-channel wide-K control. Utility snapshots are byte-identical.

The first cross-format timings stopped when the wide-K control imported a
missing module alias after baseline/NB2 had timed. Initial MXFP8 582.7185→473.0545
and W4A8 535.041→417.889us lack trailing controls and are preliminary. The
missing alias is a harness error; source and numerical kernels were unchanged.
Corrected complete/reverse comparisons follow in separately named raw files.

Read-only independent audit found no NB2-specific ownership or bounds defect.
It confirmed both MMAs precede stage releases, two epilogues precede accumulator
release, and per-token scales/channel offsets/SF32 exchange participation remain
consistent. GELU-tanh and ReLU-squared checks completed; SiTU uses normalized SwiGLU
with non-null situ_beta/situ_linear_beta and is checked separately.

## Final bounded policy and integration handoff

Keep activation reuse as an additional FC1 tactic, not a replacement for the
existing two-CTA M256/N128 wide-K tactic. Logical `((512,128),(2,1),False)` issues
two physical M256 MMAs with shared activation B/SFB; it uses four native K steps
and four SF16/five SF32 stages. Existing `((256,128),(2,1),False)` retains eight
native K steps. Both retain the existing three-element tactic/API structure.
AUTO can choose based on complete-pipeline timing; there is no token threshold.

Measured reasons for retaining both choices:

|---|---:|---:|---:|
| NVFP4 T128 | 96.0965 | 101.840 | 96.224 |
| MXFP8 T128 | 159.520 | 171.2805 | 159.440 |

| NVFP4 T4096 | 114.368 | 119.6635 | 114.512 |
| NVFP4 T8192 | 182.7685 | 165.248 | 182.784 |

Large SF32 complete comparisons (with moderate control drift, so not precise
percentage retention claims): MXFP8 NB2-SF5/wideK/NB2-SF4/NB2-SF5 =
435.888/496.7045/472.576/451.4085us; W4A8 =
406.1765/509.233/417.889/417.521us. The first corresponding runs were
456.223 vs504.463us(MX) and405.776 vs510.049us(mixed). Five SF32 stages is selected
for the candidate; eight-K/two-stage NB2(538.6065us MX,507.809us mixed) is rejected.

NB2+CLC is not integrated. Its single bounded native NVFP4 screen is
283.951/276.735/290.3355us(static/CLC/static), with a strict native byte check.
The modest gain and control drift do not justify adding a scheduler warp and
metadata pipeline before full-AUTO retention. All CLC code stays diagnostic.
