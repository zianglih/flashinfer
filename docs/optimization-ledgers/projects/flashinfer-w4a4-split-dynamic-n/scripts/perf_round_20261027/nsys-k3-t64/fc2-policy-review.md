# Current FC2 policy and remaining signals

Source `f7182d5c`, current K3 T64 native tactic: one CTA, route N32, K512, shared CLC, PDL. Source references below are in `flashinfer/fused_moe/cute_dsl/blackwell/blockscaled_contiguous_grouped_gemm_finalize_fusion.py`. This review changes no implementation.

- **Prefetch is already capacity-wide.** `startup_stages=min(num_stages,k_tiles)` (2535) primes A and SFA before the payload wait (2538–2569). The selected stage costs49,152 bytes: A32,768 + B8,192 + SFA4,096 + SFB4,096. Four stages fit; five exceed232,448 bytes even before metadata. Six FC2 K tiles therefore prime four. The producer subsequently skips those already-issued weights (2693) and can run across output-tile boundaries as empty slots return. Increasing the loop limit cannot overwrite the four live slots. K4/K8 is already an autotune dimension; adding a second depth axis would violate the agreed policy.
- **No safe blanket barrier deletion is apparent.** Narrow-SFB completion and generic→async publication precede S2T; two-CTA publication also joins the remote CTA (3022–3057). MMA must acquire the accumulator slot before writing it. Existing final/proxy/pipeline joins protect different lifetimes. Prior elected-owner, deeper-metadata, role-split TMEM and extra SF-publisher trials are not new opportunities.
- **The source-row clamp is independently redundant.** Lines2668–2670 select source row0 for inactive lanes, although the unchanged copy predicate (2781) already generates zero-source-size cp.async. The baseline retains a SASS selector. A separate +1/−4 candidate and bounded gate are recorded in `../sf-source-address/`; it preserves every zero-filled shared byte and is distinct from removing inactive SF copies.

Current FC2 NCU artifacts (10 collection hashes verified, source f718; `../ncu-k3-fc2/evidence`) report582,844,416 CuTe TMA bytes versus506,677,248 TRT bytes, while DRAM reads are480,827,904 versus477,299,200 and executed instructions7,531,847 versus9,207,417. These are profiling counters, not retention timings. The saved public K3 T64 table records77 active experts. There are28 FC2 channel tiles/expert and six K512 stages, yielding12,936 stage instances. CuTe's bytes equal exactly12,936×(32,768 A+4,096 SFA+8,192 B). TRT's total equals12,936×(32,768+4,096+2,048 N8 B+256 N8 SFB). The latter is a consistent operand-size model, not a disassembly proof of TRT's individual transfers. It supports investigating activation overfetch before adding issue/synchronization machinery.

The current B copy height is static `b_copy_rows`; only its starting row responds to live N (2640). Merely reducing the MMA descriptor does not shrink TMA. [NVIDIA's device tensor-map modification procedure](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/async-copies.html#device-side-encoding-and-modification-of-a-tensor-map) requires descriptor modification/publication when changing its box. A descriptor bank would need selection and matching completion-byte counts, with care for each CTA's packed N slice. Those changes are larger than testing the existing N16 tactic and should follow that evidence. Historical physical-N16/extra-stage and compact-SFB trials bundled different changes and were rejected; they do not establish current N16 versus N32 performance.

Skipping physical SFB rows is also distinct from the safe address-selector deletion. The current S2T atom copies a complete canonical128-row scale block; stale scale bytes must be proven unobservable through each dtype's TMEM scale selector before any copy is suppressed. No such general proof is claimed here. Retaining zero fill while removing the redundant source address selection gives a smaller instruction-cleanup experiment first.

The subsequent same-source K3 T64 N32–N16–N16–N32 diagnostic (`../k3-n-width/evidence/summary.json`, 400 samples, matching routes) measured only 0.995913× for N16: control medians237.9215/237.729µs versus238.785/238.8175µs. This does not justify an N8 tactic or tensor-map machinery from traffic counters alone. The width diagnostic is separate from public AUTO results and is not a replacement table.
