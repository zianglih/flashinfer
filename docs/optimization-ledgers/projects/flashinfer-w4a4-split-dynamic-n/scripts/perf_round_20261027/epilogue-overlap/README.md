# Protected-prefix epilogue overlap candidate

Frozen from retained `2995bfda8338ca6ae623fbc2657d44e35e665627`; only the Blackwell shared grouped core changes. The original independent source copy was removed after rejection; its exact patch and helpers remain here. The sole active successor is the separate register-role review copy. `source.json` and the full-index `source.patch` identify the exact candidate.

The current capacity-derived overlapping accumulator windows share one or two 32-column slabs. The old loop processes and stores the first slab before reading the second slab, extending the next MMA's ownership wait. The candidate first finishes the existing TMEM load/transposition work for every protected slab, stores its fragment in registers, issues the existing TMEM read fence and one accumulator release, then performs their output reduction, quantization and stores. Remaining slabs retain the original static traversal and output order. No new tactic, public argument, model/dtype threshold, geometry or barrier is introduced.

`_load_token_group` contains the original TMEM-dependent work; `_store_token_group` contains the original output work. For per-token gated activation, the existing independent token-alpha/activation arithmetic moves after the two original TMEM transposes and release. `_run_token_group` composes the two for unchanged paths. Ordinary gated activation still precedes its single transpose. Per-token gated scaling/activation still follows its two transposes, preserving the exact expression order and rounding. Relu2 activation remains after both transposes. Packed-half output retains its original FP32 arithmetic, cast and packed transpose; its two 16-value views now cross the helper boundary. No new arithmetic expression or rounding contract is introduced.

## Ownership and data lifetime

- Phase zero traverses the high prefix in reverse; phase one traverses the low prefix forward. The current derived protected column count and per-channel tile offset are unchanged.
- All protected accumulator reads and all TMEM transpose scratch use complete before the same `fence_view_async_tmem_load` and `consumer_release`. Both CTAs retain their existing release participation and phase. MMA may then overwrite only the released intersection; the remaining slabs are disjoint from it.
- Live-row predicates are identical on load and store. Invalid protected slabs perform no load, no register read and no output work. The release remains unconditional after the prefix, including short/empty valid ranges.
- SF32 reduction uses the separate existing shared-memory scratch/barrier, after release; neither MMA nor another epilogue consumes that scratch. Output/SF stores remain in the same slab order and complete before the unchanged kernel/PDL publication. The producer, scheduler, operand rings, accumulator state advancement and PDL policy are untouched.
- With two protected slabs, the extra simultaneous live payload is one 16-value FP32 fragment per lane for ordinary gated activations, or one pair (32 FP32 values) for per-token gated activation and Relu2. This is a compiler/register-pressure risk, not a claimed free optimization.

## Completed local checks

`check_candidate.py` proves AST equality of the original three load and store arithmetic branches (normalizing only the two packed-half views), unchanged whole-module AST outside the two factored/new and two edited methods, and 1,544 interval/live-row/traversal cases for N256/M256 and N128/M512, both window phases and 32/64 protected columns. Python syntax, `git diff --check`, and scoped pre-commit pass. V1 smoke passed exact/spill checks but is rejected before timing: its forced per-token activation staging delayed the hardware release by269–276 SASS operations relative to the last TMEM read. V2 explicitly defers that independent arithmetic. Frozen V1 source/proofs are under `freeze-v1`; actual evidence is in the sibling `epilogue-overlap-v1` folder. V2 smoke passes8 exact replays but is rejected before timing: early release succeeds (709/703→223 SASS sites from the first protected TMEM read), at the cost of184 bytes stack and83 LDL/32 STL sites in each FC1 variant. FC2 remains unchanged. See `v2-disposition.json`; no broader V2 gate or timing ran. A separate register-role experiment on retained94a tests whether role redistribution is useful independently; it does not retain or silently repair V2.
