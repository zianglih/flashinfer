# Per-token epilogue release order

Tiny independent follow-up at retained `f175faea`; source is left unstaged in `flashinfer-epilogue-release-20261027`. The larger prefix-buffer/register experiments were rejected; their patches and evidence remain under `register-overlap*` and `register-need*`.

For the existing gated per-token branch, release the accumulator immediately after both original TMEM transposes. The following token-scale lookup and activation use register fragments plus read-only inputs, so they do not need accumulator ownership. Ordinary gated output still activates before its one transpose and releases afterward. Every enabled case releases exactly once; partial/empty-slab handling stays unchanged. No buffering, register redistribution, planner, tactic, arithmetic, or helper changes.

`check_candidate.py` reverses exactly this release move and verifies whole-module AST equality with the retained base. The full-index source delta is four lines added and one changed; scoped pre-commit passes. The decision rule was to skip timing if actual source-paired codegen showed equivalent scheduling.

The focused gate now passes 32 exact replays per source and 16 core pairs, with no spills or geometry changes. `review_codegen.py` independently verifies all 176 artifact hashes. Twelve unaffected core pairs and all six prepare pairs have identical instruction encodings; all instruction counts are unchanged. The four per-token FC1 cores differ in scheduling.

For the 2CTA SiTU case, first protected TMEM load to release shrinks from 709 to 586 instruction slots with PDL off and 703 to 579 with it on. The final protected slab moves 98 SiTU arithmetic instructions and dependent route/scale lookup after release. Registers rise from 104 to 120 and 108 to 118, consistent with keeping both transposed fragments live until the deferred arithmetic. The 1CTA SwiGLU case already places activation after release, but moving route/scale lookup shortens that interval from 361 to 346 and 365 to 348; registers remain 118/120. Both arms release two instruction slots after the final TMEM load. These are static scheduling distances, not cycle or latency measurements. The source remains frozen for a bounded four-cell timing decision; no 48-cell or native-AUTO campaign is planned.

Decision: retained as `ee88cf2acc59748a64ee2614fed2f16f05f67988`. Three affected real-model points show small positive results, and the dependency is removed without adding buffers, a register policy, a planner/tactic axis or a public argument. The larger refactors remain rejected. Evidence is bounded to these selected prefill points and focused exact gates; there was no fresh AUTO or full-grid rerun, no new TRT timing, no sanitizer run and no claim that decode or all remaining performance gaps are solved. `decision.json` pins the source and evidence hashes.
