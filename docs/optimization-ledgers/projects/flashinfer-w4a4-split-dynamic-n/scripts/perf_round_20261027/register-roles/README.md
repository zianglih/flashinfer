## Resource cause and policy

V2 emits `.reqntid320`, `.minnctapersm1`, and no `.maxnreg`. Its168 initial registers/thread match CUTLASS's default warpgroup-rounded planning budget, floor8(512/ceil(CTA_threads/128)). The two complete warpgroups are producer WG0 and epilogue WG1; MMA/optional CLC occupy the partial WG2. The extra protected fragments are live across release; ptxas spills them instead of making the otherwise idle producer registers available to the epilogue. This is a supported hypothesis for redistribution, not a claim that register pressure is the only remaining cost.

The candidate derives that initial budget from the existing physical thread count, assigns256 to the complete epilogue group, and assigns the complementary `2*initial−256` to the complete producer group. With the current288/320-thread overlap layouts this is80/256, preserving exactly the original full-group register total. The partial MMA/CLC group is untouched. The inline producer+epilogue path emits no reconfiguration. No dtype/model threshold, public option, or tuning axis is added.

Both role instructions occur at their existing role entries after common barrier/TMEM initialization and PDL startup/prefetch, before role-specific state construction or payload work. Every lane of WG0 executes the same decrease and every lane of WG1 executes the same increase, even for empty routes. The donor does not wait for epilogue progress before donating; the receiver may block until the donor returns registers. Each group executes only one reconfiguration, so no second-reconfiguration synchronization is needed. Existing end-of-loop and final CTA joins remain; warp0 teardown retains its decreased budget and is included in the spill gate. One-/two-CTA clusters use separate CTA-local pools with the same local role assignment.
