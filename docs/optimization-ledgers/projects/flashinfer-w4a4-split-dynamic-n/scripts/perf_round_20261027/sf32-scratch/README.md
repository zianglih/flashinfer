# Two-slot gated-SF32 exchange experiment

Base: pushed `f175faea1bd97a038fcbf3b51c84c22fd41843ed`. The unstaged source copy `flashinfer-sf32-scratch-20261027` was removed after rejection; see `disposition.md` and `cleanup.json`. This experiment changes no arithmetic, tuning axis, public API, register policy, cache policy, CLC ownership or TMEM release point.

Each live token slab writes one of two 512-byte scratch slots, joins the 128 epilogue threads, and reads the adjacent warp's local maximum. The next slab uses the other slot. All reads of slab i precede arrival at publication i+1; completion of that publication precedes every write of slab i+2. Thus publication i+1 protects reuse of slab i's slot, replacing the old per-slab reuse join. One final join after the complete helper protects reuse by the next helper call. Empty calls execute no join. A one-slab call still executes two joins; L live exchanges execute L+1 rather than 2L joins.

The ordinary epilogue helper handles one channel tile, so token-slab parity is sufficient. The overlapping FC1 helper spans channel tiles in forward or reverse order: its dense live rank is `channel_tile * ceil_div(valid_tokens, 32) + token_start // 32`. This increments/decrements by one between actual exchanges, including partial route tiles. Physical virtual-slab parity is unsafe: two channel tiles with one live slab each and physical width 64 would otherwise both select slot zero. No phase survives a helper call. All four epilogue warps participate even when the subsequent output-channel mask suppresses stores; the shared maximum exchange itself precedes that mask.

The same derived minimum scratch-byte requirement feeds K selection, operand stage capacity, capability admission and final allocation. Only gated activation + generated output scales + SF32 needs 1024 bytes; all other paths retain 512 bytes (or their original larger bulk-store buffer). The resource contract is propagated through the generic launcher, FC1 capability adapter/public wrapper, and tuner. The FC2 capability adapter has no activation or output-scale generation and correctly retains the defaults. Rubin's separate admission path is unchanged.

`proof.py` executes the source's host planner with explicit dtype/SM100-capacity stubs and analytical operand-layout byte counts. It checks 2,004 lifetime/address sequences (partial/empty tiles, one/two channel tiles, both directions), 13,500 constructors and 12,600 admission/final-allocation cases. The tested geometries retain their stage/K choices. A separate capacity-edge check proves that a one-stage configuration accepted with 512 bytes is rejected when 1024 bytes does not fit. This is a CPU proof, not proof of generated layouts or compiler motion.

The focused GPU gate will retain public-wrapper math/routes and PDL off/on replays, dump actual PTX/SASS/storage, and report the added 512 bytes only on gated SF32 FC1. It must show no additional one-slab decode join, unchanged release semantics, exact outputs, no spills, and no unintended non-target codegen/resource change. Timing is not yet authorized until those boundaries are reviewed. No upstream test additions are proposed.
