# Prepare/combine source audit, base84f9

Scope: read-only audit of Blackwell `moe_prepare.py` and deterministic `moe_finalize.py`, plus the public caller boundary. No source edit is proposed from this pass.

- Prepare copies payload bytes without conversion using256-bit vectors. Payload rows are32-byte aligned, SF words4-byte aligned, and the SF width is a multiple of four. Those are format/address constraints, not model dimensions. Copy loops derive from payload/SF width. Hidden256/384/1024 and short K-tail behavior are covered by the planned gates.
- Dynamic tile count and limits determine valid rows. N16 adds at most16 physical payload rows for the existing N32 MMA storage, then rounds SF initialization through128-row atoms. Invalid payload is intentionally untouched while invalid SF is zero. The proposed logical-N16 B copy can use less payload without changing this padding contract; it must retain matching expected transaction bytes and physical stage strides.
- Prepare's launch is hardware bounded by SM count times128-thread resident blocks. No V3/V41/K3 dimensions appear. Runtime zero-local-work has count0, so all lanes still take the PDL wait/signal path and do no payload/SF work. A zero-capacity standalone prepare call is not currently defended separately; the public routed workspace provides capacity even for zero-local work. This is a boundary observation, not an established public-API bug.
- Combine masks route entries before expert loads and handles expanded/permuted rows explicitly. The first slot uses FP32 RN multiply, later slots ordered RN FMA. Missing slot0 leaves positive-zero accumulator; all-masked rows write positive zero. PDL only permits route metadata reads before the wait; expert reads follow it. These are shared W4A4/W4A16 numerical and ordering contracts.
- Combine's address arithmetic widens row offsets toInt64. Input/output BF16 rows must be multiples of8 and16-byte aligned; every vector access remains inside a complete8-element interval. Cache keys include dimensions, scale dtype, selected vector width, PDL and expanded/permuted layout.
- Remaining empirical scheduling policies:32threads for<=8tokens, otherwise128;4vectors/thread above1024tokens; expanded rows may choose5/6/7vectors to exactly divide hidden size. These are existing geometry/performance choices, not correctness requirements and not part of the current logical-B-copy change. Replacing them would need its own whole-chain screen because combine is shared with W4A16.

Existing68 selection is strong for API/SiTU/N128twoCTA/channel padding and K tails, but it does not by itself prove full public N16per-token/zero-work/persistent behavior. `probe_chain.py` supplies exactly those boundaries with16 configurations/96 replays per source, compared against clean84f9 on the same GPU, without changing timing helpers. It also includes H384/I128 MXFP8 to avoid relying only on one small power-of-two hidden size.
