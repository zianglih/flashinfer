# Cancellation ordering history and present comparison

The isolated recorded order experiment is in the older W4A16 dequantization core, documented in `flashinfer-w4a16/w4a16_optimization_experiments.md:2538–2559`. It kept metadata depth2 for FC1 and3 for FC2, moved the next CLC request behind local metadata-slot acquisition for live routes, and let padded routes query immediately. The native AUTO whole-chain sweep used V3 shape (H7168,I2048,E256,topk8), EP8 and simulated TP8, tokens1,2,4,8,16,32,64,128,256,512,1024,2048,4096, warmup10/100 CUDA-graph CUPTI samples, no fused finalize. Raw full-grid means are recomputed in the companion JSON. Each focused correctness log reports5 passed.

The original transient source hashes and native selected-tactic caches were not saved in the located logs. Do not claim this is a fixed-tactic order comparison. Git retained commit2c402c1e329f760b7701a2e73c1b12d8fe617888 (`perf(moe): dynamically schedule W4A16 GEMM1`) is later than these measurements and includes subsequent queue-depth refinements; its source hash is provided as a retained-code pointer only, not the measured-source pin. The NCU report separately records a two-CTA W4A16 kernel with384threads,168registers,grid(32,287,1) FC1 and(56,287,1) FC2 atEP8T4096. It does not supply the native benchmark selected-tactic cache.

The earlier W4A4 scheduler experiment on7829fc00 used the gather4-era pipeline and inherited acquire-before-cancel; it did not isolate order. The later regular-TMA experiment onfca8462cbd9096059d0019a206aa760fb34ca8c4 also inherited the order, comparing depth1/2 instead. Its retained common core hash wasbc36c575f8ae044818d5365198c0b016828dc630886b874caffd4edb11737882. The V3T16 N16/M128 depth regression is not an ordering measurement.

Therefore no located evidence repeats the proposed current regular-TMA depth1 cancellation-before-acquire experiment. The old W4A16 result is a useful risk prior but not a redundant modern A/B. Preserve one CLC response slot, acquire its empty barrier before cancellation, and retain current-response publication before response wait/release. The current register-resident work record and independent response/info storage make reordering dependency-safe; performance remains empirical.
