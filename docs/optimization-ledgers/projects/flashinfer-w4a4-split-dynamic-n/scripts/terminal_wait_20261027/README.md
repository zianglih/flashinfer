# Remove one duplicate terminal TMEM load wait

Independent source `../../flashinfer-terminal-wait-20261027`, clean base `b85eff41a6c30687a93e95455a3f68ff77d14ac5`, with one unstaged line removed from `blackwell/utils.py`. No other kernel, tactic, cache, public API or benchmark policy changes.

`Sm100BlockScaledMoeEpilogue` has one production construction site and two `run` call sites, both in the common blockscaled core. Both callers retain their final TMEM load drain after the channel loop, before ordinary accumulator release. The dedicated FC1 overlapping-window path calls the distinct `run_overlapping_fc1` entrypoint and retains its caller drain. Every internal fence that precedes an early accumulator release remains unchanged, as do bulk-copy waits, SF proxy fences, named barriers and TMEM teardown.

Removing only the final helper wait moves ordinary completion from each channel fragment to the common caller drain. Fragments use disjoint TMEM columns; the caller drains all fragments before releasing their accumulator bank. Packed FC2 conversion still consumes the loaded register values before output stores. The new one-line change does not move any arithmetic or ownership release.

This redundancy was documented in the October 25 caller audit and removed only as part of the larger unretained direct-N16 epilogue experiment. That combined experiment's neutral timing is not an isolated result for this deletion. Current R4 gate PTX still has two adjacent terminal load waits (case00 PDL-on FC2 lines 1094–1095); actual SASS has adjacent NOPs at 0x3f50/0x3f60 before accumulator release. A fresh source-paired gate must establish the isolated machine-code effect.

`static_audit.py` verifies the exact one-line delta and both caller drains. The existing task-local changing-route/data graph gate covers all four formats, PDL off/on, static/CLC, inline/overlap, one/two CTA and empty then reactivated routes. Its bounded geometry list includes wide TMA-SFB, M512 two-channel accumulation, and N256 overlapping accumulator windows to cover the relevant helper paths. The gate uses separate frozen control/candidate sources, shared verified native C++ artifacts, and source-private compiler workspaces on persistent storage. No performance claim or sanitizer claim follows from this gate.

## Completed gate

The frozen source pair passed 40 exact replays per source and 20 core variants per source. All four formats, both PDL settings, actual static/CLC execution, narrow/wide SF transport, one/two CTA, one/two channel fragments, inline/dedicated epilogue and overlapping accumulator windows are represented. Empty routing produces zero and subsequent reactivation remains byte identical.

PTX removes 22 terminal load-wait sites across the matrix. Ordinary one-fragment cores remove one actual SASS NOP; M512 cores remove two waits. The two FC1 overlapping-window cores are byte-identical because they use the separate entrypoint. Register use is unchanged in 18 variants and decreases by one in both M512 FC2 variants. All retain zero stack/local/spill instructions and identical shared-memory, TMEM, operand/accumulator stages and MMA completion counts. Across all 20 variants, static instructions excluding trailing padding decrease by 20. The M512 no-PDL FC2 variant has a net one-instruction increase from code allocation differences despite removing two wait sites; this is preserved in `validation.json`.
