## What the controls mean

The installed CUDA13.2 scope is [PTX9.2](https://docs.nvidia.com/cuda/archive/13.2.2/parallel-thread-execution/index.html), not the latest9.4 syntax. FIRST/NORMAL/LAST rank eviction preference; UNCHANGED preserves prior priority. They neither reserve cache capacity nor synchronize memory. FIRST is not no-allocation. Ordinary `.ca`/`.cg` choose cache levels; `.cs` is a streaming policy. Normal write-back output is not automatically LAST. [Cache operators and priorities](https://docs.nvidia.com/cuda/archive/13.2.2/parallel-thread-execution/index.html#cache-operators).

TMA loads and stores accept an opaque64-bit `.L2::cache_hint` policy. Ordinary loads/stores can also use a policy operand. Direct `.L2::evict_*` syntax on ordinary operations has vector-width restrictions; the128-bit combine load must not inherit the256-bit spelling. Descriptor prefetch differs from fetching payload. None replaces a completion fence or dependency wait. [TMA](https://docs.nvidia.com/cuda/archive/13.2.2/parallel-thread-execution/index.html#data-movement-and-conversion-instructions-cp-async-bulk-tensor), [load](https://docs.nvidia.com/cuda/archive/13.2.2/parallel-thread-execution/index.html#data-movement-and-conversion-instructions-ld), [store](https://docs.nvidia.com/cuda/archive/13.2.2/parallel-thread-execution/index.html#data-movement-and-conversion-instructions-st).

Use NORMAL when intentionally returning an access to ordinary priority; UNCHANGED alone cannot retire an earlier LAST priority. An ordinal channel tile is not a globally ordered final consumer across CTAs, so naming it “last use” would require a separate lifetime proof.

## Source and codegen evidence

- [W4A16/Mega audit](L2_W4A16_PRIOR.md) pins source files and closed experiments. Split W4A16 and BF16/NVFP4 Mega use packed-weight A FIRST, BF16 activation B LAST, weight scales default. Mega's transport separately uses FIRST payload loads and NORMAL stores. The actual NVFP4 Mega compute kernel has no explicit operand priority; the reference implementation's descriptor prefetch is not a payload-priority policy.
- Current blockscaled narrow A-FIRST is already measured and retained for one-CTA/eight-K-step geometry. ## PDL startup and the current causal boundary

The ac1 core creates barriers/TMEM/views and TMA partitions before `griddepcontrol_wait` at1003; it reads `num_tiles` at1021 and issues weight/activation payload transfers only later. Preparation waits at96 before its count/mapping/payload reads. Finalizer intentionally loads ready route mapping/scales at133–138, waits at141, then reads FC2 output at156. Thus early dependent startup does not currently fetch future weight or activation tensors. Keep that boundary: descriptor/allocator/setup overlap is separable from tensor traffic, and cache hints cannot make an otherwise premature data read safe.

The [ac1 timeline](../pdl_timeline_audit/ac1-prefill/README.md) shows a20.480us longer single-replay prefill span after restoring FC1's80-register codegen. FC2 and combine each have longer spans after their predecessor's completion, but this does not establish L2 contention. In particular, graph lifetimes include waits and grid tails; no useful-work marker or cache-counter attribution was collected. Resolve the remaining FC2 trigger/codegen experiment before treating caches as its cause.

## Concrete policy recommendation

Use semantic lifetimes rather than a token-count switch. Do not mark every activation or output LAST. At this T16384/N256 route, the padded FC1 payload+SF is 79,478,784 bytes and FC2 input22,708,224 bytes; the16,280 valid BF16 FC2 rows total233,390,080 bytes. Persisting an obsolete FC1 buffer can compete with the next handoff. All those totals also exceed or materially occupy L2; priority does not make them fit.

| Data / access | Proposed policy boundary |
|---|---|
| Expert weights | Preserve retained narrow A-FIRST and wide/default policy until separate evidence; wide prefill reuses weights across routed token tiles. |
| Route metadata and scale metadata | Keep current normal accesses initially. They are small/reused, but a LAST change is a distinct measured candidate, not necessary to validate the output lifetime idea. |
| Routed FC1 payload/SF and FC1→FC2 input | NORMAL/default throughout; do not introduce persistent LAST without a retirement operation and proven reuse benefit. |
| FC2 scratch output | A possible isolated test is LAST on its producer stores, paired with FIRST on combine's consumed-input reads. Each consumed line loses protection rather than remaining LAST until a future allocation. Preserve all store widths, layout, fences and numerical order. |
| Final model output | Normal write-back; its next model consumer is outside this function, so this kernel cannot declare it dead or safely select FIRST on that basis. |

The paired FC2-store/consumer-demotion test is **a hypothesis, not a recommendation to retain**. It differs from the old FC1-store-LAST-only experiment and avoids protecting dead FC1 inputs. Large-N implementation would change the existing bulk-store cache operand (`blackwell/utils.py:117–131,910–914`) and the128-bit finalizer input copy (`moe_finalize.py:127–128,156`); narrow SIMT FC2 output must use the same semantic contract if the candidate is advertised as unified. No change to final-output stores or math is implied. Current blockscaled finalization explicitly uses expanded input (`cute_dsl/fused_moe.py:851–859`; MX/mixed assembly `bench_cute_dsl_mxfp8.py:312–320`). FC2 scatters through the sort mapping to the unique expanded row `token * top_k + slot`; combine consumes each valid expanded row once across disjoint channel columns (`moe_finalize.py:133–156`). At T16384, the expanded BF16 allocation is1,879,048,192 bytes (T × top-k × H ×2), while only233,390,080 valid bytes are produced/consumed in this route. Allocation capacity must not be reported as traffic. W4A16 instead uses the default nonexpanded path (`moe_w4a16.py:502–509`). A generic repeated-mapping consumer still needs its own last-use argument; this audit does not transfer the blockscaled contract to it.

Limitations: the producer finishes before dependent payload consumption, the complete233MB output cannot reside in L2, and production/consumption traverse it differently. A cache line can also contain multiple vector fragments, so FIRST on one read does not mean every byte in that line has been consumed. Demotion is only a priority preference, not discard. It may reduce near-future line reuse. A useful test must compare whole-chain traffic and latency on the same source/PDL policy, with exact outputs and both decode/prefill cases; isolated GEMM improvement alone is insufficient. Do not add extra data-prefetch traffic, sweeps, per-token policy branches, or L2-flush operations to this hypothesis.
