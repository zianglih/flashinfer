# Worst static code-size case: config5 FC1 PDL on

Source-bound to retained control `9b4721b0` and repaired owner patch `d8ca478d`. Evidence and hashes: `config5-fc1-pdl1-codegen.json`; extracted instruction lines in the adjacent control/candidate scheduler text files. Original artifacts are under `gate/evidence-v2/gate-v2-gpu7/{control,candidate}`.

- Whole kernel: 6379 → 6433 static SASS instructions (+54); registers 156 → 158. Both report stack/local bytes 0 and static SMEM 1024. The MOV.SPILL/R2UR.FILL mnemonics below exchange uniform and regular registers; they are not evidence of local-memory spills.
- Candidate adds seven ordinary `BSSY`/`BSYNC` pairs and one `BSSY.RECONVERGENT`/`BSYNC.RECONVERGENT` pair. Seven ordinary pairs are visibly in/around the scheduler branch; candidate SASS lines 12249–12465. Whole-kernel differences also include +20 `MOV`, +3 `MOV.SPILL`, +3 `R2UR.FILL`, +4 `R2UR`, +6 `UIADD3`. Register scheduling elsewhere changed, so the entire +54 cannot be charged solely to the scheduler's hot loop.
- Control's raw CLC issue is a direct `UGETNEXTWORKID.BROADCAST` at SASS line 10829 (address 0x15230). Candidate adds `VOTEU.ALL`, a conditional UGETNEXTWORKID, `ELECT`, and `BRA.U.ANY` replay logic at lines 12319–12335 (0x180c0–0x18140). Candidate PTX lines 9126–9128 contains expect_tx and raw try_cancel without that explicit election: this is compiler lowering around the divergent owner branch, not a new Python helper election.
- Metadata storage remains `STS` + `STS.64` and one full arrival. The raw response remains one `LDS.128`, required shared proxy fence, and one encoded empty arrival site; compare control lines 10919–10927 and candidate 12431–12439. Converged control lanes already issue one SIMT load/arrival instruction, with aggregated arrival semantics. Reducing participating lanes is not a 32x instruction reduction.
- Candidate reconverges before delayed PDL acquire and final warp/CTA teardown (SASS 12465–12469). The outer lane selection changes control flow and scheduling state; static count alone does not establish dynamic instruction cost or end-to-end behavior.

The measured compiler result does not support an instruction-efficiency claim for this implementation. Fresh CAAC timing remains decisive. If neutral or worse, a separately frozen @cute.jit-isolated scheduler invoked inside elect_one is a plausible way to preserve compiler-recognized election and avoid fixed-lane peeling, while keeping the successful source-paired protocol. It remains an untested hypothesis and must not mutate the ongoing source.
