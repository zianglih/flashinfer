# Schedule published routing during PDL payload wait

Base b85eff41 plus the same six-field all-CLC diagnostic enumeration as the matched control. Only the kernel's dependency-wait placement changes. No new tactic, policy flag, queue, layout or arithmetic.

The existing `prefetch_weights_before_wait` contract explicitly requires predecessor startup publication of routing in the same memory domain. Warp zero already reads `num_tiles` and `expert_idx` before its payload wait to issue A/SFA prefetch. The CLC scheduler uses that same published routing (`num_tiles`, `expert_idx`, `mn_limit`) and hardware cancellation responses, never B/SFB or intermediate output. Let it start after the existing common allocation/barrier setup, while all operand, MMA and epilogue roles keep their original payload wait. The scheduler performs its delayed dependency wait after draining its queues, before the common teardown barrier.

Startup release/trigger remains on roles which completed the immediate wait. The publication-enabled public FC1 already limits this to warp zero; the non-public startup-without-publication configuration also excludes the early scheduler. Producer-exit triggers are unchanged. PDL-off and static configurations keep their original wait placement. All consumers still read metadata only after their payload waits. Acquisition-before-cancellation, one tile per request, terminal publication, group-two joins and final barrier participation remain unchanged.

Expected benefit: prepare initial routing metadata and cancellation requests during predecessor payload work, reducing CLC startup bubbles. Possible costs: earlier cancellation can reserve work too soon; scheduler resource lifetimes or register allocation may grow. Gate all four formats, PDL on/off, one/two CTA, inline/dedicated epilogues, empty/reactivated/skewed routes with source-paired output hashes, then inspect codegen. Fixed-tactic cold-L2 CAAC comparisons precede any retention; do not attribute a different native tactic to this change.

## Separate PDL/grid hypothesis

The [CUDA programming guide](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/programmatic-dependent-launch.html) and [CUDA 13.2 PTX contract](https://docs.nvidia.com/cuda/archive/13.2.0/parallel-thread-execution/index.html#parallel-synchronization-and-communication-instructions-griddepcontrol) require all prerequisite CTAs to trigger or complete before the dependent becomes eligible. A static persistent grid has only resident-sized launch work; the current CLC grid represents the full route-capacity/channel product. This suggests a structural limit on early dependent launch until pending CLC launches are resolved. It is an inference, not a measured attribution or an assertion of undocumented cancellation semantics. Existing NSYS shows less inter-phase overlap under CLC, but geometry and steady-state scheduling costs also matter. Correlate final cancellations and dependent start before attributing the remaining gap to this mechanism.
