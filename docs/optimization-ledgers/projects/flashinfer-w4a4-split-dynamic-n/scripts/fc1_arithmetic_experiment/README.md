# FC1 arithmetic and loop diagnostic (7829fc00)

Task-local only. No production edits or retained performance claim.

The frozen candidate is `7829fc00dc7121341cc40cd4190660507e006490`.
C1 `fi-w4a4-dyn-n-1024`, B200 GPU3 timing / GPU7 paired checks,
`nvcr.io/nvidia/pytorch:26.05-py3`, CUDA13.2, CuTe DSL4.7.1.
Actual `bench_moe_deepseek.py` NVFP4 preparation and routing at16384 tokens,
H7168/I2048/top-k8/32 local experts; FC1 M256/N256/cluster2.
Isolated phase timing uses10 warmups,100 cold-L2 CUDAgraph/CUPTI samples.
This is a diagnostic, not the native AUTO retention benchmark.

The current MegaMoE quantizer uses `max.xorsign.abs.f32` and a final sign clear;
its gated activation uses `min.xorsign.abs.f32` for symmetric clamping.
The official PTX ISA also supports Blackwell three-input `max.abs.f32`.
Reference: https://docs.nvidia.com/cuda/parallel-thread-execution/#floating-point-instructions-max

Variants are immutable modules generated by `build.py`:

- `abs3`: balanced three-input absolute max tree, with an explicit zero final
  operand preserving the original all-NaN -> zero reduction convention.
- `absxor`: serial absolute max with a final sign clear.
- `compact`: abs3 plus one-instruction symmetric clamp for nonnegative limits;
  NaN propagation stays enabled and negative limits use the original formula.
- `unroll`: statically unroll only the FC1 token-slab loop.

All native output/SF byte comparisons passed. The compact variant additionally
passed24 paired cases spanning six blockscaled format families, N128/oneCTA and
N256/twoCTA, quantized output and per-token BF16 output, gathered repeated and
reversed rows, K tails and persistent reuse. These checks do not imply complete
exceptional-value coverage.

Decision: reject all four for retention at this point; changes are below1% and
not a meaningful improvement. No primary sweeps or old baselines were rerun.
Raw `logs/fc1-arithmetic-*` are retained locally and remotely. The manifest records
source hashes. The source production checkout remained unchanged.
