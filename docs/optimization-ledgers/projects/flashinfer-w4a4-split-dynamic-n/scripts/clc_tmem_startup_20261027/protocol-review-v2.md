V1 (`be8a12bb`) is superseded. Its prior source review, exact gate and neutral timing remain historical evidence for that frozen implementation only; they are not retention evidence or validation for V2's different participation and synchronization spelling.

**Publication count is correct.** Inline epilogues have128 producer/epilogue readers plus32 MMA readers; allocator warp0 is already among them, so barrier3 expects160 arrivals. Overlapped epilogues have128 dedicated epilogue readers plus32 MMA readers; allocator warp0 must independently contribute32 nonblocking arrivals after allocation, for192 total. The other96 producer threads and optional32 scheduler threads do not participate. Do not use160 for overlap: reader-only synchronization cannot publish warp0's allocation result. Do not add the nonblocking arrival in inline mode: that would double-count warp0.

**Use the explicit divergent-participation APIs.** Preserve a local `tmem_ready` object and call `tmem_ready.arrive_unaligned()` from overlap allocator warp0. Call `tmem_ready.wait_unaligned()` immediately before each actual role-local pointer retrieval. Exact SDK `wait_for_alloc` is only an alias for the configured barrier's aligned `arrive_and_wait`; no allocator-completion behavior is lost by using the same barrier directly. The unaligned forms are a better contract for separate role branches and producer/consumer participation than legacy `bar.arrive`/`bar.sync`. The [PTX named-barrier contract](https://docs.nvidia.com/cuda/parallel-thread-execution/#parallel-synchronization-and-communication-instructions-bar) permits mixing arrive and sync with one ID/count, but reserves aligned conditional execution for uniform participation. Every participating warp contributes exactly once to this one-use startup phase.

**Initialization must remain common.** The unconditional qualified SDK initialization join is necessary, including static one-CTA overlap. Deferred pipeline initialization must complete before pure producers or scheduler can run ahead of allocation. The one-CTA join uses barrier0 and finishes before role divergence. Two-CTA cluster arrive/wait remains unchanged. Keep the existing init fence; the similarly named local helper is not a substitute for the join.

**PDL and empty-work progress remain valid.** Reader waits occur before first pointer use and before role-loop work-validity checks, so padded/empty routes cannot omit arrivals. Existing prefetch occurs after initialization, primes at most the initially empty operand stages and does not use TMEM. It therefore does not require a reader to pass barrier3 first. No B/SFB access is moved ahead of the existing payload wait. Routing publication, signals and delayed scheduler wait keep their present conditions; their timing can advance, which is a performance consideration rather than a new visibility contract.

**Final retrieval is safe for nonreading producers.** The final full-CTA barrier1 includes allocator and all readers, then the existing128-thread barrier2 precedes free. Consequently producers that bypassed barrier3 may still retrieve the pointer inside that final branch. Only warp0 issues actual deallocation. Preserve the SDK's independent two-CTA deallocation handshake and response tail. No pointer value should cross runtime role branches or be manufactured on scheduler paths.

**Validation boundary.** In addition to the existing eight-case CLC and two-case static gate, include a static one-CTA overlapped-epilogue case with PDL off/on: it exercises producer bypass and the newly necessary one-CTA initialization join together. Inspect PTX `barrier.arrive`/`barrier.sync` counts160/192, one overlap allocator arrival, no inline double arrival, no producer/scheduler startup pointer read, unchanged final joins/handshake, and register/spill/resources. Keep performance claims separate from source correctness, and assess the cost of the extra static one-CTA join. No source edits or GPU launches were made by this reviewer.
