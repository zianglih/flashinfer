A minimal prototype can separate CLC scheduling from TMEM readiness without changing the scheduler protocol. Apply it to retained `9b4721b0`, preserving the full-warp CLC scheduler and existing host policy; the rejected elected-owner implementations are not dependencies.

- The current TMEM named barrier3 includes192/320 threads under CLC. The worker roles contain160/288 threads; `32 * self.schedule_warp` expresses this count for both static and CLC kernels. Keep common `allocate()` so allocator bookkeeping remains coherent, and let only worker warps enter `wait_for_alloc()` under the compile-time CLC flag.
- Remove the common `retrieve_ptr()`. Read the pointer inside the existing producer/inline-epilogue, dedicated-epilogue, and MMA branches, using role-local names. No pointer is defined on the scheduler path, and none crosses a runtime branch. Retrieve again inside the existing final `warp < 4` free branch after the final all-thread join. This avoids an undefined incoming SSA value or an unsynchronized unused shared read. It may add a final pointer load; codegen will determine whether it affects resources/instruction count.
- Keep the current mbarrier-init fence and two-CTA relaxed cluster arrive. Replace the cluster wait with qualified SDK `pipeline.pipeline_init_wait(cluster_layout)`, enabled for CLC or two-CTA kernels. Exact SDK4.7.1 resolves this to cluster wait for2CTA and `sync_threads()` for1CTA. Thus2CTA synchronization is unchanged;1CTA CLC gains one all-CTA initialization join before allocation, replacing the initialization guarantee it previously inherited from the TMEM barrier. Static1CTA remains unchanged.
- SDK `sync_threads()` uses barrier0; this kernel explicitly uses1 for final all-thread join,2 for the128-thread free rendezvous,3 for TMEM readiness, and6 for epilogue transpose. Startup initialization finishes before role divergence. There is no concurrent reuse of barrier0 or change to counts for IDs1/2/6.
- Preserve both PDL placement and publication policy, metadata acquire-before-claim, CLC response-tail drain, final all-thread join, allocator warp0, and the independent two-CTA deallocation handshake. Scheduler still honors the existing payload wait when weight-startup prefetch is off; this experiment changes only its TMEM dependency.
