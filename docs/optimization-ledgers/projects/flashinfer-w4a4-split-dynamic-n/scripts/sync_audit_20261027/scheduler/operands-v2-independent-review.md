The review read the independent V2 snapshot/diff/proof, current custom `PipelineTmaUmma.create/producer_acquire/consumer_release`, exact installed4.7.1 `sdk-MbarrierArray.py` and `sdk-mbarrier_arrive.py` captures in `scripts/clc_elected_owner_20261026`, and the explicit `_blockscaled_cluster_try_wait` helper.

- `MbarrierArray` derives initial pending arrivals from the producer group's size. Its TmaLoad arrival still elects a single lane and performs one `arrive_and_expect_tx`; it does not issue one arrival per group member. Only CTA0's producer calls it. The combined count is therefore correctly three: one expectation plus two SF publications.
- Each CTA retains its128-thread local cp.async completion wait and generic-to-async proxy fence. The elected SF arrival still targets CTA0 with explicit cluster scope. The new leader wait is explicitly acquire.cluster, matching the cross-CTA publication; it does not silently inherit the ordinary CTA-scoped full wait.
- The count cannot reach zero before the expectation plus both SF arrivals. Transaction completion is independently required. If SF arrives first, the TMA expectation remains a pending arrival; if TMA finishes first, SF pending arrivals remain. The unchanged atomically combined expect/arrive operation establishes the byte count before its arrival is discharged.
- Local/peer producer empty waits and the leader's post-MMA empty multicast are unchanged. A successful combined-full wait precedes scale consumption and all channel MMAs, then the same empty release permits stage overwrite. Thus a next-generation SF arrival cannot wrap into the prior full phase: it requires a fresh local SF stage whose producer overwrite is still blocked by that shared empty ring.
- The peer MMA warp can advance after publication, but no extra same-slot generation is admitted without that producer/empty dependency. Its unused local full array is never awaited or repurposed. Leader-only full expectations and combined waits remain consistent with the existing transport.
- PDL startup acquires at most one pass over the stage ring and prefetches independent weights/scales. Pending full expectations do not admit activations or SF publication ahead of the dependency wait. Scheduler, final joins, producer tails and TMEM deallocation are unchanged.
- One-CTA cp.async and all TMA-SFB paths retain their previous count/wait protocol. Metadata capacity planning removes the matching readiness storage argument rather than introducing a shape-specific tuning choice.

Recommended gate inspection remains: actual full count3, unchanged byte expectation, local SF wait/proxy ordering, cluster-acquire leader wait, same empty multicast and phase advances, repeated wraps, PDL on/off and empty→live replay. This approval is based on code/ownership proof, not on the abstract event model alone.
